# Voice 예시 (base) — raw 사례 모음

`voice.md`의 1차 특성화는 아래 5개 사례에서 추출했다. 각 사례에 라벨(모드 quick|deep / mode 0·1·2)을 달아두었고, **본문은 사용자 작성 원문 그대로**다(오·탈자 포함, 톤 앵커가 목적). 비어 있으면 출력은 그 화자 어투가 아니라 generic이다.

> 본문은 코드블록으로 감쌌다 — 이 화자의 phrase 단위 줄바꿈(연 구조)이 voice의 일부라, GitHub 렌더링에서 줄바꿈이 공백으로 합쳐지지 않게 하기 위함.

### 왜 이게 나다운가 (한 줄)
BEFORE는 라벨+불릿이라 "슬라이드를 읽는" 느낌 → 내 톤 아님. AFTER는 "무슨 말이냐면 / 그래서 / 그리고 이게 중요한데 / 곁들여서" 구어 연결어로 *말하듯* 흐르고, 괄호 방백·"(한 줄 토)"·어미 modulation이 살아 있음. 정보량은 같은데 골격이 prose다.

## 사례 8 — quick / mode: 0 (relay) — register drift
label: negative→positive (반말 이탈 → 해요체 교정)
note: quick을 **반말체**로 써낸 드리프트 사례. 원인 두 겹 — (1) [4] STYLE의 "적용 전 examples.md 반드시 읽기"를 건너뛰고 voice.md 산문 설명만 보고 register를 재구성, (2) quick overlay의 "동료에게 *말하듯*"을 *반말 license*로 오독("말하듯"은 내러티브 친밀도이지 speech-level이 아님). 어미만 다른 같은 문장 대조라 speech-level 앵커가 목적(발췌).

### BEFORE (반말 — 내 톤 아님)

```
…제목부터 도발적이야 …
무겁다는 게 늘 문제였고. …
결과가 좋아(!!). …
정식화해 둔 셈이야.
```

### AFTER (해요체 — 내 톤)

```
…제목부터 도발적이에요 …
무겁다는 게 늘 문제였고요. …
결과가 좋아요(!!). …
정식화해 둔 셈이에요.
```
(출처·결론은 -ㅂ니다, 주관 평가는 "~인 것 같아요"로 hedge)

### 왜 이게 나다운가 (한 줄)
BEFORE는 "-야/-어/-고."로 끝나는 반말이라 *동료에게 말하듯*이어도 내 speech-level이 아님 → 내 톤 아님. AFTER는 어미만 해요체/-ㅂ니다로 돌렸을 뿐 흐름·괄호 방백·"!!"는 그대로. ("말하듯"은 내러티브 친밀도이지 반말이 아니다 — 불변 DNA #9, voice.md quick overlay.)

## 새 사례 추가 형식 (template)

한 사례당 위 블록을 복사해 쓴다. `before/after` 쌍과 **부정 예시**가 모이면 가치가 가장 크다(voice.md "아직 없는 것" 참조). raw 본문은 코드블록으로 감싸 줄바꿈을 보존한다.

```
## 사례 N — quick|deep / mode: 0|1|2
label: positive | negative     # negative = "이건 generic, 내 톤 아님"

### BEFORE (원본 소스 또는 raw 입력)
(원문/요지 — raw면 코드블록으로)

### AFTER (내가 실제로 쓴/쓸 버전)
(내 어투 버전. negative면 "내 톤이 아닌 generic 버전"을 넣는다)

### 왜 이게 나다운가 (한 줄)
(무엇이 'after'를 'before'와, 그리고 generic 요약과 다르게 만드는가. negative면 '왜 나답지 않은가')
```
