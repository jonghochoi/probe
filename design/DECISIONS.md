## 3. 분석 목록 (`index.html`)

### 3-1. 옵션으로 정한 것

| 항목 | 결정 |
|---|---|
| 가장 최근 카드 | 없음. 가장 최근 논문은 목록 첫 줄 |
| 추천 카드 | 없음 (데스크톱·휴대폰 모두) |
| 서재·연구 축 거르기 자리 | 목록 위 가로 줄 |
| 연구 축 줄 이름 칸 | 왼쪽에 옅은 주색 칸 + 연구 축 아이콘(겹친 층). 글자 없음 |
| 목록 · 한 줄 요약 | 보이기 |
| 목록 · 결과 줄 | 숨기기 |
| 목록 · arXiv 번호 열 | 보이기 |
| 목록 · 연구 축 칩 | 보이기 |
| 링크 | 아이콘만. 데스크톱은 제목 바로 뒤, 휴대폰은 연구 축 칩 옆 |
| 분량·용어 | 표시하지 않음 (그 칸은 휴대폰에서 링크 아이콘 자리) |
| 한 쪽에 몇 편 | 10 · 20 · 30, 기본 10 |
| 줄에 올리면 주요 그림 | 줄 아래에 떠오르는 카드 — 그림, 캡션 전문(자르지 않음), "Figure 2, 원문 §3". 폭 640px, 그림 높이는 화면의 55%까지, 카드는 화면 안에 머문다. 데스크톱만 |

### 3-2. 옵션 밖에서 정한 것

- **연구 축 줄**
  - "연구 축" 제목 글자와 서재 항목은 뺀다.
  - 오른쪽 끝에 "91편 · 최근 날짜"를 둔다 (데스크톱).
  - 항목의 숫자는 이름과 같은 글자 기준선에 맞추고, 색 점만 가운데 정렬한다.
  - 테두리는 글자색 24%, 그림자는 얇게 한 겹만 둔다. 넓게 번지는 그림자는 배경과 섞여 경계가 흐려진다.
  - 휴대폰에서는 옆으로 밀고, 오른쪽 끝에 "더 있음" 그라데이션을 두며, 끝에 닿으면 지운다. 이름 칸은 밀어도 왼쪽에 고정된다.
  - 누른 항목은 주색 바탕에 흰 글자, 색 점에 흰 테두리.
- **쪽 이동 줄**
  - [이전 1 2 … 10 다음] 오른쪽 끝에 [≡ 10 ˅] 하나만 둔다.
  - 누르면 위로 10편 / 20편 / 30편 메뉴가 열린다. 바깥을 누르거나 Esc를 누르면 닫힌다.
  - "1–10 / 91편" 표시와 구분선은 두지 않는다.
  - 휴대폰에서도 한 줄 (320px까지 확인).
  - 현재 쪽은 2px 밑줄.
- **추천 카드를 실험하며 버린 것**
  - 여러 카드 스타일, 링크·새로고침·결과 수치, "추천" 이름 칸 시안 모두 버렸다.
  - 남는 교훈: 카드 오른쪽에 아이콘 칸을 따로 두면, 휴대폰에서 제목이 좁은 칸에 갇힌다.

## 4. 신규 탐색 (`scout-new.html`)

페이지는 제목 띠 → 날짜 줄 → 추천 카드 → 후보 표 순서다. 묶음 제목은 없다
(분석 목록처럼). 카드와 표 모양이 둘을 가르고, 순위는 칩이 말한다.

### 4-1. 옵션으로 정한 것

| 항목 | 결정 |
|---|---|
| 묶음 제목 | 없음 (분석 목록처럼) |
| 연구 축 줄 | 빼기 — 탐색은 이미 연구 축별로 고른 결과 |
| 회차 고르기 자리 | 날짜 줄 (연구 축 줄 자리) |
| 날짜 줄 표시 | 날짜 + 편수 (`11.12 15`) |
| 회차 머리 | 없음 (날짜 줄이 회차를 보여 줌) |
| 추천 카드 글 | 모두 — 영어 원제목, 한 줄 요약, 평가 태그 |
| 추천 카드의 '1위' | 보이기 |
| 순위 표시 모양 | 칩 안에 `P2 · 2위` (카드와 표 공통, '추가'·'인접'도 같은 모양) |
| 평가 태그 | 카드에만 |
| 추천 카드 줄 나누기 | 줄을 고르게 — 5편이면 3 + 2, 짧은 줄의 카드는 넓어져 채움. 태블릿 두 칸, 휴대폰 한 칸 |
| 후보 목록 모양 | 분석 목록과 같은 표 — 열 제목 띠(arXiv · 논문 · 한 줄 · 연구 축), 제목 아래 한 줄 요약 |
| 논문 세부 내용 | 옆에서 열리는 서랍 (휴대폰은 아래에서 올라오는 시트) |
| 세부 내용 짜임 | 탭 — 문제 · 방법 · 결과 · 판단 |
| 세부 내용 제목 짓기 | 짧은 명사 + 회색 부제 (첫 화면 규칙) |
| 목록에만 오른 논문 · 근접 후보 | 보이지 않음 |
| 추천 카드의 주요 그림 | 카드 안 작은 그림 — 이름 아래, 원제목 위에 높이 150px (휴대폰 130px) |

### 4-2. 옵션 밖에서 정한 것

- **날짜 줄**
  - 분석 목록의 연구 축 줄과 같은 카드다. 위치·폭·높이가 픽셀까지 같다
    (페이지 여백을 분석 목록과 같게: 데스크톱 위 1.5rem, 휴대폰 1.1rem .9rem).
  - 왼쪽 옅은 주색 칸의 달력 아이콘이 달력 버튼이다. 오른쪽 "달력" 버튼은 없다.
  - 달력은 아이콘 아래, 날짜 줄 왼쪽 끝에서 펼쳐진다. 휴대폰도 같은 팝업이며
    페이지가 아래로 이동하지 않는다. 바깥을 누르면 닫힌다.
  - 고른 회차는 주색 바탕에 흰 글자. 휴대폰에서는 옆으로 밀고, 고른 날짜가
    자동으로 화면 안에 들어온다.
- **추천 카드**
  - 윗줄: 연구 축 칩(순위 포함) 왼쪽, arXiv 번호 오른쪽. 번호는 arXiv로 연결된다.
  - 제목이나 카드 아무 곳을 누르면 세부 내용이 열린다.
  - 평가 태그 줄은 모든 카드의 아래쪽 같은 높이에 붙는다. 휴대폰에서는 태그를 뺀다.
- **후보 표**
  - 줄 어디를 눌러도 세부 내용, arXiv 번호는 arXiv로.
  - 마우스를 올리면 분석 목록처럼 왼쪽에 주색 선.
  - 휴대폰에서는 번호 / 제목 / 요약 / 칩이 세로로 쌓인다.
- **세부 내용**
  - 지금 사이트의 회차 페이지(`s/<날짜>/index.html`)가 싣는 내용을 쓴다 — 논문 요지
    (문제의식 · 접근 · 성과), 연구 축별 시사점, 먼저 확인할 점.
  - 머리: 연구 축·순위, arXiv 링크, 이름, 영어 원제목, 그 아래 저자 · 출처 한 줄
    (탭 안에 되풀이하지 않는다), 한 줄 요약, 평가 태그.
  - 머리 아래 주요 그림을 크게 (높이 420px까지, 휴대폰 300px), 캡션 전문과 출처.
  - 그 아래 탭. 탭 이름은 두 글자 명사, "판단" 옆에만 확인할 점 개수를 회색 숫자로.

    | 탭 | 안의 제목 (굵은 명사 + 회색 부제) |
    |---|---|
    | 문제 | 질문 · 이 논문이 푸는 것 / 한계 · 기존 방법이 막힌 곳 |
    | 방법 | 핵심 · 무엇을 하나 / 차이 · 기존과 다른 점 |
    | 결과 | 기여 · 저자가 내세우는 것 / 가치 · 남는 것 |
    | 판단 | 시사점 · 연구 축별 / 확인 · 먼저 볼 것 · N |

  - 탭을 넷으로 나누는 까닭은 분량이다. 요지·시사점·확인할 점 세 탭이면 추천 60편의
    중간값이 약 1,190 / 200 / 230자로 한 탭에 73%가 몰린다. 넷으로 나누면 약 290 /
    250 / 320 / 200–450자다.
  - 아래 목록만 소개하는 첫 줄("저자들이 주장하는 세 가지"처럼 22자 미만)과, 머리의
    한 줄 요약을 되풀이하는 첫 줄은 싣지 않고 바로 목록을 보인다.
  - 닫기: ×, 바깥 누르기, Esc. 서랍은 내비 위에 뜬다.
- 학회 일정은 표시하지 않는다 (첫 화면에만).

## 5. 비교 (`cmp-new.html`)

분석 목록·신규 탐색과 같은 결: 제목 띠 → 연구 축 줄 → 카드. 묶음 제목은 없다.

| 항목 | 결정 |
|---|---|
| 연구 축 줄 | 두기 — 분석 목록과 같은 줄, 오른쪽 끝에 "9편 · 최근 날짜". 축을 누르면 그 축의 비교만 |
| 목록 모양 | 탐색 추천처럼 카드, 줄을 고르게 (9편이면 3 + 3 + 3) |
| 표의 둘째 줄 | 갈래 — 논문마다 입장 (표 모양으로 바꿀 때 쓰는 값) |

카드 하나는 위에서부터 이렇다.
- 윗줄: 연구 축 칩, 오른쪽에 작성 날짜.
- 질문 (제목 서체).
- `공통` 한 줄 — 둘 또는 셋이 같은 자리.
- 구분선 아래, 논문마다 한 줄: 이름과 그 논문의 입장.
- 카드를 누르면 그 비교 페이지로 간다.

## 6. 서재 (`shelf-new.html`)

분석 목록·신규 탐색과 같은 결: 제목 띠 → 종류 탭 → 표. 묶음 제목은 없다.
즐겨찾기·책갈피·메모는 서로 다른 것이라 아이콘을 하나로 묶지 않고 종류마다 둔다.

| 항목 | 결정 |
|---|---|
| 맨 위 모양 | 밑줄 탭 — `☆ 즐겨찾기 5 │ 책갈피 2 │ ✎ 메모 2`, 종류마다 아이콘. 논문 페이지의 요약·상세 탭과 같은 밑줄 |
| 나누는 방식 | 탭 — 한 번에 하나 |
| 즐겨찾기 모양 | 분석 목록과 같은 표 |
| 내보내기 · 가져오기 | 탭 줄 오른쪽 끝 ⋯ 메뉴 (JSON 내보내기, 마크다운 내보내기, 가져오기) |
| 조율실이 보여 줄 내용 | 예시 데이터 — 실제 저장소에는 쓰지 않는다 |

표는 종류마다 이렇다.
- **즐겨찾기:** 저장일 / arXiv / 제목, 아래 한 줄 요약 / 연구 축. 읽은 논문은 제목 끝에 "읽음".
- **책갈피:** 저장일 / arXiv / 제목, 아래 책갈피 자리(예: "2. 무엇을 바꿨나", 누르면 그 절로) / 연구 축.
- **메모:** 고친 날 / arXiv / 제목, 아래 메모 앞 두 줄 / 초안·게시됨.
- 비어 있으면 표 대신 무엇을 하면 채워지는지 한 줄로 안내한다.
- 휴대폰에서는 분석 목록처럼 날짜·번호 / 제목 / 둘째 줄 / 칩이 세로로 쌓인다.

## 8. 사이트로 옮길 때 고칠 코드

조율실은 빌드된 페이지 위에 CSS를 입히고 DOM을 옮기는 방식이라, 그대로
옮길 수 없는 부분이 있다.

1. **한 쪽 개수.** `filter.js`는 개수 버튼(`[data-size]`)에서 선택지를 읽는다.
   빌드가 10 / 20 / 30을 찍고, 쪽 이동 줄 끝의 메뉴로 옮긴다. `.pgstat`은 내지 않는다.
2. **가장 최근 카드 제거.** 카드를 빼면 그 논문의 목록 줄이 첫 쪽에 남아야 한다.
   카드만 숨기면, 카드 몫으로 비워 둔 줄 때문에 가장 최근 논문이 목록에서 사라진다.
3. **제목 뒤 링크 아이콘.** 지금 `.row-main`은 제목과 한 줄 요약을 감싼 링크
   하나라 그 안에 링크를 넣을 수 없다. 제목을 링크로 만들고 `::after`로 클릭
   영역을 칸 전체로 넓힌 뒤, 아이콘을 그 위(`z-index`)에 둔다.
4. **연구 축 줄이 상단 띠 위로.** 상단 띠(`.mast::before`)가 제목 아래로 약
   58px 더 내려온다. 줄 카드에 `position: relative; z-index: 1`이 없으면 띠가
   카드 위쪽을 물들인다.
5. **현재 쪽 밑줄.** 안쪽 그림자(`inset box-shadow`) 대신 배경 그라데이션으로
   그린다. 일부 브라우저에서 가장자리에 세로 선이 남는다.
6. **고운돋움.** 조율실은 Google Fonts에서 받는다. 사이트는
   `site/builder/fonts.py`가 서체를 코퍼스 글자로 잘라 직접 싣는다. 같은 방식으로
   넣어야 한다.
7. **휴대폰 가로 밀기 힌트.** `mask-image`를 쓰면 카드 테두리까지 지워진다.
   끝에 붙는 `::after` 그라데이션으로 그린다.
8. **내비 현재 메뉴 밑줄.** 쪽 번호와 같은 까닭으로, 안쪽 그림자 대신 배경
   그라데이션으로 그린다.
9. **탐색 세부 내용.** 조율실은 회차 페이지를 불러와 `.sc-item`의 `.sc-body`를
   꺼내 쓴다. 사이트에서는 빌드가 새 탐색 페이지에 같은 내용을 직접 싣거나,
   회차 페이지로 보낸다. 표시 규칙은 `builder/scouting.py`가 이미 지키는
   공개 범위를 그대로 따른다.
10. **날짜 줄 카드가 넘치지 않게.** 달력 팝업을 보이려고 카드의 `overflow`를
    풀면, 카드가 내용 폭만큼 넓어져 휴대폰 페이지가 옆으로 밀린다. 카드와 그
    부모에 `min-width: 0`을 준다.
11. **주요 그림.** 사이트는 그림을 지금처럼 arXiv 주소로 직접 불러온다 (그림 하나에
    주소 하나). 고르는 규칙은 7을 따른다. 탐색 추천의 그림은 빌드가 arXiv HTML을 읽어
    고르는 단계가 새로 필요하다.
12. **연구 축 페이지의 결정(D#).** 연구 축 페이지는 결정마다 제목과 `context/P*.md`의
    현재 선택 한 구절을 싣는다. 기호(`D#`)는 그 자체로 읽히지 않으니 홀로 노출하지 않고,
    제목을 앞세우고 기호는 작게 곁들인다. `context/`는 공개 레포에 이미 있는 정보라
    공개 범위는 걸림돌이 아니다. 옮길 때 `site/CLAUDE.md`의 첫 불변식("`context/`는 툴팁의 `D#`
    제목 너머로 공개되지 않는다")을 이 페이지까지 허용하도록 고쳐 쓴다. 논문
    요약(`builder/glance.py`)이 `D#`과 `context/`를 싣지 않는 규칙은 그대로다 —
    그 화면은 논문만으로 말한다.

## 9. 연구 축 — 페이지 대신 팝업

연구 축 칩(P0–P4)을 누르면 그 자리에 축 소개가 뜬다. 따로 된 페이지는 두지 않는다.
분석 · 비교 목록은 연구 축 줄로 이미 축별로 거를 수 있고, 탐색은 회차마다 축 순위를
칩에 단다 — 축 페이지에 같은 목록을 다시 두면 같은 것을 두 군데서 보게 된다. 칩을
누르는 독자가 묻는 것은 "이 축이 무엇을 다루는가"이고, 읽던 자리를 떠나지 않고 그
답만 보면 된다. 이 결정으로 1-5의 "연구 축 칩을 누르면 → 연구 축 페이지로"를 대신한다.

### 9-1. 팝업에 담는 것

| 항목 | 결정 |
|---|---|
| 머리 | 칩, 한국어 이름, 영어 이름 |
| 축 설명 | 있으면 보인다 (9-2). 없으면 이 줄만 빠진다 |
| 결정 | 제목만 — 이 축이 다루는 문제들의 목록. 기호(`D9NB` 등)는 제목 옆에 작게 |
| 결정의 답 (굵은 구절) | 보이지 않는다 |
| 분석 · 탐색 · 비교 목록 | 보이지 않는다 |

### 9-2. 축 설명은 선택

- 각 `context/P#.md`에 한국어 소개 단락을 둘 수 있다. 쓰지 않아도 된다 —
  `context/_TEMPLATE.md`의 뼈대에는 넣지 않으므로 검사기가 요구하지 않는다.
- 문장은 축 주인이 쓴다. 조율실의 한국어 문장은 `context/MASTER.md` §4의 영어 한
  줄을 옮긴 초안일 뿐이다. 소개 단락을 어떤 모양으로 적을지(빌드가 찾는 표시)는
  옮길 때 `context/CLAUDE.md`에 정한다.

### 9-3. 팝업 조율실에서 정한 것

조율실은 `playground/pillar-popup/`. 사이트 페이지에 팝업을 얹어 칩을 눌러 본다.

| 항목 | 결정 |
|---|---|
| 데스크톱에서 | 칩 아래 카드 |
| 휴대폰에서 | 아래에서 올라오는 시트 |
| 여는 방법 | 누르면 |
| 머리 | 축 색 띠 |
| 축 설명 | 있을 때만 보인다 |
| 결정 묶음 이름 | 다루는 문제 |
| 결정 기호(D9NB 등) | 작게 곁들임 |
| 아래 링크("이 축의 분석 보기") | 두지 않음 |

### 9-4. 옮길 때 한 일

- 모든 칩이 같은 팝업을 연다 — 분석 목록, 탐색 카드와 표, 비교 카드, 첫 화면,
  논문 페이지. 스크립트가 없으면 칩은 지금처럼 아무 일도 하지 않는다.
- 바깥 누르기 · Esc · ×로 닫는다. 칩은 키보드로도 연다(Enter).
- 축 이름, 설명, 결정 제목은 모든 페이지가 이미 받는 `corpus-index.js`에 싣는다.
- `site/CLAUDE.md`의 첫 불변식("`context/`는 툴팁의 `D#` 제목 너머로 공개되지
  않는다")을 축 소개 단락까지 허용하도록 고쳐 쓴다. 결정의 답은 여전히 싣지 않는다.
- `playground/pillar/`의 페이지 시안은 이 결정 전의 것으로, 남겨 두기만 한다.
- 소개 단락의 모양은 `context/CLAUDE.md` "Pillar introduction" — `> **소개** —`로 여는 인용 단락.

## 10. 논문 상세 (`p/<id>/`)

### 10-0. 최종 모습 (확정)

조율실 세 번(논문 상세 · 목차 · 종합)을 거쳐 정한 것을 한곳에 모은다. 10-1부터는 그 과정의 기록이다.
이 절과 아래 절이 다르면 이 절을 따른다.

**머리** (`pages.py` `_header`)

| 자리 | 모습 |
|---|---|
| 첫 줄 | 연구 축 칩(사이트가 거는 두 축, 누르면 축 팝업) · arXiv 번호(초록 링크) · 핵심 수치(`metric:`, 주색 알약) · 오른쪽 끝 "작성 날짜" |
| 이동 경로 | 없음 — 칩 줄이 그 자리 |
| 큰 제목 | 영어 원제목만. 한국어 주장은 요약 탭의 중심 주장 카드에만 |
| 제목 아래 | 한 줄 요약(`tagline:`, 회색) → 저자 · 소속 |
| 한 문단 요약 | 싣지 않음 (요약 탭이 대신. `summary:`는 메타 설명 · 검색 · `corpus.json`에만) |
| 분량 | 싣지 않음 |

**탭 줄** (`_tabstrip`)

| 항목 | 모습 |
|---|---|
| 탭 | 요약 · 상세 (· 비교 N). 영어 부제 없음. 밑줄 탭 |
| 오른쪽 끝 | 외부 링크 묶음 + 즐겨찾기 · 읽음 묶음. 휴대폰에서 링크는 아이콘만, 넘치면 링크 묶음 안에서 옆으로 밀림 |
| 고정 | 내비 바로 아래 고정. 높이 `--tabs-h` 하나(데스크톱 3.3rem, 휴대폰 3.1rem)를 목차 · 막 줄 · 제목 건너뛰기 여백이 모두 더한다 |

**요약 탭** — 근거 카드 넷을 두 줄에 둘씩. 카드 안 수식은 본문보다 한 단계 작게.

**상세 탭 본문** (`render.py`, `probefence.py`)

| 항목 | 모습 |
|---|---|
| 첫머리 | 주장 · 부제 · 한 문단 요약 묶음 없음. 바로 1막 |
| 막 머리 | 짧은 명사 + 회색 부제, 막 번호로 정함(`ACT_NAMES`) — 문제 · 무엇이 막혔나 / 방법 · 무엇을 바꿨나 / 검증 · 정말 되는가 / 시사점 · 연구 축에 걸리는 것. 가는 선 |
| 소절 제목 | 한국어 제목 + 영어 열쇠말(그대로) |
| 확인 문제 | `<details>`로 한 줄 접음("확인 + 질문 ›"), 누르면 펼침. 왼쪽 3px 주색 띠는 유지 |
| 읽기 진행 선 | 없음 |

**목차** (`_toc`, `paper.js`)

| 자리 | 모습 |
|---|---|
| 데스크톱 (폭 1025px 이상, 마우스 있음) | 요약 이정표 — 세로선 위 막 마디 넷(번호 · 짧은 명사 · 회색 부제 · 소절 수), 그 아래 지금 읽는 소절과 책갈피 소절만 |
| 펼치기 | 목차 자리에 마우스를 올리면 0.2초 뒤 전체 목차가 본문 위 카드로 펼침, 벗어나면 0.4초 뒤 닫힘. 키보드로 들어가면 바로 열림, Esc · 링크로 닫힘 |
| 소절 | 글 전체에 걸친 번호 + 한국어 제목, 자르지 않고 전부 |
| 스크롤할 때 | 지금 소절 점만 채워짐. 지나온 곳 색 채움 · 번짐 효과 없음 |
| 책갈피 | 소절 오른쪽 깃발(`shelf.js` 버튼). 남긴 소절은 요약 상태에서도 늘 보임 |
| 휴대폰 · 태블릿 · 마우스 없는 넓은 화면 | 탭 줄 아래 고정 막 줄 — ○ 문제 ─ ● 방법 ─ ○ 검증 ─ ○ 시사점 + 목차 버튼. 글 위 목차 상자는 숨김 |
| 목차 시트 | 아래에서 올라오는 시트, 데스크톱 전체 목차와 같은 이정표 모양 · 책갈피 깃발. 머리("목차")는 목록 위에 겹치지 않게 |
| 스크립트 없음 | 전체 목차가 그대로 보이고, 목차 버튼은 나오지 않음 |

**함께 고친 것**
- 작성 규칙 `analysis/AUTHORING.md`: 한 줄 요약 · 한 문단 요약 · H1 · 막 이름 · 축 칩이 실리는 자리, 확인 문제가
  접혀 실린다는 것.

- 쓰이지 않게 된 스타일 정리: 행동 줄(actbar), 이동 경로 날짜, 탭 영어 부제, 목차 영어 열쇠말, 본문 주장 부제.

### 10-5. 옮기며 정한 것 (옵션 밖)

- 막 이름은 재작성본의 `##` 글이 아니라 막 번호로 정한다(`render.py`의 `ACT_NAMES`). 작성 규칙
  R1이 막을 넷으로 고정하므로, 이름은 페이지의 것이다. 목차 묶음 제목과 막 줄도 같은 이름을 쓴다.
- 막 줄은 폭 1024px 이하에서만 보이고, 짧은 명사만 싣는다. 스크립트가 없으면 목차 버튼은 나오지
  않고, 글 위 목차 상자가 남는다.
- 접은 확인 문제는 조율실과 달리 왼쪽 3px 주색 띠를 그대로 둔다. `site/CLAUDE.md`가 "확인 문제는
  왼쪽 띠를 가진 곁 상자"로 정해 두었기 때문이다. 스크립트 없이도 열리도록 `<details>`로 짓는다.
- 휴대폰 탭 줄에서는 링크가 글자를 빼고 아이콘만 남긴다. 링크가 넷인 논문에 비교 탭까지 있으면
  링크 묶음이 자기 안에서 옆으로 밀린다 (탭 줄은 한 줄을 지킨다).
- 연구 축 칩은 사이트가 논문을 거는 두 축(`filed`)만 싣는다 — 목록 칩과 같다. 미분류면 칩이 없다.
- 고친 것: 요약 탭 근거 카드의 수식을 본문보다 한 단계 작게(카드 폭에 맞게). 점검 때 본 "카드 4의
  빈 그림 칸"은 지연 로딩 탓의 캡처였고, 그림은 정상이다.
- 작성 규칙(`analysis/AUTHORING.md`)을 함께 고쳤다 — 한 줄 요약·한 문단 요약·H1·막 이름·축 칩이
  어디에 실리는지, 확인 문제가 접혀 실린다는 것.
- 탭 줄을 고정하면서 높이를 `--tabs-h` 하나로 정했다(데스크톱 3.3rem, 휴대폰 3.1rem). 왼쪽 목차,
  휴대폰 막 줄, 제목으로 건너뛸 때의 여백이 모두 이 값을 더한다. 휴대폰에서는 내비 · 탭 줄 · 막 줄이
  세 겹으로 쌓인다 — 목차 조율실(10-6)에서 다룬다.

### 10-6. 목차 조율실 (진행 중)

사용자 의견: 데스크톱 왼쪽 목차가 무겁고, 글이 많아 구분이 잘 안 된다. 간단한 이정표 모양 시안이
필요하고, 휴대폰에 어떻게 옮길지도 함께 본다.

조율실 `playground/toc/` — 논문 상세 2차를 옮긴 사이트 위에 목차 시안을 얹는다.

| 옵션 | 선택지 |
|---|---|
| 데스크톱 목차 모양 | 지금 / 이정표 — 막 마디 + 소절 한 줄 / 이정표 — 지금 막만 펼침 / 점 레일 — 글자는 올리면 |
| 이정표의 소절 제목 | 한 줄로 자름 / 두 줄까지 (지금 읽는 소절은 늘 전부) |
| 소절 번호 | 보이기 / 숨기기 |
| 휴대폰 · 태블릿 막 줄 | 지금 / 지금 위치 한 줄 + 막별 진행 막대 / 이정표 점 / 막 줄 없이 구석의 목차 버튼 |
| 목차 시트 | 지금 모양 / 이정표 모양 |

#### 10-6-1. 1차 고름과 의견

고른 것: 점 레일 · 두 줄까지 · 번호 보이기 · 휴대폰 이정표 점 + 목차 · 이정표 시트.

의견:
- 점 레일은 점이 너무 몰려 보인다.
- 스크롤할 때마다 왼쪽이 계속 바뀌는 움직임(지나온 곳 색 채움, 지금 점의 번짐)이 거슬린다.
- 소절의 책갈피 표시가 보이지 않는다.
- 점 레일이 최선은 아니다. 정보가 많아 가려 본 것인데, 다 가리는 게 최선인지도 모호하다.

#### 10-6-2. 2차 시안

| 옵션 | 선택지 |
|---|---|
| 데스크톱 목차 모양 | 요약 이정표 — 막 넷 + 지금 소절, 올리면 전체 / 넉넉한 점 레일 + 막 이름, 올리면 전체 / 글 길이 비례 레일 + 막 이름, 올리면 전체 / 이정표 — 지금 막만 펼침 / 점 레일 (1차) / 지금 |
| 스크롤할 때 | 차분하게 — 지금 소절만 표시 / 지나온 곳까지 색이 참 (1차) |

- "올리면 전체": 목차 자리에 마우스를 올리면(키보드로 들어가도) 전체 목차가 본문 위로 펼쳐진다. 잠깐
  스치는 것으로는 열리지 않게 0.2초 늦게 열고 0.4초 늦게 닫는다.
- 책갈피: 모든 모양에 보인다. 글자가 있는 목록은 소절 오른쪽 깃발(올리면 눌러서 남기기), 점만 있는
  모양은 그 점이 깃발 모양으로 바뀐다. 요약 이정표는 지금 소절 말고도 책갈피 소절은 늘 보인다.
  휴대폰 목차 시트에도 같다.
- 글 길이 비례 레일: 화면 높이 하나에 글 전체를 줄여, 막과 소절이 글 속 자리에 놓인다. 눈금은 소절.

#### 10-6-3. 목차 결정 ("내 설정", 논문 목차 3차) — 사이트로 옮김

| 항목 | 결정 |
|---|---|
| 데스크톱 목차 모양 | 요약 이정표 — 막 넷 + 지금 소절, 마우스를 올리면 전체 |
| 이정표의 소절 제목 | 두 줄까지 (지금 읽는 소절은 전부) |
| 소절 번호 | 보이기 (글 전체에 걸친 번호) |
| 스크롤할 때 | 차분하게 — 지금 소절만 표시 |
| 휴대폰 · 태블릿 막 줄 | 이정표 점 (막 넷을 선으로) + 목차 |
| 목차 시트 | 이정표 모양 |

옮기며 정한 것:
- 목차는 빌드가 이정표 마크업으로 바로 찍는다(`_toc`). 스크립트가 없으면 전체 목차가 그대로 보인다.
- 요약 상태에서도 책갈피를 남긴 소절은 늘 보인다. 책갈피 깃발은 기존 `shelf.js` 버튼을 그대로 쓴다.
- 전체 목차는 0.2초 늦게 열고 0.4초 늦게 닫는다. 키보드로 들어가면 바로 열리고, Esc나 링크를 누르면 닫힌다.
- 마우스가 없는 넓은 화면(`hover: none`)은 태블릿처럼 막 줄 + 목차 시트를 쓴다.
- 지금 위치는 스크롤 위치로 계산하고, 바뀔 때만 표시를 고친다. 지나온 곳에 색이 차는 효과는 없다.
