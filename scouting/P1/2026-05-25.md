## 🥇 논문 1 — 우선순위 ★★★

**Dexora: Open-source VLA for High-DoF Bimanual Dexterity**
[arXiv:2605.18722](https://arxiv.org/abs/2605.18722) · Zongzheng Zhang, Jingrui Pang, Zhuo Yang, Kun Li, Minwen Liao · source: keyword-sweep (cs.RO+dexterous)

### (a) 관련 Pillar / Decision (P# / D#)

[P1](#ref-P1)의 [D1](#ref-D1)(분리 형태)·[D2](#ref-D2)(Body 출력 공간)·[D3](#ref-D3)(Hand 출력 공간)·[D7](#ref-D7)(π backbone 통합·분할) 네 결정에 모두 걸립니다. 데이터 수집 파이프라인 단에서 팔(arm) 거시 운동과 손가락(finger) 정밀 동작을 명시적으로 갈라낸 첫 공개 소스 VLA 시스템으로, 해부학적 Body/Hand 분리 가설을 데이터와 아키텍처 두 단에서 동시에 뒷받침합니다. [CP1](#ref-CP1) 코드 진입 전 단계에서 구현 경로가 가장 많이 겹치는 선행 사례입니다.

### (b) 진정으로 새로운 점

Dexora가 기존 연구와 벌어지는 지점은 크게 두 갈래입니다. 우선 **분리형 원격 조종(decoupled teleoperation)** 쪽 — 팔의 거시 운동학(gross arm kinematics)은 커스텀 외골격 배낭으로, 손가락의 정밀 동작(fine finger motion)은 Apple Vision Pro 마커리스 추적으로 각각 따로 캡처합니다. 이 분리가 곧 P1의 "Body = wrist/flange pose, Hand = finger joint command"라는 출력 공간 설계를 데이터 수집 단계에서 그대로 재현한 셈입니다. 두 축을 단일 채널로 묶어 수집하는 기존 단일 그리퍼 기반 VLA(예: π0.5)와 대비됩니다. 한편 **품질 인식 훈련(data-quality-aware training)** 쪽에서는, 오프라인 판별기(offline discriminator)가 클립 단위 가중치를 매겨 저품질 원격 조종 시연의 기여도를 깎는 방식으로 확산-트랜스포머 정책(diffusion-transformer policy)을 학습시킵니다. 10만 건 시뮬레이션 + 1만 건 실세계 궤적의 대규모 코퍼스를 함께 풀어, 실제 이중 팔·이중 손(dual-arm dual-hand) 플랫폼에서 기본 과제 90%, 다지 조작 과제 평균 66.7%(기준선 51.7%) 성공률을 기록하였습니다.

### (c) 의사결정 함의

다음 주 파이프라인 설계에 즉각적으로 영향을 미치는 항목은 아래와 같습니다.

- **D1 분리 형태 구현 참조**: Dexora의 "팔 외골격 + 손가락 비전 추적" 분리 파이프라인은 D1 v1(공유 트렁크 + 분리 헤드)의 데이터 수집 단계에서 정확히 같은 분리를 구현합니다. CP1 코드 작성 시 `arm_teleop_device: exoskeleton | wrist_tracker | joint_sensor`, `hand_teleop_device: vision_pro | glove | joint_sensor` 형태로 입력 채널을 분리하는 설계를 미리 확보해 두는 것이 자연스럽습니다.
- **D2·D3 출력 공간 검증**: 팔 궤적은 wrist pose(SE(3)) 형태로, 손가락 궤적은 finger joint angle 형태로 독립 저장됩니다. D2 v1(both-wrist/tool-flange pose)과 D3 v1(finger joint command)이 데이터 표현 측면에서 자연스럽게 분리 가능함을 확인합니다.
- **D7 backbone 선택**: Dexora는 π0.5 스타일의 확산-트랜스포머 아키텍처를 채택하되 고-DoF 이중 손 출력에 맞게 확장합니다. D7 v1의 "slice partition + FT" 진행 시 단일 팔 → 이중 팔·손 확장 경로에서 Dexora의 코퍼스 조합 전략(시뮬 100K + 실세계 10K)이 직접 참조됩니다.
- **품질 인식 훈련 도입 여부**: 원격 조종 데이터 품질 변동이 클 경우 오프라인 판별기를 훈련 루프에 추가합니다. 구체적 config: `data_quality_weighting: none | offline_discriminator`. CP1 코드 초안에 이 선택을 선택적 add-on으로 등록해 둡니다.

### (d) 먼저 검증해야 할 실패 모드

Dexora의 외골격 + Apple Vision Pro 파이프라인은 전용 하드웨어 비용이 높습니다. 우리 스택이 Sharpa / xhand 인터페이스를 사용하는 경우 팔 외골격 없이 wrist pose를 추정해야 하므로, 데이터 수집 단계에서 팔·손 분리의 정확도가 낮아질 수 있습니다. 또한 Dexora는 단일 팔이 아닌 이중 팔·손 설정에서 검증되었으므로, 단일 팔 + 단일 손 설정에서 같은 분리 파이프라인이 얼마나 성능을 유지하는지 확인이 필요합니다. 가장 저렴한 사전 점검: 기존 wrist velocity + joint position 신호만으로 팔·손 분리 수집이 가능한지, 시뮬레이션 환경에서 Dexora의 데이터 형식을 재현한 소규모 in-hand rotation 과제로 먼저 검증합니다.

## 🥈 논문 2 — 우선순위 ★★

**Learning Robust Dexterous In-Hand Manipulation from Joint Sensors with Proprioceptive Transformer**
[arXiv:2605.21330](https://arxiv.org/abs/2605.21330) · Senlan Yao, Chenyu Yang, Jaehoon Kim, Aristotelis Sympetheros, Robert K. Katzschmann · source: keyword-sweep (cs.RO+dexterous)

### (a) 관련 Pillar / Decision (P# / D#)

[P1](#ref-P1)의 [D3](#ref-D3)(Hand 출력 공간 — finger joint command)와 [D5](#ref-D5)(입력 모달리티 분리 — Hand = {tactile, proprio, local visual, VLA intent}) 두 결정에 모두 걸립니다. "관절 센서만으로 in-hand rotation을 수행할 수 있는가"라는 질문에 실험적 답을 내며, D3 v1의 finger joint command 방식이 고유감각(proprioception) 피드백과 맞물려 동작한다는 이론·실험 근거를 보탭니다. [CP2](#ref-CP2)(in-hand rotation 첫 실세계 데모) 설계 직전 Hand 입력 구성을 확정할 때 곧장 참조 자료가 됩니다.

### (b) 진정으로 새로운 점

인핸드 조작(in-hand manipulation) 연구의 대다수는 시각이나 촉각 센서로 물체 상태를 추적합니다. 이 논문은 **관절 센서만(exteroception-free)** 으로 텐던-구동형 다지 핸드(tendon-driven hand)에서 연속 정육면체 회전(continuous cube rotation)을 끌어냅니다. 핵심 장치는 두 가지입니다. 하나는 **Proprioceptive Transformer(PT)** — 관절 위치·속도 이력(joint position·velocity history)에서 암묵적 물체 상태(implicit object state)를 길어 올리는 Transformer 구조입니다. 나머지 하나는 **특권-교사→학생 증류(teacher–student distillation)** — 특권 물체 정보로 학습한 교사 정책을 PT로 증류해, 외부 지각 없이도 견줄 만한 성능을 냅니다. 실세계 ORCA 핸드 실험에서 기준선 대비 **3.1배 높은 회전 속도**, 정육면체 위치 추정 RMSE 23.4% 감소가 확인되었습니다. 촉각·시각 없이 관절 고유감각만으로 in-hand rotation이 가능함을 처음으로 실증하였습니다.

### (c) 의사결정 함의

- **D5 Hand 입력 집합 축소 가능성**: D5 v1의 Hand 입력 집합 "Hand = {tactile, proprio, local visual, VLA intent}" 중 `tactile` 및 `local visual` 없이도 in-hand rotation이 달성 가능하다는 직접적 증거입니다. 촉각 센서 미확보 상태의 CP1·CP2 단계에서 `hand_obs: proprio_only | proprio_tactile` 두 조건을 ablation 설계에 포함시키는 근거로 삼습니다. 구체적 config: `hand_input_obs: [joint_pos, joint_vel]` 단일 구성이 첫 베이스라인으로 충분할 수 있음을 의미합니다.
- **D3 finger joint command 피드백 루프 설계**: PT가 관절 이력에서 물체 상태를 암묵적으로 추출한다는 결과는, D3 v1의 finger joint command 루프에서 별도의 물체 추적 모듈 없이도 충분한 접촉 정보를 표현할 수 있다는 가능성을 보여줍니다. CP2 진입 시 "물체 상태 명시적 추정 vs. 관절 이력 암묵적 추출" 비교 ablation 조건을 Decision Log에 기록합니다.
- **D5 deferred (β) rate separation과의 상호작용**: PT가 25 Hz 이상의 관절 이력을 입력으로 사용한다면, D5 deferred 조건(body와 독립적인 고주파 hand 루프) 진입 시 관절 이력 기반의 고주파 Hand 전문가 루프 설계가 자연스럽습니다. `hand_ctrl_hz`를 body와 분리하는 인터페이스를 CP1 코드 초안에 포함시킵니다.

### (d) 먼저 검증해야 할 실패 모드

PT는 텐던-구동형 핸드(ORCA hand)에서 정육면체 회전이라는 단일 과제를 대상으로 합니다. 우리 스택의 Sharpa / xhand가 모터 인코더 방식이 아닌 다른 관절 센서를 사용하거나, 대상 과제가 단순 회전이 아닌 다지 접촉(fine manipulation)이면 PT의 Transformer 아키텍처가 동일한 방식으로 물체 상태를 추출할 수 있는지 불분명합니다. 또한 교사-학생 증류는 특권 정보(물체 pose)가 시뮬레이션에서 가용하다고 가정합니다. Sim2Real 이전 단계에서 ORCA와 하드웨어 인터페이스가 다른 핸드로 증류 과정을 재현하려면 추가 교사 학습이 필요합니다. 최소 사전 점검: Sharpa / xhand의 관절 센서 샘플링 레이트와 신호 노이즈를 확인하고, PT 입력 형식과 호환되는지 측정합니다.

## 🥉 논문 3 — 우선순위 ★

**SkiP: When to Skip and When to Refine for Efficient Robot Manipulation**
[arXiv:2605.15536](https://arxiv.org/abs/2605.15536) · Mingtong Dai, Guanqi Peng, Yongjie Bai, Feng Yan, Chunjie Chen, Lingbo Liu, Liang Lin, Xinyu Wu · source: citation-graph (π0.5 인용)

### (a) 관련 Pillar / Decision (P# / D#)

[P1](#ref-P1)의 [D6](#ref-D6)(조정 방향·흐름 — v1: body→hand, hierarchical flow) deferred 조건인 "slip fails to reshape arm motion in time" 트리거 설계에 간접 근거를 제공합니다. Skip(자유 공간 이동) 구간과 Key(접촉·파지·정렬) 구간의 구분은 P1에서 Body 전문가(거시 이동) 지배 단계와 Hand 전문가(접촉 정밀도) 지배 단계를 나누는 D6 전환 트리거(trigger) 설계에 참조됩니다. [CP1](#ref-CP1) ablation 설계 시 body→hand 전환 시점을 rule-based vs. motion-spectrum으로 비교하는 ablation 조건의 근거가 됩니다.

### (b) 진정으로 새로운 점

기존 imitation learning 정책은 조작 궤적의 모든 스텝을 동등하게 취급하지만, SkiP는 **Motion Spectrum Keying(MSK)** 알고리즘을 통해 수동 주석 없이 'Skip(자유 공간)' 구간과 'Key(접촉·파지)' 구간을 자동 분리합니다. Key 구간에서만 dense 예측을 수행하고, Skip 구간에서는 다음 Key 구간 진입 액션으로 직접 도약하는 **action relabeling** 메커니즘이 핵심입니다. 계층적 구조나 별도의 skip 계획기 없이 단일 통합 네트워크로 구현된다는 점이 기존 hierarchical 접근과 다릅니다. 72개 시뮬레이션 과제와 3개 실세계 과제에서 실행 스텝을 15–40% 줄이면서도 성공률을 유지하거나 향상시켰으며, 코드와 프로젝트 페이지를 공개하였습니다.

### (c) 의사결정 함의

- **D6 body→hand 전환 트리거 설계 참조**: MSK가 action signal의 local motion complexity를 기반으로 Key 구간을 탐지하는 방식은, D6 v1(body→hand hierarchical flow)에서 body action chunk 종료 후 hand 전문가 활성화 시점을 데이터 기반으로 결정하는 참조 알고리즘이 됩니다. CP1 ablation 설계에 `body2hand_trigger: rule_based | motion_spectrum_keying | learned_phase_token` 3가지 조건을 포함시킵니다.
- **Hand 전문가 활성화 지점 표현**: SkiP의 "Key segment entrance action"을 Hand 전문가의 조건 신호로 해석하면, body→hand conditioning 경계(D6 v1 hierarchical flow의 $a_b$ 핸드오버 지점)를 데이터에서 자동 추출하는 방법론의 기반이 됩니다. 이는 D4(Body↔Hand 정보 공유)의 v1 FiLM 조건화 시점을 정적으로 고정하지 않고 동적으로 선택하는 설계로 확장 가능합니다.

### (d) 먼저 검증해야 할 실패 모드

SkiP는 단일 통합 정책 네트워크로 동작하며, P1의 명시적 Body/Hand 전문가 분리와 구조가 다릅니다. MSK가 탐지하는 "Key 구간"이 P1의 Hand 전문가 활성화 시점(contact-rich 구간)과 항상 일치한다는 보장이 없으며, 특히 in-hand rotation처럼 전 구간이 접촉 집약적인 과제에서는 MSK의 구간 분리가 의미를 잃을 수 있습니다. 또한 SkiP의 action relabeling은 imitation learning(BC) 기반이어서 flow matching 정책(π0 backbone)에서의 적용은 추가적인 설계 수정이 필요합니다. 가장 저렴한 사전 점검: in-hand rotation 과제에서 MSK가 탐지하는 Key/Skip 구간 분포를 시각화하여 Hand 전문가 활성화 구간과 얼마나 일치하는지 확인합니다.

### Decision Log

**D3 deferred (iii) 임피던스 → 관절 명령 복수 검증 확보**: Proprioceptive Transformer는 관절 명령만으로 접촉 과도 없이 in-hand rotation 3.1배 성능 향상을 달성했습니다. D3 v1의 "finger joint command" 선택이 올바름을 두 번째 독립 논문(05-22 AT-VLA: 25 Hz 촉각 + 관절 듀얼 스트림에 이어)이 지지합니다. D3 deferred "(iii) impedance → trigger: stiff position control causes excessive contact force / CP2" 트리거 조건은 PT 결과에 따라 CP2 이전 단계에서 확인이 필요한 수준이 낮아졌습니다.

**D6 v1 전환 트리거 설계를 CP1 ablation에 포함**: SkiP의 MSK 알고리즘이 action signal complexity로 Key/Skip 구간을 자동 탐지하는 방식을 D6 body→hand 전환 트리거 설계의 데이터 기반 접근으로 참조합니다. CP1 ablation에 `body2hand_trigger: rule_based | motion_spectrum_based` 두 조건을 포함시키도록 Decision Log를 업데이트합니다.

**D1 분리 형태 외부 구현 증거 확보**: Dexora가 "팔 외골격 + 손가락 비전 추적"이라는 데이터 수집 수준 분리를 통해 90%/66.7% 성공률을 달성한 결과는 D1 v1(공유 트렁크 + 분리 헤드)의 구현 방향이 올바름을 지지합니다. CP1 코드 작성 시 Dexora의 데이터 포맷을 호환 입력으로 활용하는 방안을 §9.A 구현 결정에 추가합니다.
