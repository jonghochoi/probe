## 🥇 논문 1

**Decoupled Asynchronous System for Humanoids (DASH): Latency-Agnostic Scaling of Vision-Language-Action Models for Humanoid Manipulation**
[arXiv:2611.11854](https://arxiv.org/abs/2611.11854) · Bingzhang Wang 외 6인 · arXiv preprint · source: keyword-sweep

**점수 9/15** · R3 · N2 · M2 · Real2 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문

[![P1](https://img.shields.io/badge/P1-fddcc2.svg)](#ref-P1) / [![D1MZ](https://img.shields.io/badge/D1MZ-d97706.svg)](#ref-D1MZ)

### (b) 논문 요지

- 느린 VLM과 빠른 액션 헤드를 분리해 제어 주기를 고정
- **문제** — 백본이 제어 경로에 놓여, 추론 중 로봇이 움직이는 동안 실행 행동이 점점 낡은 관측에 조건화되는 문제
  - 청크는 추론 시간 L이 지난 뒤에야 나와 지연되고 공간이 어긋난 행동이 됨
  - 열린 루프 지표에서는 보이지 않고, 닫힌 루프에서 느리고 주저하며 떨리는 조작으로 드러남
  - 인간형 손재주 조작에서 가장 두드러짐
- **기존 한계** — 동기 실행 VLA에서 모델 크기가 의미 일반화와 제어 반응성의 맞교환으로 작용
  - 큰 백본은 일반화와 지시 이행에 유리하나 느려서 낡은 관측 문제를 키움
  - 저자 주장은 이 맞교환이 법칙이 아니라 동기 실행의 산물이라는 것
- **핵심 방법** — 정책을 느린 의미 스트림과 빠른 반응 스트림으로 나누어 독립 주기로 동시에 실행
  - **System 2와 System 1** — VLM 서버와 flow-matching 액션 헤드가 환경·VLM 서버·액션 서버 세 프로세스로 LCM 통신하며, 제어 주기는 액션 헤드만으로 결정
  - **교차 시간척도 융합** — 고정 VLM의 캐시된 다층 상태와 액션 헤드 자체 ResNet 인코더의 신선한 시각 토큰을 헤드 안에서 결합
  - **비동기 학습** — VLM 입력을 무작위로 샘플한 지연만큼 액션 헤드 입력과 어긋나게 해, 명시적 지연 입력 없이 낡은 맥락 대응을 학습
  - **적응형 시간 집계기** — 겹치는 청크를 분수 보간으로 정렬해 가변 추론 지연을 흡수
- **차별점** — 이중 시스템 설계를 따르되 배포 시 마주칠 낡은 의미·신선한 지각의 조합을 학습에서 재현
  - 동기 학습은 이 분포를 보여 주지 않는다는 점을 구조(신선한 시각 인코더)와 학습(비동기 입력) 양쪽에서 메움
- **핵심 기여** — 시스템, 스케일링 결과, 학습 레시피
  - **DASH** — 손 달린 인간형 로봇에 배치된 비동기 VLA 시스템과 추론 파이프라인 명세
  - **지연 무관 스케일링** — 추론 지연을 시뮬레이션 시간에 과금하는 비동기 RoboTwin에서 백본 0.8B–8B 구간 동기 9.7–4.1Hz 대비 20Hz 유지, 제어 주기 2.1–4.9배, 성공률 +1.0–+5.9pp
  - **실물 인간형** — pick-and-place 24회 중 23회 성공, 동기 파이프라인 16회
  - **레시피 절제** — 백본 고정과 신선한 시각 경로를 Table IV에서 절제
- **가치** — 모델 크기를 속도와 품질의 맞교환이 아닌 자유 설계 축으로 바꾸는 경로 제시

### (c) 시사점

- 백본 크기와 제어 주기를 떼어 놓는 프로세스 단위 주기 분리의 수치 근거
- **주기 분리 비교점** — 모달리티별 주기 분리를 보인 πR²와 달리 백본과 액션 헤드를 프로세스로 분리한 사례로, 같은 백본 크기별 동기 대비 수치 확보
- **헤드 쪽 신선한 지각** — 액션 헤드가 자체 시각 경로를 갖는 설계가 낡은 의미를 보정한다는 절제 근거
- **도입 비용** — 프로세스 분리와 비동기 학습 레시피 변경이 필요하고 코드 비공개라 직접 구현 필요

### (d) 먼저 확인할 점

- **실물 범위** — 한 과제 pick-and-place 24회뿐으로 접촉 집약적 손재주 과제 검증 없음
- **벤치마크 성격** — 지연을 시뮬레이션 시간에 과금하도록 저자가 고친 RoboTwin이라 외부 벤치마크 수치와 직접 비교 불가
- **반복·한계** — 반복 시드와 한계 서술 없음
- **전이 주의** — 분리 기준이 시스템 단위(느림과 빠름)이며 신체 부위 분할은 아님, 부위별 전문가에 그대로 옮겨지는지는 별개 문제

## 🥈 논문 2

**Zero-Shot Compositional Generalization for Embodied Manipulation**
[arXiv:2611.22797](https://arxiv.org/abs/2611.22797) · Baicheng Li 외 10인 · arXiv preprint · source: citation-graph

**점수 7/15** · R3 · N2 · M2 · Real0 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문

[![P1](https://img.shields.io/badge/P1-fddcc2.svg)](#ref-P1) / [![D1QT](https://img.shields.io/badge/D1QT-d97706.svg)](#ref-D1QT)

### (b) 논문 요지

- 도구 공간 목표로 로봇별 네이티브 디코더를 감독
- **문제** — 로봇별로 모은 데모에서 일부 로봇–과제 조합이 비고, 관절 라벨이 시연 로봇의 기구학 사슬에 묶이는 문제
  - 같은 관절 수여도 같은 수치가 도구를 다르게 움직임
  - 모든 조합을 수집하면 비용이 로봇 수와 과제 수의 곱으로 증가
- **기존 한계** — 라벨을 공통 폭으로 패딩하는 방식은 네트워크 입출력만 맞출 뿐 물리적 의미를 잇지 못함
  - 공유 모델이 이미지·언어·과제 구조에서 전이를 배우더라도 네이티브 라벨 사이에는 명시적 대응이 없음
  - 네이티브 복원만으로는 교차 인터페이스 관계가 정해지지 않음
- **핵심 방법** — 시연 명령이 정하는 도구 목표를 다른 로봇의 네이티브 인터페이스 감독으로 사용
  - **공유 좌표** — 소스 행동을 공유 좌표로 인코딩하고 소스 로봇과 타 로봇의 네이티브 디코더가 각각 복원
  - **기하 감독** — 보정된 순기구학으로 도구 위치·자세·열림 목표를 만들고, 도달 가능성 양성 검사로 타 로봇에 줄 목표를 선택
  - **네이티브 복원** — 시연된 구성을 유지하는 기준점 역할
  - **정책 학습** — 시각-언어 정책이 공유 행동을 예측하고 해당 로봇의 네이티브 디코더로 실행하며, 한 예측이 소스·타 로봇 실현 양쪽으로 기하 감독을 받음
- **차별점** — 관절 라벨의 패딩이 아니라 로봇 기하로 행동 사이의 대응을 지정
  - 타 로봇의 관절 라벨 없이도 소스 명령이 타 로봇 디코더를 감독
- **핵심 기여** — 두 가지 감독 경로와 그 검증
  - **인터페이스 학습** — 시연 유래 도구 목표로 이종 전팔 행동 인터페이스 학습, 네이티브 복원만으로 의미가 미정인 이유를 인터페이스 수준 모호성 분석으로 설명
  - **정책 감독** — 정책 예측을 소스와 자격 있는 타 로봇 실현으로 함께 감독
  - **검증** — 세 백본과 두 시뮬레이터에서 일치 노출 대조, 행동 수준 진단, 반복 정책 학습으로 누락된 로봇–과제 조합의 전이 개선 확인
- **가치** — 모든 로봇–과제 조합을 수집하지 않고 기존 데모를 재사용하는 경로 제시

### (c) 시사점

- 관절 라벨 대신 도구 공간 공유 행동을 둔 설계의 대조 실험 근거
- **행동 공간 비교점** — 손 관절 명령을 잠재 공간으로 바꾼 XL-VLA와 달리 도구 공간 목표와 로봇별 네이티브 디코더로 푼 사례
- **대조군 확보** — 네이티브 관절 예측과 같은 백본에서 일치 노출로 비교한 결과 확보
- **도입 비용** — 로봇 기하와 보정, 도달 가능성 검사 구성이 필요하고 코드 비공개

### (d) 먼저 확인할 점

- **실물 없음** — 결과가 시뮬레이터 두 종에 한정되고 실물 로봇 결과 없음
- **대상 범위** — 전팔 행동 인터페이스를 다루며, 손가락 수준 행동의 검증은 본문에서 확인되지 않음
- **한계 서술** — 반복 정책 학습은 있으나 한계나 실패 모드의 별도 서술 없음
- **전제** — 보정된 기구학과 도달 가능성 검사가 전제라 보정 오차에 대한 민감도 확인 필요

## 🥉 논문 3

**Kimodo-Policy: Learning Kinematic Action Models for Humanoid Loco-Manipulation**
[arXiv:2611.11554](https://arxiv.org/abs/2611.11554) · Yunheng Wang 외 14인 · arXiv preprint · source: keyword-sweep

**점수 11/15** · R2 · N3 · M3 · Real3 · Repro0 — arXiv comment "Project page: https://kimodo-policy.github.io/" — 프로젝트 페이지만 있고 코드 문구 없음

### (a) 관련 Pillar / 질문

[![P1](https://img.shields.io/badge/P1-fddcc2.svg)](#ref-P1) / [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS) [![D9ZP](https://img.shields.io/badge/D9ZP-d97706.svg)](#ref-D9ZP)

### (b) 논문 요지

- 사전학습 모션 생성기를 행동 백본으로 쓰는 KAM
- **문제** — 인간형 이동 조작은 고차원 전신 모션을 시간·공간으로 정합해 생성하는 일이 핵심이며, 과제 이해와 인지만으로는 실행 가능한 모션이 나오지 않는 문제
- **기존 한계** — VLA는 의미, WAM은 시각 동역학의 사전지식을 쓰지만 로봇 모션의 구조적 규칙을 담는다는 보장이 없음
  - 행동 지도와 하위 정책 학습으로 전신 능력을 얻을 수는 있으나, 모션 공간 구조를 반영한 행동 표현과 의존성은 따로 필요
- **핵심 방법** — 동결한 Kimodo 텍스트-모션 백본에 가벼운 ControlNet 시각 조건을 더한 정책
  - **루트–몸–손 3단계** — 루트 궤적 생성, 루트에 조건화한 몸 관절 모션, 몸 특징과 시각 맥락에서 손 제어 예측
  - **모션 히스토리 조건** — 측정된 모션을 접두로 복원하는 제약 완성으로 쿼리를 구성하고, 청크 일부만 실행한 뒤 재예측
  - **규모와 실행** — 678M 중 92M만 학습하고 전신 추적 컨트롤러(SONIC)를 거쳐 실행
- **차별점** — 시각·언어 사전학습 대신 모션 생성 모델 자체를 정책의 주 백본으로 사용
  - 전신 모션이 정책의 출력일 뿐 아니라 파운데이션 모델 사전학습의 직접 대상
- **핵심 기여** — 패러다임, 인스턴스, 벤치마크와 실물 결과
  - **KAM** — 사전학습 모션 생성기를 백본으로 삼는 Kinematic Action Models 제안
  - **Kimodo-Policy** — 동결 백본과 가벼운 시각 조건의 첫 인스턴스
  - **시뮬레이션** — 다중 과제 HumanoidArena 72.14%로 비교 정책 중 최고, SIMPLE은 경쟁적 성능
  - **실물** — 8개 과제 평균 60%(80회 중 48회), 정책 사전학습 없는 변형 45%, GR00T N1.6 약 31%, `Ψ0` 35%
  - **절제** — HumanoidArena 세 과제 평균에서 무작위 초기화 18.33%, 미세조정 31.67%, 동결 51.67%
- **가치** — 모션 생성이 VLA·WAM을 보완하는 인간형 행동 모델의 기반이라는 초기 증거

### (c) 시사점

- 루트→몸→손 위계 분할이 사전학습 모션 백본 위에서 작동한 사례
- **분할 사례** — 부위별 단계 생성에서 앞 단계 출력이 뒤 단계를 조건화하는 상향식 아닌 하향식 결합의 실제 구현
- **백본 선택지** — 동결 백본과 별도 조건 모듈로 적응하는 방식이 미세조정보다 높다는 절제 수치
- **도입 비용** — 모션 생성기와 특정 추적기에 의존하며 코드 비공개

### (d) 먼저 확인할 점

- **분할 효과 분리** — 절제가 사전학습 백본·동결·학습 목표·기울기 분리를 다루지만 위계 분할과 단일 디코더의 직접 비교는 확인되지 않음
- **추적기 의존** — 저자 한계 서술대로 SONIC 제어 스택에서만 평가되었고 다른 추적기로의 전이는 미검증
- **실물 표본** — 과제당 10회 시행이라 저자도 배포 신뢰도가 아닌 이 평가 집합의 성능으로 한정하며, 실시간 청킹 효과는 분리하지 않음
