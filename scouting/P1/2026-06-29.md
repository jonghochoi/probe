## 🥇 논문 1 — 우선순위 ★★★

**T-Rex: Tactile-Reactive Dexterous Manipulation**
[arXiv:2606.17055](https://arxiv.org/abs/2606.17055) · Dantong Niu, Zhuoyang Liu, Zekai Wang, Boning Shao 외 · source: keyword-sweep

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-1f77b4.svg)](#ref-P1) / [![D3](https://img.shields.io/badge/D3-d97706.svg)](#ref-D3) [![D5](https://img.shields.io/badge/D5-d97706.svg)](#ref-D5)

### (b) 핵심 기여

- **기존 VLA의 촉각 무시·정적 인코더 한계 명시** — 현재 VLA 모델: 촉각 모달리티 미포함 또는 정적 인코더만 탑재 → 실시간 동적 촉각 반응 불가; 학습 데이터 부재·표준 평가 미정립·아키텍처 제약이 복합 원인
- **세 기여의 통합**:
  - **100시간 규모 촉각 풍부 데이터셋** — 기초 운동 원시패턴(elementary motor primitives) 우선 수집 파이프라인 신규 설계; 다양한 접촉 유형 포괄
  - **Temporal Tactile VQ-VAE 인코더** — 고주파 촉각 신호를 이산 시간 토큰으로 압축; 기존 VLA 능력 손상 없이 촉각 스트림 통합
  - **Variable-Rate Mixture-of-Transformers (MoT) 아키텍처** — 모달리티별 업데이트 주파수 분리(시각·언어 저주파, 촉각 고주파); 가변율 구조로 실시간 반응성과 시맨틱 이해 동시 유지
- **평가** — 12개 태스크(섬세한 힘 제어·변형체 조작 포함); 최강 베이스라인 대비 평균 성공률 +30% 이상
- **진정으로 새로운 점** — 시간적 VQ-VAE 촉각 인코더 + 가변율 MoT VLA 통합 최초; 대규모 촉각 데이터셋과 표준 평가 동시 제시

### (c) 시사점

- **핸드 액션의 감각 입력 확장 경로 직접 제시** — 시각만으로 가리는 접촉 정보를 촉각 토큰이 보완; 고-DoF 손가락 관절 명령 출력을 닫힌 루프로 보정하는 실세계 감각 피드백 경로 외부 검증
- **가변율 모달리티 분리의 실용성 증거** — 촉각(고주파)과 시각(저주파)의 처리 주기를 분리하는 구조가 12개 실세계 태스크에서 성능 개선 확인; 모달리티별 처리 주파수 분리 아키텍처의 독립 근거
- **플러그인 데이터·인코더 경로** — 기존 VLA에 촉각 VQ-VAE 인코더 추가 방식 채택; 핸드 액션 전문가 설계 시 별도 촉각 입력 스트림 추가의 구현 복잡도 파악 가능

### (d) 먼저 확인할 점

- **코드·데이터 공개 여부 미확인** — 100h 데이터셋 공개 계획 및 촉각 센서 기종·핸드 플랫폼 사양 본문 확인 필요
- **VLA 백본 종류 미확인** — 어느 기존 VLA(π0·OpenVLA 등)에 MoT를 결합했는지 본문 확인; π0 기반이면 D7 v1과 직접 비교 설계 가능
- **저렴한 점검** — 12개 태스크 중 고-DoF 손가락 관절 제어(비-그리퍼) 태스크 비중 확인; 촉각 없이 시각만으로 동일 태스크 시도 시 성능 하락폭 측정으로 촉각 채널의 필요성 1차 추정 가능

## 🥈 논문 2 — 우선순위 ★★

**VQActFlow: Vector-Quantized Action Mode Steering for Multi-Task Robot Manipulation**
[arXiv:2606.21600](https://arxiv.org/abs/2606.21600) · Zhigen Zhao, Mark Leggiero, Yipu Chen 외 · source: keyword-sweep

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-1f77b4.svg)](#ref-P1) / [![D1](https://img.shields.io/badge/D1-d97706.svg)](#ref-D1) [![D3](https://img.shields.io/badge/D3-d97706.svg)](#ref-D3)

### (b) 핵심 기여

- **단일 네트워크 멀티-태스크 한계 명시** — 단일 네트워크가 질적으로 다른 액션 모드를 멀티모달 데모 분포에서 선택 → 모드 선택 오류 시 잘못된 태스크 실행 또는 실행 불가 액션 생성
- **VQActFlow 세 요소**:
  - **이산 액션 코드북** — 연속 액션 청크를 학습된 이산 코드로 토크나이즈(VQ-VAE 기반); 액션 모드를 표현 수준에서 분리 → 멀티태스크 학습 구조적 우위
  - **Variational Flow Matching** — 코드 시퀀스를 변분 flow matching으로 생성; 액션 모드 전체에 걸쳐 명시적 선호도 유지
  - **추론 시 이중 guidance** — 언어 조건 classifier-free guidance(태스크 모드 유도) + 학습된 코드북 critic(실행 가능성 신호) 결합
- **평가** — LIBERO 시뮬레이션 + Unitree G1 휴머노이드(실세계 전신 픽앤플레이스) + ALOHA 양팔 플랫폼(접촉 집약 태스크); 연속·이산 베이스라인 모두 능가
- **진정으로 새로운 점** — VQ + 변분 flow matching + 추론 시 이중 guidance 조합 최초; 실 G1 휴머노이드에서 이산 액션 토크나이저 유효성 검증

### (c) 시사점

- **이산 코드북이 연속 분리 헤드의 비교군으로서 적합성 확인** — 연속 출력 헤드 분리 대신 이산 토크나이저로 액션 모드를 분리하는 경쟁 경로; 실 G1 휴머노이드 검증으로 비교 설계 현실성 확인
- **액션 모드 불연속 구조의 표현력 검증** — 멀티태스크 환경에서 이산 표현이 연속 표현 대비 구조적 우위 제공; 연속 바디·핸드 헤드 분리 시 모드 간섭 위험 예방 설계의 근거 추가
- **코드북 critic의 실행 가능성 신호** — 학습된 feasibility critic가 추론 시 액션 선택을 보정; 핸드 액션 전문가 출력의 실행 가능성 필터 설계 시 참고 패턴

### (d) 먼저 확인할 점

- **코드북 크기 민감도** — VQ 코드북 크기가 핵심 하이퍼파라미터; 고-DoF 손가락 관절 공간에서 코드북 크기 대비 커버리지 손실 정도 확인 필요
- **실 G1 태스크 범위** — 전신 픽앤플레이스이므로 손가락 관절 정밀 제어 포함 여부 불명확; 단순 그리퍼 제어 가능성 확인 필요
- **코드 공개 미확인** — 코드북 학습 파이프라인 공개 여부 본문 확인 필요
- **저렴한 점검** — ALOHA 양팔 접촉 집약 태스크에서 이산 vs. 연속 ablation이 존재하는지 확인; 해당 결과가 연속 헤드 분리 선택에 직접 비교 근거 제공

## 🥉 논문 3 — 우선순위 ★

**PAMAE: Phase-Aware-MoE Action Experts Towards Reliable Flow-Matching Vision-Language-Action Policies**
[arXiv:2606.27144](https://arxiv.org/abs/2606.27144) · Jiayu Yang, Tao Yang, Xiang Chang, Fei Chao, Changjing Shang, Qiang Shen · source: keyword-sweep

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-1f77b4.svg)](#ref-P1) / [![D1](https://img.shields.io/badge/D1-d97706.svg)](#ref-D1) [![D7](https://img.shields.io/badge/D7-d97706.svg)](#ref-D7)

### (b) 핵심 기여

- **단일 공유 액션 전문가의 구조적 한계 명시** — 기존 flow-matching VLA: 모든 실행 단계에 동일한 단일 액션 전문가 적용 → 단계별 제어 패턴 포착 불가; 다단계 조작에서 신뢰도 저하
- **PAMAE(Phase-Aware-MoE Action Module) 세 핵심**:
  - **스파스 전문가 혼합** — 단일 액션 전문가를 스파스 MoE로 교체; 사전학습 VLA 백본 보존하는 플러그인 방식
  - **페이즈 인식 라우터** — 경량 페이즈 예측 헤드가 실행 단계 단서(execution-phase cues) 추출 → 라우팅 정렬 목적함수로 단계별 전문가 할당 안정화
  - **2단계 학습** — 1단계: 표준 flow-matching 손실로 전문가 모듈 워밍업 → 2단계: 보조 감독하 페이즈 일관 라우팅 최적화
- **평가** — 다단계 조작 시뮬레이션 태스크; 강력한 VLA 베이스라인 대비 태스크 성공률 최대 +9.2%; ablation으로 페이즈 감독 라우팅 + 단계별 학습 모두 필수임 확인
- **진정으로 새로운 점** — 실행 페이즈 단서 기반 라우팅 정렬 목적함수를 flow-matching VLA에 적용 최초; 기존 백본 미변경 플러그인 설계

### (c) 시사점

- **단일 액션 전문가의 다단계 실패 정량 근거** — 단일 공유 전문가가 단계별 제어 패턴을 포착하지 못한다는 직접 실증; 해부학적 바디·핸드 분리가 단계 분리와 병행되는 이중 분리 아키텍처의 외부 정당화
- **백본 보존 + MoE 삽입 패턴** — 사전학습 VLA 백본을 유지한 채 MoE 액션 모듈만 교체; π0 백본 슬라이싱 후 바디/핸드 헤드 분리에 추가 단계 분리 결합 가능성 탐색 경로
- **페이즈 예측 헤드 아이디어** — 경량 보조 헤드로 실행 단계 예측; 바디→핸드 계층 흐름에서 접촉 단계 인식 보조 헤드 추가 시의 구현 복잡도 사전 파악 경로

### (d) 먼저 확인할 점

- **시뮬레이션 전용** — 실세계 검증 없음; 실제 접촉 집약 태스크(고-DoF 핸드)에서 페이즈 라우팅 유효성 미검증; 이 점이 ★ 등급 결정 요인
- **전문가 수 민감도** — 스파스 MoE의 전문가 수 선택이 성능에 중요; 최적 전문가 수와 다단계 수의 관계 본문 확인 필요
- **코드·데이터 미공개** — 시뮬레이션 셋업 재현 경로 불명확; 오픈 벤치마크 사용 여부 확인 필요
- **저렴한 점검** — π0 기반 VLA에 PAMAE 적용 시 페이즈 수와 바디/핸드 전환 수의 일치 여부 확인으로 단계 분리와 해부학적 분리의 정합성 1차 평가 가능
