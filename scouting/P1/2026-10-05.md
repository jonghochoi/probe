## 🥇 논문 1

**DualWAM: Dual-System World Action Models for Asynchronous Global Planning and Local Refinement**
[arXiv:2609.24868](https://arxiv.org/abs/2609.24868) · Yixin Zheng, Jiangran Lyu, Yuntian Deng 외 6인 · arXiv preprint · source: keyword-sweep · 코드 공개 예정

**점수 11/15** · R3 · N2 · M2 · Real3 · Repro1 — arXiv comment "Project page: https://steveouo.github.io/DualWAM-Web/"

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D1MZ](https://img.shields.io/badge/D1MZ-d97706.svg)](#ref-D1MZ) [![D5DQ](https://img.shields.io/badge/D5DQ-d97706.svg)](#ref-D5DQ) [![D5SH](https://img.shields.io/badge/D5SH-d97706.svg)](#ref-D5SH)

### (b) 논문 요지

- 전역 계획과 손목 국소 정제를 분리한 이중 시스템 WAM
- **문제** — 미래 시각 예측 비용 때문에 긴 액션 청크로 추론 비용을 나눠 쓰며 폐루프 반응성 저하
  - 청크를 줄이면 world-action 생성 빈도가 늘고, 근시안적 다음 청크 예측이 국소 외형 지름길을 선호
- **기존 한계** — 예측 축소·압축·비동기 디코딩 접근이 디노이징 단계, 시각 맥락, 갱신 주기를 한 생성 과정 안에서 함께 특화하지 않음
- **핵심 방법** — 하나의 world-action 생성을 전역 계획(System 2)과 국소 정제(System 1) 두 단계로 분해
  - System 2 — 다중 뷰 관측으로 넓은 world-action 청크를 높은 노이즈에서 중간 임계까지 양방향 디노이징해 낮은 주기로 전역 계획 수립
  - System 1 — 중간 디노이징 상태에서 시간 정렬된 짧은 창을 꺼내 최신 손목 관측만으로 저노이즈 정제 완료, 매 제어 갱신마다 수행
  - 비동기 운용 — 전역 계획 1회를 여러 국소 갱신이 재사용
- **차별점** — 한 공유 디노이징 궤적 위에서 갱신 주파수, 디노이징 구간, 시각 관측 공간(다중 뷰 대 손목 전용)을 함께 분리
  - 손목 관측이 국소 기하·모션·접촉 단서를 제공한다는 근거로 빠른 쪽에 손목 전용 배정
- **핵심 기여** — 설계 제안과 로봇 평가, 보조 데이터·배포 연구
  - Franka·Galbot 제로샷 조작 과제에서 가장 강한 평가 베이스라인 대비 평균 성공률 4.5%p 향상, critical-path 16.6× 가속
  - 역할 정합 에고센트릭·UMI 보조 데이터로 성공률 14%p 향상
  - 엣지-클라우드 실행에서 평균 다운링크 트래픽 104.6배 감소
  - 이중 시스템 분해와 국소 월드-액션 구성 요소의 통제 ablation
- **가치** — 비디오 사전학습 WAM의 지연 문제를 청크 길이 조정이 아닌 생성 과정 분해로 푸는 경로 제시

### (c) 시사점

- 손목 관측 전용 빠른 정제로 입력과 갱신 주기를 함께 분리한 사례
- 입력 모달리티와 속도 분리가 한 쌍으로 움직이는 구조라 공유 속도 기본값과 직접 대비 가능
- 별도 접촉 루프 없이 정책 내부 디노이징 궤적에서 고주파 보정 수행, 서브루프 필요성 논의의 비교 기준
- UMI 손목 시연을 국소 정제에 배정하는 역할 정합이 손 쪽 전문가의 사전학습 데이터 배정 힌트

### (d) 먼저 확인할 점

- 평가 로봇이 Franka·Galbot — 다지 손 과제와 손가락 단위 출력에도 같은 분리가 성립하는지는 원문 범위 밖
- 평균 4.5%p 향상은 작고 주 성과는 16.6× 가속 — critical-path 측정 범위 확인 필요
- 접촉 이벤트 속도 대비 국소 갱신 주기 실측 여부와 §5 한계 서술 확인 필요
- 프로젝트 페이지만 공개, 코드 공개 확인 안 됨

## 🥈 논문 2

**TacDyn-WAM: Learning Implicit Tactile Dynamics in a Heterogeneous Visuo-Tactile World Action Model**
[arXiv:2610.00638](https://arxiv.org/abs/2610.00638) · Enyi Wang, Mingxin Wang, Quan Shi 외 12인 · arXiv preprint · source: citation-graph · 코드 미공개

**점수 9/15** · R2 · N2 · M2 · Real3 · Repro0 — 초록·arXiv comment 모두 코드·프로젝트 페이지 신호 없음

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D1MZ](https://img.shields.io/badge/D1MZ-d97706.svg)](#ref-D1MZ) [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS)

### (b) 논문 요지

- 촉각 미래를 픽셀 대신 암묵 동역학으로 예측하는 WAM
- **문제** — 촉각 WAM이 영상 생성 방식으로 미래 촉각 관측을 복원해, 배포 중 접촉 위치·힘의 작은 변화에 예측이 불안정
  - 전문가 시연은 올바른 접촉 근처 촉각 이미지만 담고, 폐루프 오차가 쌓이면 분포 밖으로 이탈
  - 카메라 뷰는 거의 그대로여도 촉각 이미지는 크게 변하지만 접촉의 진행 방향은 예측 가능
- **기존 한계** — 촉각을 받는 기존 정책이 각각 다른 지점에서 부족
  - VTLA 계열 — 현재 촉각만 이해하고 상태 변화를 예측하지 못해 촉각 피드백에 반응적
  - 기존 촉각 WAM — 같은 VAE로 카메라·촉각 프레임을 인코딩하고 영상 백본으로 미래 촉각 잠재를 반복 디노이징해 추론이 느리고 픽셀 복원에 묶임
  - N0-VTLA — 고정 DINOv2 특징 공간에서 단일 horizon의 순변화만 예측, 정적 자연 이미지 기반이라 촉각 프레임 간 진화를 담지 못함
- **핵심 방법** — 시각 전문가와 촉각 동역학 전문가(ITDE)를 별도 파라미터·타깃 공간으로 두고 매 층 joint attention으로 결합
  - TacRep — 촉각 클립의 마스크 시공간 예측으로 학습하고 관계 구조 증류로 정규화한 동역학 인지 타깃 공간
  - ITDE — 단일 순전파로 여러 horizon의 미래 표현과 그 변화량을 예측, 반복 디노이징 없음
  - Tactile Understanding Memory — 읽기 전용으로 현재 촉각 상태 공급
  - 액션 전문가가 시각·촉각 예측을 함께 사용하며 단계적 학습으로 촉각 모듈 통합
- **차별점** — 미래 촉각 관측을 복원하지 않고 동역학 표현 공간에서 예측하며, 시각과 촉각의 타깃 공간을 분리
  - 순변화 하나가 중간 접촉 사건을 가리는 문제를 다중 horizon 예측으로 해결
- **핵심 기여** — 모델, 표현 공간, 시뮬레이션·실물 결과
  - UniVTAC 평균 성공률 81.5%, 제공된 시연만 사용하고도 대규모 시각-촉각 사전학습 모델 N0-VTLA·N0-TWAM과 경쟁
  - 두 촉각 경로와 TacRep이 픽셀 복원·정적 대안보다 낫다는 ablation
  - 실물 5개 과제 평균 71.0%, 촉각 정책 FTP-1 대비 16점 높음
  - 실제 시각-촉각 궤적 약 6,000개의 소규모 사전학습으로 85.0%
- **가치** — 촉각 예측 목표를 픽셀에서 접촉 진화로 옮겨 배포 드리프트에 강한 촉각 WAM 경로 제시

### (c) 시사점

- 시각 전문가 옆에 촉각 전문가를 두는 다전문가 분해의 비용·이득 근거
- 해부학적이 아닌 모달리티 축의 시임이라 공유 트렁크와 분리 헤드 구성의 비교 사례
- 전문가마다 타깃 공간을 따로 두고 joint attention으로만 결합, 분리 후 정보 공유 방식의 한 형태
- 촉각 전문가가 단일 순전파라 고주파 보정에 쓸 여지, 지연 이득은 원문 수치 확인 필요

### (d) 먼저 확인할 점

- 코드·프로젝트 페이지 신호 없음, 논문 내 Reproducibility Statement 서술 확인 필요
- UniVTAC 81.5%와 실물 71.0%는 서로 다른 설정 — 실물 베이스라인 구성 확인 필요
- 촉각 센서 전제 — 손가락 끝 센서가 없는 구성에는 이전 불가
- 예측 horizon 길이와 제어 주기의 관계가 초록에 없음

## 🥉 논문 3

**Towards a General Humanoid Loco-Manipulation Model via Egocentric Whole-Body Human Data Pretraining**
[arXiv:2610.00438](https://arxiv.org/abs/2610.00438) · Chongyang Xu, Zhao Wu, Jin Chen 외 9인 · arXiv preprint · source: keyword-sweep · 코드 공개 예정

**점수 8/15** · R2 · N2 · M2 · Real1 · Repro1 — 초록 "We will release our code, models, and data to support further research."

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS) [![D9ZP](https://img.shields.io/badge/D9ZP-d97706.svg)](#ref-D9ZP)

### (b) 논문 요지

- 전신 인간 데이터 3단계 사전학습으로 만든 휴머노이드 VLA
- **문제** — 휴머노이드 전신 이동 조작 시연은 로봇 시간과 인력이 들어 확장이 어려움
  - 에고센트릭 인간 영상의 손목·손 궤적만으로는 접근·자세 조정·파지 유지의 전신 협응 지도 부족
- **기존 한계** — 원격조작 수집과 손 궤적 중심 영상 사전학습이 각각 한계
  - 전신 원격조작 — 다양한 시연 수집이 로봇 운용과 사람 노력에 묶여 과제·환경 확장 곤란
  - 손목·손 궤적 기반 영상 사전학습 — 신체 움직임과 손-물체 상호작용의 시간적 협응을 보존하는 지도 없음
- **핵심 방법** — 학습을 3단계로 나누고 단계 전반에 공유 표현 공간을 사용
  - 1단계 — 다양한 에고센트릭 데이터셋에서 상호작용 학습
  - 2단계 — HumanVerse-500으로 신체와 손 모션의 협응 학습
  - 3단계 — 하위 과제와 로봇 구현체에 적응
  - 인간과 로봇의 상태·행동 차이는 도메인별 인터페이스가 처리
- **차별점** — 공유 전이 코어 위에 인간·로봇 도메인별 인터페이스를 분리하고 손뿐 아니라 전신 모션을 지도로 사용
- **핵심 기여** — 데이터셋, 정책, 스케일링 분석
  - HumanVerse-500 — 개방 환경 인간 이동 조작 500시간, 에고센트릭 영상과 신체·손 모션을 동기화
  - SIMPLE과 실물 4개 과제에서 가장 강한 평가 베이스라인 대비 성공률 각각 3.9%p, 22.5%p 향상
  - 전신 인간 데이터가 많을수록 검증 손실 감소, 실물 과제 진행도 향상
  - 두 인간 데이터 단계 중 전신 미드트레이닝이 실물 성공에 더 크게 기여, 인간 시연이 로봇 미경험 물체의 진행도 향상
  - 코드·모델·데이터 공개 예정
- **가치** — 전신 인간 데이터를 휴머노이드 이동 조작의 확장 가능한 지도 자원으로 쓰는 근거 제시

### (c) 시사점

- 신체·손 협응을 별도 학습 단계로 다루는 데이터 쪽 분리 사례
- 인간·로봇 도메인별 상태·행동 인터페이스 분리가 신체 출력과 손 출력 공간 정의의 참고점
- 신체-손 협응 지도를 담은 500시간 데이터가 분리 헤드의 사전학습 자원 후보
- 분리가 구조가 아닌 학습 단계에 있어 신체↔손 정보 공유 방식은 이 논문에서 확인되지 않음

### (d) 먼저 확인할 점

- 정책의 액션 출력이 신체·손 헤드로 나뉘는지 §4.1 확인 필요
- 향상이 데이터 설계 효과인지 구조 효과인지 초록에서 분리 안 됨
- 실물 4개 과제 규모, 코드·모델·데이터는 공개 전
