## 🥇 논문 1 — 우선순위 ★★★

**Route by Kinematics, Act by Observation: Kinematics-Supervised Expert Routing in MoE-Augmented VLA**
[arXiv:2607.26807](https://arxiv.org/abs/2607.26807) · Tianhang Yang et al. (Tsinghua) · source: π0 citation graph + keyword sweep (action space architecture)

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS) [![D4QX](https://img.shields.io/badge/D4QX-d97706.svg)](#ref-D4QX)

### (b) 핵심 기여

- **핵심 문제** — 기존 MoE-VLA 라우터는 관찰(observation)만 입력받아 운동학적으로 이질적인 태스크를 묵시적으로 구분 → 전문가 분배 부정확
- **KinRT (Kinematics-supervised explicit Routing)** — 액션 궤적을 운동학 군집으로 분류 → 군집 ID를 라우터 학습의 정답 레이블로 직접 지도; 추론 시에는 시각-언어 관찰만으로 전문가 배치 (운동학 불필요)
- **비대칭 증류 메커니즘** — 학습 시 액션 공간의 운동학 구조를 관찰 공간의 라우터에 녹여냄 → 명시적 운동학 지식 없이도 운동학-결합 라우팅 달성
- **실 플랫폼 검증** — 3D 프린트 기반 DIYRobot (< $2,000) 자체 구축 및 크로스 플랫폼 일반화 평가; RoboTwin 벤치마크 대비 dense/MoE VLA 모두 초과

### (c) 시사점

- **D3GS 비교군 명료화** — MoE 라우터를 '운동학 레이블'로 지도할 경우 암묵적 분리보다 성능 향상; Body/Hand 해부학적 분리 (기본값)와 정면 비교 대상으로 가장 구조화된 MoE 선행 연구
- **운동학 군집 = Body/Hand 분할 선행 연구** — 논문의 kinematic archetype이 실질적으로 arm 모션 vs. contact-rich finger 모션으로 귀결되는지 확인 시, D3GS hybrid 설계 근거 보완 가능
- **저비용 실 플랫폼** — DIYRobot < $2,000 + 3D 프린트: 자체 아키텍처 비교 실험 비용 기준점

### (d) 먼저 확인할 점

- **운동학 군집 수 민감도** — 군집 수가 고정일 때 body/hand 경계가 자연스럽게 분리되는지, 과소분류 시 성능 저하 폭 미보고
- **코드 미출시** — "will be open-sourced" 공약만 존재; 재현 전 실제 릴리즈 확인 필수
- **DIYRobot 태스크 편향** — 단순 pick-place 중심일 가능성; 접촉 집약적(contact-rich) 손가락 조작 태스크 포함 여부 미확인

## 🥈 논문 2 — 우선순위 ★★

**UniCross: Unified Cross-Skill Dexterous Manipulation Synthesis**
[arXiv:2607.28198](https://arxiv.org/abs/2607.28198) · Hui Zhang, Julian Ferchow, Jie Song, Mirko Meboldt (ETH Zürich) · source: keyword sweep (dexterous manipulation action)

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS) [![D1QT](https://img.shields.io/badge/D1QT-d97706.svg)](#ref-D1QT)

### (b) 핵심 기여

- **4가지 손재주 스킬 통합** — grasping, relocation, in-hand rotation, in-hand translation을 동일 상태·액션 공간 + 공통 목적 함수 하나로 모델링
- **단일 cross-skill 정책 증류** — 4가지 스킬 모두에서 강인한 성능; 미보 객체 일반화, 외란 내성, 장기 스킬 체이닝 가능
- **핸드 형태 이전** — 동일 공식이 다른 핸드 모폴로지로 효과적으로 이전 가능함을 검증
- **해석** — 4가지 손재주 스킬은 공유 공식의 인스턴스; 스킬 간 내재적 일관성 존재

### (c) 시사점

- **D3GS 단일 공식 vs 분리 질문** — 스킬 경계를 아키텍처 수준에서 분리하지 않아도 스킬-내 연속성 확보 가능; hybrid split (기본값)이 필요한 조건을 재검토하는 비교 기준
- **D1QT 손 출력 공간** — 4가지 in-hand 태스크 전반에서 finger joint command가 공통 액션으로 작동함을 empirical하게 지지; 단일 finger joint 공간 선택(기본값) 근거 보강
- **장기 체이닝** — grasping → relocation → in-hand rotation 연속 실행 가능성; Body/Hand 분리 아키텍처에서 hand 헤드 단독 체이닝 구조 참고

### (d) 먼저 확인할 점

- **실로봇 검증 미제시** — 초록에 실제 로봇 실험 없음; RL 기반 시뮬레이션 프레임워크로 추정; Sim2Real 전이 갭 미검증
- **코드 미공개** — 재현 불가 상태
- **스킬 분류 범위** — 4가지 in-hand 스킬에 한정; arm 매크로 모션(body 출력)과의 통합 여부 미다룸 → P1 full Body+Hand 파이프라인 직접 비교 한계

## 🥉 논문 3 — 우선순위 ★

**HCPG-Flow: Hierarchical Contact-Progress Guidance for Flow-Policy Robot Manipulation**
[arXiv:2607.17651](https://arxiv.org/abs/2607.17651) · Guanghu Xie et al. · source: keyword sweep (hierarchical action expert)

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D3GS](https://img.shields.io/badge/D3GS-d97706.svg)](#ref-D3GS) [![D5SH](https://img.shields.io/badge/D5SH-d97706.svg)](#ref-D5SH)

### (b) 핵심 기여

- **HCPG-Flow** — SAC-Flow 위에 계층적 객체 중심(contact-progress) 후보 선택기를 추가; end-effector 접근 단계 → 접촉 후 태스크 진행 단계 자동 전환
- **두 단계 분리** — 접촉 전: end-effector 위치 기반 거리 감소를 점수화; 접촉 후: 태스크 관련 거리(progress signal)로 전환 → temperature-controlled 액션 임베딩으로 실행
- **Maniskill 10 태스크** — SAC-Flow 대비 평균 성능 향상, Maniskill에서 +9.5%p 기록

### (c) 시사점

- **D5SH 계층 흐름 참고** — 접촉 전·후 상태를 별도 신호로 분리하는 방식은 body→hand 계층 흐름(기본값)의 phase-switching 구현 전략과 구조적으로 유사; 명시적 접촉 게이팅 아이디어 차용 가능
- **D3GS 비교군** — 단일 flow 정책 + 외부 selector 구조; hybrid split (기본값)과 selector-free 순수 분리 구조 간 중간 지점

### (d) 먼저 확인할 점

- **시뮬 전용** — Maniskill 시뮬레이션만; 실로봇 검증 없음; Sim2Real 전이 갭 미확인
- **코드 미공개** — 재현 불가
- **progress signal 정의 의존성** — 태스크별 맞춤 progress metric 필요; 범용 Body/Hand 파이프라인 적용 시 signal 설계 부담 증가

## 🌱 논문 4 — 인접 분야 픽

**Cross-Embodiment Transfer via Behavior-Aligned Representations**
[arXiv:2607.27549](https://arxiv.org/abs/2607.27549) · Ajay Sridhar, Jensen Gao, Jonathan Yang, Jean Mercat, Suneel Belkhale, Dorsa Sadigh (Stanford) · adjacent field: cross-embodiment VLA / 임바디먼트 이전 표현 학습

### (a) 관련 Pillar / Decision

[![P1](https://img.shields.io/badge/P1-f5e9d5.svg)](#ref-P1) / [![D4QX](https://img.shields.io/badge/D4QX-d97706.svg)](#ref-D4QX)

### (b) 핵심 기여

- **행동 정렬 표현(behavior-aligned representations)** — 객체 바운딩 박스, 언어 모션 레이블, 엔드이펙터 트레이스 등 임바디먼트 불변 중간 표현을 VLA에 주입하여 크로스 임바디먼트 이전 촉진
- **가설 검증** — 임바디먼트 간 불변성 + 로봇 액션 예측 가능성을 동시에 갖는 표현이 이전을 통일함; 시뮬 기반 크로스 임바디먼트 벤치마크로 측정

### (c) 시사점

- **D4QX body 출력 공간** — 엔드이펙터 트레이스가 임바디먼트-불변 중간 표현으로 유효함을 확인 → both-wrist / tool-flange pose (기본값) 선택의 외적 지지 근거; 다른 임바디먼트 대규모 데이터를 body expert 사전학습에 활용 가능성 시사
- **인접 신호** — 크로스 임바디먼트 이전과 body 출력 설계가 연결됨; P1 body expert 설계 시 임바디먼트-불변 출력 공간 선택이 데이터 확장 이점으로 이어짐을 간접 지지

### (d) 먼저 확인할 점

- **시뮬 전용 벤치마크** — 실로봇 이전 실험 없음
- **hand 출력 공간 미다룸** — 엔드이펙터 트레이스는 arm/wrist 수준; 손가락 조작(D1QT) 이전 표현은 미포함
