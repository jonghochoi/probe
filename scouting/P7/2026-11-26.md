## 🥇 논문 1

**RecallFlow: Episodic Memory as the Source Distribution of Generative Robot Policies**
[arXiv:2611.23731](https://arxiv.org/abs/2611.23731) · Xuji Zhang, Qilin Zhong, Zichen Zhang 외 · arXiv preprint · source: keyword-sweep · 코드 공개 예정

**점수 13/15** · R3 · N3 · M3 · Real3 · Repro1 — Appendix B "The code of RecallSuite and RecallFlow will be released." — arXiv comment는 프로젝트 페이지만

### (a) 관련 Pillar / 질문

[![P7](https://img.shields.io/badge/P7-f4d5eb.svg)](#ref-P7) / [![D5GY](https://img.shields.io/badge/D5GY-d97706.svg)](#ref-D5GY)

### (b) 논문 요지

- 에피소드 기억을 생성 정책의 출발 분포로 쓰는 플로우 정책
- **문제** — 더는 보이지 않는 정보에 따라 행동해야 하는 메모리 의존 조작에서 현재 장면만 보는 정책은 추측에 의존
  - **예시** — 컵 세 개 아래 공을 찾는 야바위(shell game), 이미 건드린 용기, 물체를 집었던 위치
  - 현재 관측은 할 수 있는 일은 보여주나 해야 할 일은 보여주지 못함
- **기존 한계** — 관측 이력을 추가 조건으로만 넣고 생성은 여전히 가우시안 잡음에서 시작
  - **조건으로서의 이력** — 긴 관측 창, 게이트 교차 어텐션, 구조화 메모리 상태 모두 한 네트워크가 긴 중복 이력에서 대상 찾기와 움직임 결정을 함께 떠맡음
  - **허위 상관** — 메모리가 필요 없는 과제에서 무기억 정책보다 크게 낮아지는 사례
  - **무정보 잡음** — 생성 시작점이 기억한 대상 쪽으로 유도되지 않음
  - **기존 학습 사전분포** — 데이터셋 통계·현재 관측·최근 행동·다른 에피소드·압축 이력에서 유도, 같은 에피소드에서 앞서 본 대상은 반영 안 함
- **핵심 방법** — 기억이 생성의 출발점을 정하고 현재 관측이 도달 방식을 정하는 분업
  - **Recall–Relocalization** — 이전 프레임 패치 토큰의 에피소드 메모리 뱅크를 현재 시각 토큰이 메모리 어텐션으로 읽고, 소수의 학습 가능한 recall slot이 메모리와 현재 뷰를 함께 읽어 기억한 대상의 현재 위치를 반영
  - **Recall Anchors** — 각 slot을 행동 공간의 가우시안 앵커로 바꾸고 표준 가우시안과 섞어 혼합 출발 분포 구성, 우도로 학습
  - **수송 네트워크** — 현재 관측만으로 행동 청크를 완성, 추론 비용은 무기억 정책과 거의 같음
- **차별점** — 기억을 조건이 아니라 플로우 매칭의 출발 분포에 넣음
  - 같은 수송 네트워크에서 기억을 조건으로 쓸 때 NoRepeat 92.0%, 출발 분포로 쓸 때 97.0%
- **핵심 기여** — 출발 분포로서의 기억, 재위치화 모듈, 메모리 부하별 평가 스위트
  - **RecallSuite** — 시뮬레이션 5과제, 메모리 부하별 두 그룹, 무기억 2종·이력 조건 2종 대비 평균 성공률 20.3점 상승, NoRepeat-4 64.7% 대 15.0%
  - **MIKASA-Robo** — 공개 메모리 벤치마크 5과제 평균 80.4%, 기존 최고 발표치 Chameleon 75.1%
  - **RoboMimic** — 메모리가 필요 없는 Square 과제에서 평균 89.0%로 무기억 FM 86.2%·DP 85.7%와 동급, 장기 이력 DP는 무기억 DP 아래로 하락
  - **실물** — xArm 7 평행 그리퍼, 메모리 의존 4과제, 과제당 24회, 평균 82.3% 대 최강 기준 장기 이력 DP 63.5%
  - **절제** — 재위치화 제거 시 NoRepeat 12.3점·MarkedPair 11.0점 하락, 세 학습 시드 평균
  - **비용** — 청크당 1.1 ms 추가, 중·장기 이력 DP는 RecallFlow보다 37.0·34.0 ms 더 소요
- **가치** — 생성 정책에서 기억이 들어가는 자리를 조건에서 출발 분포로 옮기는 새 설계 축 제시

### (c) 시사점

- 이력을 조건으로 늘리지 않고 출발점에 넣는 기억 설계
- **비교 근거** — 같은 프로토콜에서 무기억·중기 이력·장기 이력·출발 분포 기억을 나란히 측정한 공개 기준점
- **부작용 측정** — 메모리가 필요 없는 과제에서 장기 이력은 성능을 깎고 출발 분포 기억은 깎지 않는다는 결과, 이력 길이 선택의 판단 근거
- **도입 비용 낮음** — 플로우 매칭 행동 헤드를 쓰는 정책이면 출발 분포만 바꾸는 구조, 추론 지연 증가가 작음
- **다지 손 이식** — 손가락 관절까지 포함한 고차원 행동 공간에서 가우시안 앵커가 의도 행동 근처를 잡을지가 관건

### (d) 먼저 확인할 점

- 코드 공개는 부록의 약속뿐, arXiv comment에는 프로젝트 페이지만
- 메모리는 단일 팔 탁상 장면의 시각 토큰을 고정 용량으로 저장, 길고 조밀한 과거에는 요약형 메모리가 필요할 수 있다고 저자 명시
- 실물은 평행 그리퍼 xArm 7 한 플랫폼, 과제당 24회
- 평가 과제는 첫 선택이 맞아야 성공인 이산 선택형 기억 위주, 연속적인 진행 상태 기억으로의 일반화 확인 필요
- 언어 조건·다중 과제 정책으로의 확장은 미검증

## 🥈 논문 2

**Toward Agentic Robotics: A Large-Scale Study of Harness Design for Robot-Use Agents**
[arXiv:2611.34778](https://arxiv.org/abs/2611.34778) · Yuxiang Lai, Jike Zhong, Yu-Jhe Li 외 · arXiv preprint · source: keyword-sweep · 코드 공개

**점수 12/15** · R3 · N2 · M3 · Real1 · Repro3 — §7 "releasing our unified evaluation suite, evolved policy code, and 470,000+ rollout logs at github.com/google-research/x-as-policies" · Appendix B·D 시드·VLM 구성 상세

### (a) 관련 Pillar / 질문

[![P7](https://img.shields.io/badge/P7-f4d5eb.svg)](#ref-P7) / [![D3HN](https://img.shields.io/badge/D3HN-d97706.svg)](#ref-D3HN)

### (b) 논문 요지

- 47만 회 롤아웃으로 VLM–VLA 하니스 설계를 비교한 연구
- **문제** — VLM 추론과 VLA·WAM 제어를 잇는 정책 하니스(policy harness)의 설계 공간이 수천 가지이고, 같은 모델로도 설계에 따라 성공률이 수십 점 갈림
  - **VLM** — 장면 이해와 과거 사건 회상은 되나 확장 추론으로도 3D 그리퍼 자세 예측이 부정확하고 루프 안 호출이 로봇을 멈춤
  - **VLA·WAM** — 학습 과제에서는 빠르고 매끄러우나 도메인 이동과 장기 기억·추론 과제에서 실패, π0.5가 LIBERO 95% 초과에서 LIBERO-PRO 위치 이동 시 약 4분의 1로 하락
- **기존 한계** — 설계 하나 시험에 수천 회 롤아웃과 큰 API·GPU 비용이 들어 기존 연구는 소수 후보 중 하나의 하니스에 고정
  - 절제를 한 체제·한 벤치마크로 한정
- **핵심 방법** — 하니스를 다섯 구성요소로 정의하고 일치 시드에서 한 번에 한 요인씩 통제 비교
  - **컨텍스트** — 지시, 카메라 프레임·영상, 도구 출력, 좌우 관례 같은 규약을 적은 과제 노트
  - **도구** — 인식 도구, 모션 프리미티브, 언어 하위 목표와 스텝 한도를 받는 VLA 도구
  - **정책 코드** — 자유 형식 Python 또는 행동 트리·PDDL 템플릿, 폐루프·개루프, 정체·실패 시 VLM을 부르는 가드
  - **사전 진화** — 학습 에피소드의 실패 보고로 코드를 고치고 학습 성공률이 오를 때만 채택
  - **실행 시 단계** — VLM 호출 없는 Offline, 실패 신호 때만 부르는 Semi-online, 하위 목표마다 부르는 Full-online
- **차별점** — 하니스 하나를 제안하는 대신 시뮬레이션 벤치마크 8개·VLM 6종·VLA/WAM 체크포인트 15개에서 설계 축을 일곱 통제 연구로 분해
- **핵심 기여** — 대규모 비교, 일곱 설계 지침, 참조 레시피 X-Harness
  - **규모** — 4,000개 이상 설정, 47만 회 이상 롤아웃, 시뮬레이션 벤치마크 8개 267과제
  - **실행 시 VLM 호출** — RoboCasa365 장기 과제에서 실패 신호 뒤 단계별로 VLM을 부르는 다회 구조(multi-turn rescue)가 Full-online과 동급이면서 VLM 토큰 42% 절감, 일회성 인계는 구한 에피소드보다 망가뜨린 진화 코드 에피소드가 더 많음
  - **폐루프 코드** — 상태를 확인하고 실패한 하위 목표를 재시도하는 진화 코드가 물체 이동·낙하 교란에서 4개 벤치마크 기준 VLA 대비 20점 이상 우위
  - **이득 위치** — 학습 분포 안 과제는 VLA에 그대로 위임, RoboMME 명시적 기억·LIBERO-PRO 이동·VLABench 다단계 추론에서 큰 이득
  - **X-Harness** — 가중치 갱신 없이 기반 정책을 기억·추론·도메인 이동 과제에서 최대 +42.8점 향상
  - **공개** — 통합 평가 스위트, 진화된 정책 코드, 롤아웃 로그 저장소 공개
- **가치** — 에이전트형 로봇의 하니스 설계를 VLM과 VLA 역량에 맞춘 실행 지침으로 정리

### (c) 시사점

- 과제 분할을 정책 밖 코드에 둘 때의 이득 지도
- **분할 위치 대조군** — VLA 단독, 하위 목표마다 VLM 호출, 실패 시에만 호출을 같은 시드로 비교, 계획기 분할 대 단일 정책의 측정 근거
- **회복 트리거** — 실패 신호에서만 단계별로 VLM을 부르는 방식이 매 단계 호출과 동급, 회복 설계의 비용 대비 기준
- **기억을 정책 밖에** — RoboMME에서 VLM이 전체 영상 이력과 과제 노트를 받아야 사건을 놓치지 않는다는 결과, 정책 내부 기억과 견줄 대조군
- **공개 기준점 확보** — 저장소·롤아웃 로그 공개로 재현 비용 낮음

### (d) 먼저 확인할 점

- 결과 전부 시뮬레이션, 실물은 부록 J의 양팔 YAM 검증으로 실행 성공률 수치 없음
- 정밀 조작은 VLA 위임에 의존, 다지 손 인핸드 조작은 평가 범위 밖
- 상용 클라우드 VLM 의존, 호출 지연과 토큰 비용이 고주파 손 제어와 충돌 가능
- 하니스 이득은 기반 VLA가 약하고 VLM이 강할수록 커서 강한 정책에서의 이득 크기는 과제별 확인 필요

[![P7](https://img.shields.io/badge/P7-f4d5eb.svg)](#ref-P7) / [![D5GY](https://img.shields.io/badge/D5GY-d97706.svg)](#ref-D5GY)

### (b) 논문 요지

- 시각·렌치 기억과 예측형 테스트 시간 적응을 묶은 VLA
- **문제** — 다음 행동이 시간에 걸쳐 모은 감각 정보에 달린 조작에서 시각 단서와 렌치 단서가 모두 필요
  - **금고 비밀번호 예시** — 시각 기억은 시도한 숫자와 다음 키를 추적하나, 키에 다가갈 때와 누른 뒤 떼어낼 때 그리퍼 모습이 거의 같아 누름 완료는 힘의 오르내림으로만 구분
- **기존 한계** — 한 감각 이력만 쓰거나 기억 범위와 접촉 가중이 고정됨
  - **단일 모달리티 기억** — 시각 기억 또는 렌치 기억 한쪽만 써 다른 쪽 단서 누락
  - **DAM-VLA 고정 버퍼** — 창을 벗어난 초기 단서(처음 열려 있던 서랍) 소실
  - **TTT 압축** — 전체 시각 이력을 fast weight에 압축하면 특정 순간의 세부 복원이 어려움
  - **렌치 가중** — 렌치 토큰 직접 추가는 가중이 암묵적, DAM-VLA·DeCAL의 게이트는 접촉 특징만 봐 지시나 진행 단서에 반응하지 못함
  - **고정 정책** — 렌치 기억이 있어도 배치 시 접촉 동역학 변화에 취약
- **핵심 방법** — WALL-X 기반 VLA에 세 모듈 결합
  - **TTT 뱅크** — 각 항목이 해당 프레임 특징과 그 시점 fast weight 판독을 융합, 유한 뱅크에 저장해 프레임 세부와 창 밖 단서를 함께 보존
  - **컨텍스트 게이트** — 지시·시각 맥락·렌치 이력으로 과제 단계마다 행동 전문가가 접촉 정보를 얼마나 쓸지 결정
  - **예측형 테스트 시간 적응** — 미래 행동과 렌치를 함께 디노이징, 측정 렌치와의 예측 오차를 마지막 디노이징 스텝으로만 역전파해 저랭크 어댑터 갱신
- **차별점** — 프레임별 세부와 창 밖 단서를 한 항목에 합친 기억, 접촉 특징만이 아니라 지시와 시각까지 보는 렌치 게이트
- **핵심 기여** — 다중 모달 기억 VLA, TTT 뱅크, 예측형 적응
  - **전체 성능** — 양팔 플랫폼 2종, 실물 8과제, 평균 82.71%, π0.5·π-Mem·MemoryVLA·ForceVLA·TA-VLA 중 최강 기준 51.25% 대비 31.46% 절대 향상
  - **TTT 뱅크 절제** — 같은 백본의 Frame Bank·GDN·TTT only·RoboTTT식 구현 대비 진행 추적·초기 장면 회상·시연 순서 따르기에서 우세
  - **컨텍스트 게이트** — 렌치 직접 주입과 게이트 교차 어텐션(GCA)보다 높은 단계 성공률
  - **적응** — 화이트보드 접촉 변화 두 조건에서 닦기 성공률 85.0%에서 97.5%로, 갱신당 평균 159.5 ms(RTX 5090)
- **가치** — 시각 기억과 접촉 기억을 한 정책에서 함께 다루고 배치 중 자기 지도로 적응하는 경로 제시

### (c) 시사점

- 이력을 fast weight와 프레임 뱅크에 나눠 두는 설계
- **기억 형태 비교** — 같은 WALL-X 백본에서 FIFO 프레임 뱅크·순환 상태·TTT 변형 3종을 실물로 대조, RoboTTT식 구현도 포함
- **힘 기억** — 단계별 접촉 정보 가중을 지시와 시각까지 보고 정하는 게이트, 손목 렌치를 쓰는 접촉 과제 정책의 직접 참고
- **단계 전이 단서** — 누름 완료처럼 시각으로 구분되지 않는 단계 전이를 렌치 이력으로 가르는 사례

### (d) 먼저 확인할 점

- 코드 공개 신호 없음, 프로젝트 페이지만
- 두 기억을 함께 유지해 추론 지연 증가, 저자도 한계로 명시
- 실물 평가는 6축 손목 렌치를 쓰는 양팔 플랫폼 2종, 다지 손과 손가락 촉각은 평가에 없음
- 전체 과제는 과제당 20회(Open Safe 30회) 시행, Open Safe 절제는 단계별 60회로 표본 변동 축소
- 적응 갱신 159.5 ms가 고주파 손 제어 루프에 맞는지 확인 필요

**Self-Sensing Compliant Anthropomorphic Hand for Speed-Dictated Shared Force Control in Teleoperation**
[arXiv:2611.32937](https://arxiv.org/abs/2611.32937) · Huijiang Wang, Yu Zhang, Rui Chen 외 · adjacent field: 보철·신경과학의 촉각 감지 — 직렬 탄성 고유수용감각 손 · arXiv preprint

### (a) 관련 Pillar / 질문

[![P7](https://img.shields.io/badge/P7-f4d5eb.svg)](#ref-P7) / [![D7KC](https://img.shields.io/badge/D7KC-d97706.svg)](#ref-D7KC)

### (b) 논문 요지

- 텐던 직렬 스프링을 센서로 쓰는 유연 손의 공유 제어
- **문제** — 시각 기반 원격조작은 운용자가 촉감을 느끼지 못해 접촉 뒤 파지력 조절이 어려움
  - 깨지기 쉬운 물체는 과압축, 무거운 물체는 미끄러짐
  - 손가락 자기 가림과 사람 손·로봇 손의 기구학 불일치가 문제를 키움
- **기존 한계** — 접촉 정보를 얻는 기존 방식의 통합 부담과 고정된 인계 동작
  - **손가락 촉각 센서** — 손끝 6축 힘 센서·연성 자기전기 손가락·촉각 스킨은 관절 배선, 좁은 공간 장착, 감도 확보 부담
  - **영상 기반 힘 추정** — 파지 중 가림에서 성능 저하
  - **기존 손 수준 공유 제어** — 접촉 시 고정 파지 동작으로 전환, 운용자가 추가 장치 없이 힘 요구를 정하는 방법은 미탐구
- **핵심 방법** — 텐던 구동 인간형 손의 직렬 스프링을 전완 모터 박스의 전위차계로 읽어 고유수용감각만으로 접촉과 힘 판단
  - **자기 감지** — 네 손가락 MCP 텐던과 엄지 CMC 텐던 2개의 스프링 신호와 모터 상태로 관절 각도와 손끝 힘 추정, 손 안 전자 부품 없음
  - **접촉 인계** — 접촉 감지 전까지 VR 손 추적으로 운용자 운동학을 매핑, 접촉 뒤 손가락 수준 힘 제어기로 전환
  - **속도 지정 파지력** — 접촉 순간 스프링 하중 증가율로 운용자가 손을 닫는 속도를 읽어 부드러운 파지와 단단한 파지 선택
  - **손가락별 권한 배분** — 손가락별 상태 기계로 한 물체를 쥔 채 다른 물체 조작
- **차별점** — 유연성을 수동 적응 요소가 아니라 내재 센서로 쓰고, 닫는 속도를 별도 장치 없는 암묵적 힘 명령으로 해석
- **핵심 기여** — 자기 감지, 접촉 인계 공유 제어, 손가락별 권한 배분과 실물 검증
  - **힘 추정** — 다섯 채널 선형 모델 평균 R² 0.96, 학습에 쓰지 않은 연속 램프에서 약 0.8 N까지 평균 RMSE 18 mN
  - **모터 전류 대비** — 정적 하중에서 힘 분산 설명 23% 대 스프링 94%
  - **속도 분류** — 시료 8종 240회 접촉에서 단일 임계값 정확도 95%
  - **파지 성공률** — 실물 손, 과제당 20회, 직접 원격조작 대비 컵 35%에서 80%로, 병 45%에서 90%로
  - **한 과제 안 전환** — 물 따르기에서 컵은 부드럽게, 병은 단단하게 명시 명령 없이 전환
- **가치** — 유연 손의 기계적 유연성을 촉각 센서 없는 접촉 감지 자원으로 쓰는 경로 제시

### (c) 시사점

- 접촉 감지로 제어 단계를 넘기는 손 수준 단계 전환
- **진행 신호 후보** — 손가락별 접촉 시점을 고유수용감각으로 잡아 상태 기계를 전환, 정책이 파지 단계 진입을 아는 하드웨어 측 신호
- **손가락별 단계** — 한 손 안에서 손가락마다 다른 단계에 있는 상태를 표현한 사례
- **시연 품질** — 원격조작 시연의 파지력 품질을 높이는 저비용 경로, 텐던 구동 유연 손에서 도입 가능

### (d) 먼저 확인할 점

- 학습 정책 없는 원격조작 공유 제어, 정책의 진행 판단으로의 이식은 미검증
- 속도 등급은 두 단계뿐이고 임계값은 경험적 조정
- 스프링 강성이 감도와 범위를 맞바꿔 무거운 하중에서 힘 추정 포화
- 손가락당 스프링 하나로는 접촉 위치·접선력·미끄러짐 검출 불가
- 다수 운용자 평가는 향후 과제로 남김
- 코드 공개 신호 없음, 프로젝트 페이지만
