## 🥇 논문 1 — 우선순위 ★★★

**Drop-Then-Recovery: How Redundant Are Vision-Language-Action Models?**
[arXiv:2606.27755](https://arxiv.org/abs/2606.27755) · Guoheng Sun, Kaixi Feng, Shwai He, Xiaochuan Gong, Yexiao He et al. · 2026-06-26 · source: citation-graph (GR00T N1 인용)

### (a) 관련 Pillar / Decision

[![P4](https://img.shields.io/badge/P4-d5def5.svg)](#ref-P4) / [![D19](https://img.shields.io/badge/D19-d97706.svg)](#ref-D19) [![D20](https://img.shields.io/badge/D20-d97706.svg)](#ref-D20)

### (b) 핵심 기여

- **Drop-Then-Recovery(DTR) 분석 프로토콜** — 사전학습된 VLA 모델에서 트랜스포머 블록을 제거한 뒤 파인튜닝으로 재회복 가능한지 측정, 제거된 용량이 실제로 필요했는지 통제된 개입으로 검증
- **GateProbe** — 파인튜닝 없이 블록별 다운스트림 액션 손실 기여도를 순위화하는 원샷 가상-게이트 민감도 지표
- **핵심 발견** — 언어 백본은 표준 조작 태스크에서 고도로 중복(LLM 블록 절반 제거 시 OpenVLA-OFT 성공률이 95.0%에서 98.3%로 오히려 개선, 언어 블록 2개만 남겨도 기준 성능 회복), 반면 비전·액션 경로는 제거 내성이 훨씬 낮음
- **검증 범위** — 복수 VLA 아키텍처·복수 조작 벤치마크·실제 산업 현장 로봇 시나리오 전반에서 이 비대칭적 회복 가능성을 일관되게 확인

### (c) 시사점

- 백본 전체를 하나의 덩어리로 동결·보존하는 관행의 근거 재검토 필요 — 표준 조작 태스크 한정이지만 언어 표현 용량이 실제 필요보다 과도하게 큰 것으로 나타남
- 보존 우선순위를 "언어 표현 전체"가 아니라 "비전·액션 경로"로 재조정할 근거 확보
- 파라미터 예산 절감과 프라이어 보존을 동시에 겨냥하는 선택적 동결·가지치기 설계의 실증 기초 자료로 활용 가능

### (d) 먼저 확인할 점

- 검증이 LIBERO 등 표준 벤치마크와 산업 현장 시나리오에 한정 — 손재주(다지·양손) 조작 태스크로의 일반화는 미검증
- 초록에 명시된 코드 공개 링크(`github.com/s1ghhh/VLADrop`)를 직접 확인한 결과 저장소 파일이 모두 404 — 코드 실접근 불가 상태, 공개 여부 재확인 필요
- 언어 블록 제거 후에도 성능이 유지되는 현상이 LIBERO 특유의 짧고 단순한 지시문 구조에 기인할 가능성 — 복잡한 자연어 지시 환경에서 동일 결과 재현 여부 확인 필요

## 🥈 논문 2 — 우선순위 ★★

**Training Vision-Language-Action Models with Dense Embodied Chain-of-Thought Supervision (ZR-0)**
[arXiv:2606.30552](https://arxiv.org/abs/2606.30552) · Haoyang Li, Guanlin Li, Youhe Feng, Chen Zhao, Zhuoran Wang et al. · 2026-06-29 · source: citation-graph (Being-H0.5 인용)

### (a) 관련 Pillar / Decision

[![P4](https://img.shields.io/badge/P4-d5def5.svg)](#ref-P4) / [![D21](https://img.shields.io/badge/D21-d97706.svg)](#ref-D21) [![D22](https://img.shields.io/badge/D22-d97706.svg)](#ref-D22)

### (b) 핵심 기여

- **ZR-0** — Qwen3-VL-2B 기반 VLM(System 2, 구조화 추론) + Diffusion Transformer 액션 전문가(System 1, 연속 액션 생성) 이중 스트림 구조, cross-attention으로 결합하며 추론 시 추론 트레이스 생성을 완전히 생략 가능(청크당 약 90ms, 단일 A6000)
- **ProcCorpus-60M** — Franka·xArm·GR-1·ALOHA·ARX5·UR5 등 다양한 embodiment에 걸친 6천만+ 프레임(약 1,000시간)·40만+ 궤적, 프레임의 96.8%에 조밀한 Embodied Chain-of-Thought(ECoT) 주석 부여
- **학습 목표** — ECoT 추론용 다음-토큰 예측과 연속 액션 청크용 플로우 매칭을 공동 최적화, 조밀한 추론 주석이 이질적 embodiment 간 표현 정렬의 풍부한 그래디언트 신호로 작동
- **성능** — LIBERO 97.8%·RoboCasa GR-1 Tabletop 69.3%·RoboTwin 2.0 88.70%/87.98%(양팔), 실물 xArm 태스크에서도 강건한 성능 확인

### (c) 시사점

- 조밀한 ECoT 주석을 매개로 한 크로스-embodiment 표현 정렬이 이질적 로봇 플랫폼 간 지식 전이의 실질적 레버로 작동함을 대규모로 실증
- 공식 저장소가 base 체크포인트와 3개 파인튜닝 체크포인트(LIBERO·RoboTwin·RoboCasa)를 모두 공개, 설치 스크립트가 lerobot 클론을 전제로 작성되어 있어 코드 계보가 특정 foundry와 직접 일치 — 실접근성이 높음
- Qwen 계열 VLM을 backbone으로 채택한 사례가 계속 축적되며 계보 후보 비교를 위한 데이터가 확대됨

### (d) 먼저 확인할 점

- 실물 로봇 검증이 xArm 단일 플랫폼에 국한 — 손재주(다지) 조작 플랫폼으로의 이전 여부는 미검증
- ECoT 주석 96.8% 커버리지가 자동 생성 파이프라인 산출물로 추정 — 주석 품질·오류 전파가 다운스트림 액션 정밀도에 미치는 영향은 논문에 미보고
- 2.6B 파라미터 모델의 사전학습 컴퓨트 규모(GPU 시간·클러스터)가 명시되지 않음 — 자체 재현 시 비용 추정 별도 필요

## 🥉 논문 3 — 우선순위 ★

**Wh0: Generative World Models as Scalable Sources of Egocentric Human Hand Manipulation Data**
[arXiv:2606.22136](https://arxiv.org/abs/2606.22136) · Yangtao Chen, Zixuan Chen, Peiyang Wang, Yong-Lu Li, Jing Huo et al. · 2026-06-20 · source: citation-graph (Being-H0.5 인용)

### (a) 관련 Pillar / Decision

[![P4](https://img.shields.io/badge/P4-d5def5.svg)](#ref-P4) / [![D22](https://img.shields.io/badge/D22-d97706.svg)](#ref-D22)

### (b) 핵심 기여

- **Wh0** — 생성형 비디오 world model을 언어·객체·장면 조건으로 활용해 에고센트릭 인간-손 조작 데이터를 대량 생성하는 프레임워크
- **WM-H** — 5만 에피소드 규모 에고센트릭 인간-객체 상호작용 합성 비디오 데이터셋, hand motion reconstruction과 visual editing을 거쳐 로봇 학습 가능한 관측-행동 supervision으로 변환
- **정량 결과** — 소량의 실제 로봇 데이터와 co-training 시, 18개 실물 손재주 조작 태스크의 zero-shot 성공률을 8.3%에서 38.9%로 개선
- **Ablation** — 데이터 생성의 확장성과 장면·embodiment 정렬(alignment)이 성능 향상의 핵심 동인임을 별도로 검증

### (c) 시사점

- 에고센트릭 코퍼스를 "실제 인간 영상 수집"뿐 아니라 "생성형 world model 산출물"로도 확보할 수 있는 대안 경로 제시
- 정렬(장면·embodiment) 품질이 데이터 양 자체보다 성능에 더 크게 기여한다는 근거 — 코퍼스 구성 시 스케일보다 정렬 기준을 우선할 근거로 활용 가능
- 소량의 실제 로봇 데이터와의 co-training이 전제 조건 — 순수 생성 데이터 단독 학습으로는 검증되지 않음

### (d) 먼저 확인할 점

- 코드·데이터 공개가 프로젝트 웹사이트(`chenyt31.github.io`) 경유로만 명시 — 이번 확인에서는 네트워크 정책상 해당 도메인 접근이 차단되어 실접근 여부 미검증
- 18개 태스크 전원이 저자 자체 로봇 플랫폼 기준 — 외부 재현 시 하드웨어 차이에 따른 성능 변동 가능성
- WM-H 생성 비디오의 물리적 사실성(접촉 정확도 등) 검증 방식이 상세히 기술되지 않음 — 생성 아티팩트가 학습에 미치는 부정적 영향 확인 필요
