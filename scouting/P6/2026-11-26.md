## 🥇 논문 1

**Control-Aware Command Generation for Asynchronous Control and Action Inference with Vision-Based Policies towards Fast Execution**
[arXiv:2611.11089](https://arxiv.org/abs/2611.11089) · Takayuki Osa, Kazuki Ota · arXiv preprint · source: citation-graph · 코드 공개

**점수 13/15** · R3 · N2 · M3 · Real3 · Repro2 — §B.2 "The implementation of the proposed framework is available at https://github.com/TakaOsa/ACT_Async"

### (a) 관련 Pillar / 질문

[![P6](https://img.shields.io/badge/P6-e4d8f5.svg)](#ref-P6) / [![D0BZ](https://img.shields.io/badge/D0BZ-d97706.svg)](#ref-D0BZ) [![D3MR](https://img.shields.io/badge/D3MR-d97706.svg)](#ref-D3MR)

### (b) 논문 요지

- 정책은 두고 명령 생성 계층으로 비동기 실행을 받치는 방법
- **문제** — 비전 기반 정책의 실행 속도가 행동 추론의 계산 비용에 묶이는 문제
  - 정책 학습 과정을 건드리지 않고 제어 수준에서 얼마나 빨라질 수 있는지가 저자들의 물음
- **기존 한계** — 가속 시도들이 적용 범위나 매끄러움에서 빈틈을 남김
  - **고충실도 컨트롤러 기반 방식** — 로봇 컨트롤러로 행동 생성을 이끌지만 임의 로봇 플랫폼에 적용되는지 불명확
  - **시연 다운샘플링** — 학습 전에 시연을 솎아 가속하지만 실행 중 동작의 매끄러움은 다루지 않음
  - **RTC** — 인페인팅으로 비동기 추론의 불연속을 풀지만 확산·플로우 매칭 정책에 한정
    - ACT나 OpenVLA에는 바로 적용 불가
    - 학습 기반 생성이라 가속도 한계 같은 제약을 명시적으로 보장하지 못함
- **핵심 방법** — 불연속한 정책 출력에서 연속 명령을 뽑는 추종 제어와 적응형 행동 건너뛰기
  - **제어 인식 명령 생성(CAC)** — 정책이 내는 불연속한 목표 위치에서 연속 목표 위치를 만드는 일을 추종 제어 문제로 정식화, 가속도 같은 고속 제약을 지키며 목표로 수렴
  - **멀티스레딩 구현** — 로봇 제어 스레드와 행동 추론 스레드를 분리해 비동기로 실행
  - **적응형 건너뛰기** — 예측 위치열의 분산에 따라 예측 행동을 건너뛰어 실행을 더 가속
- **차별점** — 정책 학습·구조를 바꾸지 않고 배포 시점의 명령 생성에서 처리
  - 확산·플로우 매칭 정책에 묶이지 않아 ACT와 OpenVLA-OFT에 그대로 적용
  - 시연 다운샘플링 방식과 직교한다는 입장으로, 둘을 결합 가능하다고 서술
- **핵심 기여** — 실물 쌍팔 ALOHA 세 과제에서 속도와 매끄러움 측정, 시드 세 개에 시드당 10회 반복
  - ACT 위에서 CAC·비동기·적응형 건너뛰기를 합치면 실행 시간이 ACT 동기 실행의 53–63%
  - 펜 수납 성공률 30%에서 83%로 상승, 모든 행동을 균일하게 건너뛰는 변형은 완전 실패
  - CAC가 가속도를 제한하고 저크를 크게 줄임, CAC 없는 비동기 ACT는 가속도와 저크가 더 큼
  - OpenVLA-OFT 펜 수납에서 성공률은 모두 약 80%로 비슷하고, 추론 대기 시간은 에피소드당 약 18.5초에서 0.8초 미만으로 감소
  - 구현 저장소 공개
- **가치** — 정책 모델을 고치지 않고 정책 출력을 로봇 명령으로 바꾸는 실행 계층 설계만으로 속도 이득을 얻을 수 있다는 근거

### (c) 시사점

- 정책 수정 없이 얹는 실행 계층의 속도·저크 실측
- **청크 경계** — 비동기 실행이 키우는 가속도와 저크를 명령 생성이 줄이는 측정, 확산 계열이 아닌 ACT·OpenVLA-OFT에서도 확인
- **속도 설정** — 균일 건너뛰기는 실패하고 분산 기반 적응형만 정밀도를 지켜, 속도를 정책 출력 뒤에서 정할 때의 비용을 보여 주는 근거
- **도입 비용** — 재학습 불필요, 구현 저장소 공개

### (d) 먼저 확인할 점

- 저자 명시 한계 — RTC나 범용 평활화 방법과 비교하지 않았고, 가속 방식의 체계적 비교는 향후 과제
- 단순 과제에서는 방법 간 성공률이 비슷하고 속도 이득은 ACT 위주, OpenVLA-OFT는 한 과제만 검증
- 평가가 ALOHA 그리퍼 쌍팔 과제, 다지 손의 접촉 단계에서 분산 기준 건너뛰기가 정밀도를 지키는지는 별도 확인 필요
- 체크포인트·데이터 공개 언급 없음, 저장소만 있음

## 🥈 논문 2

**ODEAction: From Predicting Chunks to Evolving Actions**
[arXiv:2611.09672](https://arxiv.org/abs/2611.09672) · Qishen Wang 외 16인 · arXiv preprint · source: citation-graph

**점수 10/15** · R3 · N2 · M2 · Real3 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문

[![P6](https://img.shields.io/badge/P6-e4d8f5.svg)](#ref-P6) / [![D0BZ](https://img.shields.io/badge/D0BZ-d97706.svg)](#ref-D0BZ)

### (b) 논문 요지

- 청크 대신 행동의 연속 진화를 ODE로 생성
- **문제** — 독립적으로 예측한 인접 청크가 경계에서 시간 일관성 제약 없이 이어져 행동이 급변하고 궤적이 끊기는 문제
- **기존 한계** — 연속성을 강제하는 기존 방법도 청크를 생성의 기본 단위로 남겨 둠
  - **RTC** — 추론 때 새 청크를 이미 확정된 행동에 맞춰 제약
  - **학습 시점 RTC와 Legato** — 학습 때 연속성 제약을 도입
  - 세 방법 모두 청크 사이의 연결만 개선하고 행동 생성 패러다임은 그대로
- **핵심 방법** — 행동 공간의 상미분방정식(ODE)을 학습하고 현재 행동에서 적분해 다음 행동을 재귀 생성
  - **행동 전이장(Action Transition Field)** — 관측·언어·고유수용감각을 받아 현재 행동과 진화 시간마다 변화율 벡터를 내는 장
  - **학습** — 시연 궤적을 따라 진행하는 성분과 이탈 보정 성분을 합친 목표장을 만들어 직접 지도
  - **추론** — 현재 행동을 초기 조건으로 ODE를 수치 적분, 생성한 행동이 다음 진화의 시작점이 되어 명시적 의존이 생김
  - 서로 다른 비전-언어 백본에 붙는 모듈형 행동 헤드
- **차별점** — 청크 이음을 손보지 않고 청크 예측 자체를 없애, 전체 미래 구간을 한꺼번에 예측하지 않고 이전 행동에서 다음 행동을 잇는 생성
- **핵심 기여** — 시뮬레이션 세 벤치마크와 실물에서 성공률과 궤적 품질 동시 개선
  - **LIBERO와 EBench** — π0.5 기반 평균 성공률이 LIBERO 96.85%에서 98.25%, EBench 15.28%에서 24.72%로 상대 61.8% 개선
  - **이음 방법 비교** — RoboTwin 5개 과제에서 기준 82.4%, RTC 추가 81.2%, Legato 추가 78.0%, ODEAction 84.4%이고 경계 점프는 0.1165에서 0.0847로 27.3% 감소
  - **실물 AgileX Cobot Magic 1.0** — 4개 과제를 과제당 20회 시험해 평균 성공률 기준 65.00%, RTC 63.75%, Legato 66.25%, ODEAction 80.00%
  - 실물에서 컵 놓기 70.0%에서 90.0%, 숟가락 끼우기 25.0%에서 55.0%로 상승
  - 경계 불연속 감소와 성공률 상승이 평가 단위 10개에서 강한 양의 상관(Spearman 0.939)
- **가치** — 청크 단위 생성의 대안 패러다임 제시, 경계 연속성이 과제 성능과 이어진다는 정량 근거

### (c) 시사점

- 청크 경계를 잇는 대신 없애는 비교 근거
- **경계 처리 비교** — RTC와 Legato가 경계 점프를 줄이고도 성공률을 올리지 못한 설정에서 청크 없는 생성이 성공률과 매끄러움을 함께 개선
- **연속성과 성공** — 경계 불연속 감소와 성공률 상승의 상관, 정밀 과제에서 이득이 커 접촉 단계의 청크 경계가 점검 우선순위
- **도입 비용** — 행동 헤드 교체와 재학습이 필요하고 코드 비공개

### (d) 먼저 확인할 점

- 저자 명시 한계와 반복 시드·분산 진술 없음
- 이음 방법 비교가 RoboTwin 5개 과제의 한 백본과 실물 4개 과제에 한정, 상관 0.939도 평가 단위 10개 기준
- 실물이 AgileX 쌍팔 그리퍼 과제, 접촉이 빠르게 바뀌는 다지 손에서 같은 이득이 유지되는지는 별도 확인 필요
- 코드 저장소나 공개 약속 없음

**ExRL: Sample-Efficient Online Adaptation of Long-Chunk Policies via Execution Length Control**
[arXiv:2611.13482](https://arxiv.org/abs/2611.13482) · Xu Luo 외 7인 · arXiv preprint · source: citation-graph

**점수 11/15** · R2 · N3 · M3 · Real3 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문

[![P6](https://img.shields.io/badge/P6-e4d8f5.svg)](#ref-P6) / [![D0BZ](https://img.shields.io/badge/D0BZ-d97706.svg)](#ref-D0BZ)

### (b) 논문 요지

- 청크 행동 대신 청크 실행 길이만 강화학습으로 조정
- **문제** — 긴 청크 정책을 온라인 강화학습으로 적응시킬 때 필요한 표본이 많은 문제
  - 실물에서는 상호작용 데이터 수집이 느리고 비싸고 때로 위험해 표본 효율이 핵심 요건
  - 시연 범위가 제한되고 일반화가 불완전해 긴 청크 정책도 실제 배치에서는 최적에 못 미침
- **기존 한계** — 청크 전체나 그 잠재 변수를 최적화하는 강화학습은 청크가 길수록 탐색 공간이 커짐
  - **행동을 수정하는 방식** — 잔차 강화학습은 정책에 무관하고 가볍지만 청크 전체를 보정하는 연속 행동 최적화가 필요
  - **정책 종류에 묶인 방식** — DSRL 등은 확산·플로우 정책의 잠재 공간이나 생성 과정을 최적화해 특정 정책 종류에 묶임
  - **적응형 실행 길이 선행 연구** — AAC는 행동 엔트로피, FFDC는 학습된 검증기로 길이를 고르며 보상에서 직접 길이를 학습하지 않음
  - **가장 가까운 동시 연구** — 실행 길이를 강화학습으로 적응시키지만 PPO에 의존
- **핵심 방법** — 기본 정책을 고정하고 청크마다 몇 개 행동을 실행할지 고르는 가벼운 어댑터를 오프폴리시 강화학습으로 학습
  - **어댑터** — 상태와 예측 청크를 받아 재계획 전에 실행할 행동 수를 고르는 이산 결정
  - **선택적 온라인 BC** — 성공한 온라인 궤적을 기본 정책에 모방 손실로 되돌려 증류
  - **오프라인 데이터 활용** — 임의의 궤적 구간을 다른 실행 길이의 오프폴리시 경험으로 재해석
- **차별점** — 행동을 바꾸는 대신 얼마나 오래 실행할지만 최적화해 탐색 공간이 청크 길이에 따라 커지지 않음
  - 청크가 길수록 고를 수 있는 실행 길이가 늘어 표현력은 커짐
  - 기본 정책을 건드리지 않아 거의 모든 청크 정책에 붙는 정책 무관 인터페이스
- **핵심 기여** — 시뮬레이션과 실물에서 고정 길이 실행 대비 표본 효율적 개선
  - LIBERO에서 π0.5가 환경 단계 200,000회 안에 성공률 0%에 가까운 상태에서 90% 이상으로 상승
  - Tool Hang에서 DP 기반 ExRL-SAC는 90% 이상 성공, 나머지 베이스라인은 약 20% 이하
  - 실물 π0.5 네 과제에서 고정 길이 k=10 대비 ExRL-Q 성공이 쌓기 20회 중 9회에서 17회, 접기 12회에서 17회, 전원 삽입 25회 중 10회에서 22회
  - 쌓기는 물리 상호작용 10분 만에 100%에 가까워지고 옷 접기는 85분 안에 90%에 가까워짐
  - 청크 길이 H=50에서 고정 k=50은 쌓기 1/20, 전원 삽입 0/25로 크게 떨어짐
- **가치** — 실행 길이를 긴 청크 정책의 적은 상호작용 적응 인터페이스로 쓸 수 있다는 근거

### (c) 시사점

- 청크를 몇 개 실행할지가 적응 변수라는 측정
- **경계 처리** — 청크 경계에서 재계획 시점을 학습으로 고르는 새 갈래, 고정 길이 실행이 정책마다 크게 갈리는 실물 근거
- **적응 비용** — 기본 정책 고정에 어댑터만 학습, 쌓기 10분 수준의 실물 상호작용
- **도입 비용** — 코드 비공개
