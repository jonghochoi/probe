## 🥇 논문 1

**Contact Imitation Interface: Transferring Dexterous Skills by Showing How Contact Unfolds**
[arXiv:2610.41028](https://arxiv.org/abs/2610.41028) · Zhixuan Xu 외 7명 · arXiv preprint · source: citation-graph · 코드 공개

**점수 12/15** · R3 · N2 · M2 · Real3 · Repro2 — arXiv comment "Project website with code and hardware designs: …"

### (a) 관련 Pillar / 질문
[![P5](https://img.shields.io/badge/P5-e4d8f5.svg)](#ref-P5) / [![D2KT](https://img.shields.io/badge/D2KT-d97706.svg)](#ref-D2KT)

### (b) 논문 요지

- 접촉면을 맞춘 손끝 모듈로 로봇 없이 모으는 다지 손 시연
- **문제** — 평행 그리퍼용 휴대형 수집 방식을 다지 손으로 넓히기 어려움
  - 사람과 로봇의 기구학·접촉면 기하가 달라 시연된 접촉 순서를 로봇이 재현하기 어려움
  - 사람의 자연스러운 손재주를 살리면서 로봇 손으로 옮겨지는 접촉 기반 관측과 동작을 함께 얻는 인터페이스 필요
- **기존 한계** — 사람 중심과 로봇 중심 인터페이스 모두 시연자 자유도와 로봇 쪽 충실도의 맞교환에 묶임
  - **사람 중심 인터페이스** — 영상·모션캡처·계측 장갑은 기록이 사람 구현체에 묶여 리타게팅이 접촉 전개를 보존하지 못할 수 있고, 관측도 로봇 실행 때와 다름
  - **로봇 중심 인터페이스** — 원격조작·외골격·링키지는 로봇 전용 하드웨어나 작업자 숙련이 필요하고 시연 동작이 제한됨
- **핵심 방법** — 시연 인터페이스와 학습 인터페이스를 모두 접촉면 중심으로 구성
  - **정합 손끝 모듈** — 사람·로봇 손이 접촉면 기하와 카메라 배치가 같은 손끝 모듈을 쓰고, 각 모듈의 RGB 접촉 카메라가 손끝-물체 상호작용을 기록
  - **접촉 정렬 우선 리타게팅** — 손목과 손가락 동작을 함께 최적화해 시연된 접촉 재현을 우선하고, 넓은 장면 시점은 로봇 시점으로 재투영
  - **계층 정책** — 접촉면 플래너가 상대 접촉면 궤적을 예측하고, 컨트롤러가 이를 손목·손가락 명령으로 변환
- **차별점** — 손목 상대 동작과 관절 명령을 직접 예측하는 기존 표현 대신 접촉면 궤적을 정책의 중간 표현으로 사용
  - 이 표현이 고자유도 손의 접촉 과제에서 손목-손가락 협응 불량과 접촉 어긋남을 낳는다는 관찰이 근거
- **핵심 기여** — 여섯 손-과제 조합에서 기준 정책 대비 평균 성공률 50%p 이상 향상
  - **정책 평가** — LEAP·Wuji 손, 조합당 20회 롤아웃, 접촉 카메라와 접촉면 정책 조합이 평균 최종 단계 성공률 80.8%
  - **접촉 카메라 효과** — 접촉면 정책에서 평균 성공률 1.7%가 80.8%로, 손목 상대 동작·관절 정책에서 0.8%가 30.8%로 상승
  - **수집 효율** — 같은 작업자 15분 수집량이 맨손의 70%(동전)와 71%(전구), 원격조작 대비 전구 과제 2.3배, 동전 과제는 원격조작이 성공 시연 0건
  - **설계 ablation** — Q6 설계 요소별 ablation 수행
  - **공개물** — 하드웨어 설계와 소프트웨어 공개
- **가치** — 공유 접촉면이 다른 손 구조 사이에서 접촉 민감 기술을 옮기는 실용 인터페이스라는 근거 제시

### (c) 시사점

- 접촉 우선 맵을 같은 정책 조건에서 잰 실물 근거
- **보존 대상** — 손끝 위치 대신 접촉면 움직임을 지키는 리타게팅과 그 표현을 쓰는 정책이 두 손에서 모두 학습됨
- **작업자 시간** — 로봇 없는 수집이 원격조작보다 빠르고 맨손의 70% 처리량, 시연 단가 비교 기준점
- **도입 비용** — 하드웨어 설계와 소프트웨어가 공개되어 있으나 사람·로봇 쪽 손끝 모듈 제작 전제

### (d) 먼저 확인할 점

- 조합당 20회 롤아웃, 반복 시드 서술 없음, 과제 네 가지와 손 두 가지의 소규모 실험
- 정책 비교 기준선이 한 가지 표현(손목 상대 동작과 관절 변화 예측)이라 다른 리타게팅 기준과의 직접 비교는 제한적
- 접촉 카메라 없는 조건에서는 두 정책 모두 낮아 이득 대부분이 접촉 카메라 입력에서 나옴
- 양팔·이동 조작 확장은 향후 과제로 남김

## 🥈 논문 2

**DexMimic: A Generalist Dexterous Hand-Object Tracking Policy via Value-Guided Reset Allocation**
[arXiv:2610.19089](https://arxiv.org/abs/2610.19089) · Zhexi Luo 외 5명 · arXiv preprint · source: citation-graph

**점수 8/15** · R3 · N2 · M2 · Real1 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음, arXiv comment "Project page: …"는 프로젝트 페이지뿐

### (a) 관련 Pillar / 질문
[![P5](https://img.shields.io/badge/P5-e4d8f5.svg)](#ref-P5) / [![D7HF](https://img.shields.io/badge/D7HF-d97706.svg)](#ref-D7HF)

### (b) 논문 요지

- 한 정책이 여러 궤적을 함께 추적해 궤적당 비용을 낮춤
- **문제** — 사람 손-물체 상호작용 데이터를 로봇 손 기술로 바꾸는 물리 기반 추적을 데이터 규모에 맞게 확장하기 어려움
  - 사람과 로봇 손의 형태·구동·접촉 동역학 격차를 물리 시뮬레이션에서 메워야 함
- **기존 한계** — 기존 물리 기반 강화학습은 궤적마다, 또는 작은 궤적 묶음마다 전문 정책을 따로 학습
  - **전문 정책 방식** — 학습한 제어 사전지식을 궤적 사이에 재사용하지 못하고 시연 수가 늘면 학습 비용이 반복
  - **참조 상태 초기화(RSI)** — 기구학 리타게팅 상태가 물리적으로 어긋난 접촉을 담아 즉시 실패 리셋을 부르고, 균일 시점 샘플링은 쉬운 구간을 과대 표집해 어려운 구간 학습이 부족
- **핵심 방법** — 공동 학습 중 초기화 분포를 정책과 함께 바꾸는 Value-Guided Reset Allocation
  - **리셋 상태 할당** — 시점별 리셋 버퍼에서 추적 지속 기대 보상이 높은 시작 상태를 선택
  - **리셋 시점 할당** — 비평가 추정으로 덜 학습된 참조 구간에 롤아웃을 우선 배정
  - **온라인 루프** — 같은 경험으로 정책과 비평가를 갱신하고 리셋 후보와 시점 우선순위도 갱신
- **차별점** — 궤적별 전문가 대신 하나의 참조 조건부 정책을 여러 궤적에 공동 학습
  - 초기화 분포를 고정된 RSI에서 학습 중 적응하는 분포로 교체
- **핵심 기여** — 일반 추적 정책, 벤치마크, 규모 확장 결과
  - 어려운 양손 과제 50개에서 성공률 88.40%, ManipTrans는 56.64%, 궤적당 평균 학습 시간 15.5배 단축
  - 공동 학습 궤적을 20개에서 500개로 늘리면 미지 물체 제로샷 성공률 2.00%에서 51.65%
  - 학습, 미세조정, 일반화를 아우르는 벤치마크 제안
  - 리셋 상태 할당과 리셋 시점 할당을 따로 뺀 ablation
  - xArm과 Wuji 손 실물 플랫폼에서 검증
- **가치** — 궤적마다 정책을 새로 학습하지 않고 사람 시연 데이터를 쓰는 길 제시

### (c) 시사점

- 궤적당 학습 비용을 한 정책으로 나눠 수율을 올리는 경로
- **수율** — 전문 정책(ManipTrans)과 같은 과제에서 성공률과 궤적당 시간을 함께 비교, 물리 검증 비용 논의의 기준점
- **도입 비용** — 궤적이 늘수록 추가 학습이 줄고 새 참조에는 미세조정만 필요
- **보존 대상** — 리타게팅 맵 자체는 다루지 않고 기구학 참조를 입력으로 받음

### (d) 먼저 확인할 점

- 실물 결과는 시뮬레이션 성공 롤아웃의 개루프 재생이며 성공률 수치 없음
- 학습 가능한 규모가 사용 가능한 사람 손-물체 데이터셋 크기에 묶인다고 저자가 한계로 밝힘
- 재구성된 손-물체 상호작용의 잡음에 대한 강건성은 향후 과제
- 코드 저장소나 공개 약속 없이 프로젝트 페이지만 있음

## 🥉 논문 3

**OmniHOI: Dexterous Hand-Object Interaction from Monocular Human Video**
[arXiv:2610.10855](https://arxiv.org/abs/2610.10855) · Ting Mao 외 6명 · arXiv preprint · source: citation-graph

**점수 8/15** · R3 · N2 · M2 · Real1 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음, arXiv comment "The project page is available at …"는 프로젝트 페이지뿐

### (a) 관련 Pillar / 질문
[![P5](https://img.shields.io/badge/P5-e4d8f5.svg)](#ref-P5) / [![D7HF](https://img.shields.io/badge/D7HF-d97706.svg)](#ref-D7HF) [![D2KT](https://img.shields.io/badge/D2KT-d97706.svg)](#ref-D2KT)

### (b) 논문 요지

- 단안 영상에서 학습 없이 다지 손 궤적을 만드는 3단 파이프라인
- **문제** — 풍부한 사람 조작 영상을 로봇 손 시연으로 바꾸려면 재구성과 로봇 전이 양쪽의 오차를 풀어야 함
  - 단안 깊이 모호성은 가림과 접촉을 혼동시키고, 작은 기하 오차가 접촉을 관통이나 분리로 바꿈
  - 사람 손에 가능한 동작이 형태·동역학이 다른 로봇 손에는 불가능할 수 있음
- **기존 한계** — 입력 가정과 오차 처리 위치가 방법마다 달라 초기 기하 오차가 뒤 단계까지 남음
  - **영상 재구성 후 과제별 정책 학습** — VideoManip 등은 정책이 재구성 오차를 흡수하도록 맡김
  - **모션캡처 전제 방식** — ManipTrans와 SPIDER는 깨끗한 모션캡처에서 출발해 영상의 잡음 재구성을 다루지 않고, SPIDER는 참조 동작이 잡음일 때 성능 저하
  - **학습 없는 영상 방식** — Do as I Do는 손과 물체를 주로 중심 정렬로 연관 짓고 접촉을 시뮬레이션 안에서만 명시적으로 다룸
- **핵심 방법** — 단계마다 그 단계에서 얻는 증거로 물리 일관성을 강제하는 파이프라인
  - **재구성** — 조밀한 손-장면 대응으로 손-물체 기하를 복원하고 가림·접촉·관통·손가락 교차를 보정
  - **접촉 인지 리타게팅** — 사람이 보인 접촉을 지키면서 형태 차이에서 오는 관통과 교차를 제거하도록 로봇 손을 최적화
  - **물리 정제** — 시뮬레이션에서 CMA-ES 최적화로 물체 추적, 접촉, 파지 안정성을 개선
- **차별점** — 오차를 학습 정책에 맡기지 않고 발생한 단계에서 바로잡는 학습 없는 구성
- **핵심 기여** — 재구성, 전이, 영상-로봇 종단 결과
  - 모션캡처 궤적 150개를 6–22자유도 다지 손 다섯 종에 전이해 성공률 39–89%, 기존 전이 방식은 최대 31%
  - 영상 60개 종단 성공률 53%, VideoManip 28%, Do as I Do 25%
  - 궤적당 소요 시간 19분, 순수 기구학 OmniRetarget 0.3분보다 길고 SPIDER 37분과 ManipTrans 385분보다 짧으면서 세 방식보다 성공률이 훨씬 높음
  - 재구성 단계와 전이 단계를 따로 뺀 ablation
  - 양팔 실물 로봇에서 궤적 실행
- **가치** — 영상 한 편에서 정책 학습 없이 실행 가능한 다지 손 궤적을 얻는 경로 제시

### (c) 시사점

- 영상 입력에서 궤적당 시간과 성공률을 함께 잰 수율 근거
- **수율** — 기구학만 쓰는 방식, 샘플링 최적화, 강화학습 기반 방식과 궤적당 시간과 성공률을 같은 표로 비교
- **보존 대상** — 리타게팅 단계에서 접촉 기하를 지키고 관통·교차를 제거하도록 최적화하는 맵
- **도입 비용** — 학습이 필요 없어 과제별 정책 학습 비용은 없으나 궤적당 19분의 최적화 시간 소요

### (d) 먼저 확인할 점

- 실물 실행은 일곱 개 자체 촬영 궤적의 개루프 재생이며 성공률 수치 없음
- 영상 60개 중 28개에서 실패, 인지 14건과 실행 13건, 물체 크기 오재구성이 가장 흔한 원인
- 단안 지각 정확도, 특히 미터 단위 스케일 추정에 한계가 있다고 저자가 밝힘
- 영상에서 얻은 물체 기하와 물리 속성 추정 오차가 물리 정제에 전파
