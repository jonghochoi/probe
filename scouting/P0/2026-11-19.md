## 🥇 논문 1

**TaF-Foundation: Wrench-Grounded Cross-Sensor Tactile Representations**
[arXiv:2611.20718](https://arxiv.org/abs/2611.20718) · Jiaming Jiang, Yuzhe Huang, Baokun Yang 외 · arXiv preprint · source: citation-graph

**점수 11/15** · R2 · N3 · M3 · Real3 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문
[![P0](https://img.shields.io/badge/P0-fbd7d6.svg)](#ref-P0) / [![D1AL](https://img.shields.io/badge/D1AL-d97706.svg)](#ref-D1AL)

### (b) 논문 요지

- 24종 센서 1억 쌍 촉각-렌치 데이터와 공통 인코더
- **문제** — 촉각 센서마다 감지 원리와 관측 형식이 달라 데이터와 표현을 센서 간에 재사용하기 어려움
  - 촉각 표현 학습의 확장성이 이종성에 막힘
- **기존 한계** — 기존 접근이 센서 다양성과 규모에서 제한적이라는 지적
  - **공유 구조 자기지도 학습** — 공통 틀은 주지만 센서 간 물리적 기준이 없음
  - **교차 센서 정렬** — 같은 접촉 조건에서 모은 쌍 데이터에 의존
  - **힘 기반 접지 선행 연구** — 센서 다양성과 규모가 작아 미지 센서 일반화가 충분히 탐색되지 않음
  - 독립 수집 촉각 데이터셋에는 센서 간 접촉 상태를 비교할 공유 물리 기준 부재
- **핵심 방법** — 모든 센서의 관측을 직접 측정한 6차원 렌치와 짝지어 센서 간 쌍 수집 없이 공유 물리 지도를 구성
  - **입력 적응** — 센서별 어댑터가 관측 형식을 맞춤
  - **공유 인코더** — Transformer가 학습형 물리 쿼리로 토큰을 모음
  - **렌치 정렬** — 모멘텀 갱신 렌치 인코더의 목표와 정렬하고 공유 디코더로 렌치를 복원
  - **TaF-Policy** — 촉각 특징, 시각 관측, 로봇 상태를 합쳐 액션 청크 생성
- **차별점** — 센서끼리 짝짓지 않고 각 센서를 렌치에만 짝지어 공통 물리 기준을 만듦
  - 서로 다른 감지 원리를 같은 연속 특징 공간에 올림
- **핵심 기여** — 데이터, 표현, 정책 세 가지
  - **데이터** — 전용 수집 플랫폼으로 4개 감지 계열(광학·자기·압력·압저항) 24종 센서에서 1억 쌍 이상 수집
  - **벤치마크** — 단일 프레임 힘 RMSE 2.799N에서 2.321N로 17.1% 감소, 교차 센서 검색 R@1 21.27%에서 34.38%로 13.11%p 상승, 모두 센서별 최강 베이스라인 대비
  - **시뮬레이션 조작** — UniVTAC 3개 과제 평균 51.3%, 최강 베이스라인 47.3%
  - **실물 조작** — 모든 방법이 수행한 3개 과제 평균 40.0%, 최강 베이스라인 18.3%
- **가치** — 이종 촉각 센서를 한 물리 척도로 비교하고 재사용하는 기반 제시

### (c) 시사점

- 측정 접촉 코퍼스의 센서 간 공통 기준점 후보
- **접촉 데이터 공백** — 시각 위주 코퍼스가 못 채우는 촉각 신호를 센서 24종 규모로 직접 측정해 제공
- **평가 도구** — 렌치 추정과 교차 센서 검색이 촉각 인코더의 비교 과제로 쓰일 여지

### (d) 먼저 확인할 점

- **공개 여부** — 데이터셋과 코드의 공개 약속이 초록·comment·본문에 없음
  - 프로젝트 페이지만 있어 규모와 라이선스를 가져다 쓸 수 있는지 확인 필요
- **저자 인정 한계** — 미지 센서 적응에도 라벨된 촉각-렌치 쌍과 센서별 입력 모듈 학습이 필요
- **실물 실패 사례** — 정밀 정렬이 필요한 Key Insertion, 파지가 불안정한 Lift Bottle에서 정책이 불안정
- **로봇 손 범위** — 센서 24종 중 다지 손 장착 여부는 초록에 없음, 손 단위 촉각 코퍼스인지 별도 확인 필요

## 🥈 논문 2

**ManiLadder: Benchmarking Robot Manipulation Through a Categorized and Multi-Difficulty Level Task Ladder**
[arXiv:2611.16374](https://arxiv.org/abs/2611.16374) · Chongkai Gao, Jieao Shi, Zhaoyu Mu 외 · arXiv preprint · source: keyword-sweep

**점수 11/15** · R2 · N3 · M3 · Real3 · Repro0 — 초록·arXiv comment·본문 모두 코드 저장소나 공개 약속 없음

### (a) 관련 Pillar / 질문
[![P0](https://img.shields.io/badge/P0-fbd7d6.svg)](#ref-P0) / [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 논문 요지

- 정책 성공률로 난이도를 맞춘 112개 과제 4단계 사다리
- **문제** — 기존 시뮬레이션 벤치마크로는 모델이 풀 수 있는 조작 난이도의 한계를 잴 수 없음
  - 과제 다양성만 넓혀 능력의 수직 성장을 보이지 못함
- **기존 한계** — 가로 확장 위주 벤치마크와 난이도 정의 방식의 확장성 문제
  - **기존 벤치마크** — pick-and-place, 밀기, 문 열기 같은 단순 기술을 장면과 물체만 바꿔 재조합
  - **이론 척도·하위 기술 조합·수작업 술어·접촉 패턴** — 다양한 현대 조작 과제로 확장하기 어렵다는 지적
  - 시뮬레이터와 절차적 생성 도구도 과제 난이도를 보장하지 못함
- **핵심 방법** — 표준 학습 조건에서 정책이 내는 성공률을 경험적 난이도로 쓰고 과제를 반복 보정
  - **표준 학습** — 과제마다 시연 20개를 고정하고 하나의 플로우 매칭 모방 학습 정책을 학습
  - **보정** — 물체 형상, 초기 무작위화, 지각 난이도, 시간 조율, 오차 허용치를 목표 난이도 구간에 들 때까지 조정
  - **검증** — 시연 재수집, 재학습, 서로 다른 정책, 에이전트형 학습 시스템에서 난이도가 유지되는지 확인
  - **Attained Level** — 알고리즘이 안정적으로 푸는 최고 난이도 단계를 재는 지표
- **차별점** — 난이도를 이론 척도가 아니라 표준 정책의 실측 성공률로 정의
  - 4단계 사다리에 보정된 난이도를 두어 단계별 능력 경계를 직접 측정
- **핵심 기여** — 벤치마크와 분석
  - **규모** — 4단계 112개 과제, 32개 스위트, 강체·변형체와 단일 팔 그리퍼·단일 팔 다지 손·양팔 그리퍼·양팔 다지 손 4종 로봇 구성
  - **데이터와 설정** — 표준 시연 2,240개 궤적, 다중 시점 RGB와 행동 레이블, 스크립트 전문가 제공
  - **분석** — 과제 속성, 소형·대형 VLA 비교, 다중 과제 대 단일 과제, 과제 전이와 데이터 스케일링
  - **실물 검증** — 4개 난이도 단계에서 고른 8개 과제로 시뮬레이션 난이도 순서가 실물에서 유지되는지 비교
- **가치** — 조작 능력이 어느 난이도까지 올랐는지 한 척도로 보고하는 공통 시험대 제공

### (c) 시사점

- 다지 손 과제를 난이도별로 비교하는 평가 사다리
- **평가 도구** — 손 계열 구성 2종이 들어 있어 다지 손 정책을 난이도 단계로 보고할 수 있음
- **한계** — 접촉 집약적 인핸드 기술에 초점을 둔 벤치마크는 아님, 난이도가 기준 정책에 묶인 점은 활용 시 고려

### (d) 먼저 확인할 점

- **공개 여부** — 초록·comment·본문에 코드 저장소나 공개 약속 없음
  - 본문의 버전별 공개 언급은 코드 문구가 아니어서 과제 설정과 보정 도구를 받을 수 있는지 확인 필요
- **난이도 의존성** — 저자도 보정이 평가 횟수와 사용 정책에 영향받는다고 인정
  - 시드 세 개로 시연을 다시 모아 검증했으나 정책 구조에 따라 난이도가 달라질 가능성은 남음
- **다지 손 비중** — 112개 과제 중 손 계열 구성의 수와 접촉 집약도는 본문 표로 확인 필요
