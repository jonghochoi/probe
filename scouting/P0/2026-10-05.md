## 🥇 논문 1

**The Imitator Game: Benchmarking Robot Imitative Ability Beyond Action Prediction**
[arXiv:2608.22301](https://arxiv.org/abs/2608.22301) · Xunzhe Zhou, Yiyang Cai, Fengyi Wang 외 9인 · arXiv preprint · source: citation-graph · 코드 공개 예정

**점수 11/15** · R3 · N3 · M3 · Real1 · Repro1 — 초록 "The project website and access to Imitator Arena are available at https://imitator-game.github.io"

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 논문 요지

- 인간 시연의 의도 모방을 4단계로 재는 벤치마크와 쌍 데이터셋
- **문제** — 로봇 정책이 시연의 궤적을 재현할 뿐 시연이 의도한 목표를 추론하지 못하는 한계
  - 인간 영상 학습이 인간 시연과 로봇 장면이 거의 같을 때만 통하는 궤적 수준에 머묾
  - 인간 영상이 실제 감독 신호로 쓰일 수 있는지를 가르는 능력이 바로 이 의도 수준 모방
- **기존 한계** — 손 키포인트·옵티컬 플로우를 추출해 로봇 동작으로 리타깃팅한 뒤 비슷한 장면에서 재생하는 방식
  - 물체 배치·형상·도구가 조금만 바뀌어도 시연 동작이 무효화
  - 기존 일반화 벤치마크는 학습 중 본 장면의 교란에 대한 강건성만 평가
  - 영상 조건부 정책은 시연과 실행 환경의 불일치가 작은 분포 내에서 주로 시험
- **핵심 방법** — 시연 장면과 로봇 장면의 불일치를 키우는 4단계 평가 틀과 이를 받치는 데이터·플랫폼
  - L0 장면 동일 실행, L1 공간 배치 변경, L2 외형·형상이 다른 같은 범주 물체, L3 기능이 다른 물체로 대체한 의도 수준 전이
  - IG-10K — 환경 정렬 인간-로봇 쌍 에피소드 데이터셋
  - Imitator Arena — 블라인드 A/B 인간 평가 오픈 플랫폼
- **차별점** — 장면 교란 강건성이 아니라 인간 영상을 보고 낯선 장면에서 의도를 재현하는지를 단계별로 분리해 측정
  - 기능적 대체(같은 의도를 다른 물체 어포던스로 달성)를 L3로 명시
- **핵심 기여** — 벤치마크, 데이터셋, 평가 플랫폼, 모델 비교의 네 가지 공개·수행
  - IG-10K — 쌍 에피소드 2만+, 과제 50+, 6개 도메인(서문은 과제 변형 200+), 시뮬레이션과 실물 양쪽을 4단계 전부에서 구성한 유일한 쌍 데이터셋이라고 주장
  - 9개 모델(학습 변형 15종)을 평가 — L0에서 L2까지 안정적이나 L3에서 붕괴
  - 인간 영상 조건부 모델이 캡션 조건부 모델을 앞서나 미학습 과제 제로샷 성공률은 전 모델 13% 미만
  - IG-10K 사전학습 모델에 쌍 시연 10개만으로 미세조정해도 큰 이득, 사전학습 규모에 따라 이득 증가
- **가치** — 인간 영상이 로봇 조작의 실질 감독원이 되는 데 필요한 능력과 현재 장벽을 수치로 드러내는 기준점
  - 장벽을 기능적 대체로 특정해 이후 방법이 어느 단계에서 갈리는지 비교할 자리를 제공

### (c) 시사점

- 인간-로봇 쌍 코퍼스와 단계형 모방 벤치마크의 동시 확보
- 환경 정렬 쌍 데이터라는 인간 영상 중심 축의 보조 코퍼스 후보
  - 실물·시뮬레이션 양쪽 쌍 에피소드를 갖춰 인간 영상 활용 경로 평가에 쓸 수 있음
- L0–L3 구조가 평가 하니스의 단계 설계 참고안
- 데이터 규모 확장만으로 L3 붕괴가 풀리지 않는다는 결론은 코퍼스 투자 우선순위 판단의 반례

### (d) 먼저 확인할 점

- 코드·데이터 공개가 프로젝트 페이지 안내뿐, 저장소 URL과 라이선스 조항 확인 필요
- 실물 평가 수치가 초록·서문에서 분리되지 않아 실물 비중은 본문 확인 필요
- 저자 명시 한계 — 과제·단계마다 대체 패턴이 하나뿐이라 대체 변이에 따른 분산 미측정
- 시뮬레이션 L3 결과는 한정된 자산과 규칙 기반 모션 계획의 편향 포함
- 평가 대상 정책이 이 벤치마크용으로 설계되지 않은 적응 모델이라 최적 구조는 미결

## 🥈 논문 2

**MANIGUARD: A Benchmark and Data Suite for Specification-Grounded Safety Evaluation and Improvement of Robotic Manipulation**
[arXiv:2608.17386](https://arxiv.org/abs/2608.17386) · Yiyan Peng, Philip Wang, Simon Sinong Zhan 외 11인 · arXiv preprint · source: citation-graph · 코드 공개 예정

**점수 9/15** · R2 · N2 · M3 · Real1 · Repro1 — 초록 "we release 8,000 safety-annotated demonstrations"

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 논문 요지

- 성공과 분리해 안전을 재는 접촉 집약 벤치마크와 시연 데이터
- **문제** — 파운데이션 모델 정책이 과제 성공은 빠르게 늘었으나 안전하게 성공하는지의 엄밀한 평가 부재
  - 공격자 없이 정상 지시·일반 장면에서도 쏟음·넘어뜨림·충돌·순서 위반이 발생
  - 실물 손상은 비용이 크고 되돌리기 어려워 시뮬레이션 기반 노출이 필요
- **기존 한계** — 기존 평가가 안전을 정의하거나 실행 중 감시하지 않음
  - 조작 벤치마크는 과제 성공과 일반화만 측정
  - 에이전트 안전 벤치마크는 위험 인식과 계획 수준에 머물러 접촉 집약 궤적 수준 실행까지 가지 못함
  - 형식 사양을 쓰는 소수 벤치마크는 접촉 물리가 없는 단순 시뮬레이터이거나 기존 과제에 감시기를 덧댄 형태
  - 사양과 짝지은 안전 주석 데이터가 없음
- **핵심 방법** — 안전 사양을 형식 논리로 쓰고 자동 감시기로 매 스텝 판정하는 벤치마크와 데이터 생성 파이프라인
  - 가정 조작 6개 과제군을 기술 수준 × 제약 유형 분류로 구성
  - 안전 요구를 시뮬레이터 상태에서 뽑은 물리 술어 위의 LTLf 식으로 명세하고 결정적 유한 오토마타로 컴파일, 학습 분류기나 LLM 판정기 없이 위반 판정
  - Isaac Sim·OmniGibson 기반, 동일 과제 조건의 Franka 실물로 확장
  - cuRobo 기반 자동 생성기와 원격 조작 인터페이스가 같은 감시기로 주석
- **차별점** — 안전을 과제 성공과 직교하게 설계해 성공하고도 위반하거나 실패하고도 안전한 경우를 구분
  - 형식 사양 벤치마크 중 학습용 안전 주석 데이터를 함께 공개하는 구성
- **핵심 기여** — 벤치마크, 생성 파이프라인, VLA 실패 모드 평가
  - 과제 200개 고정, 분포 내 1개와 단일 축 분포 외 변형 4개로 시나리오 1,000개 구성
  - 안전 주석 시연 8,000개 공개 — 기본 과제당 40개
  - 23,000회 이상 롤아웃 평가 — 성공 롤아웃의 6–21%가 사양 위반
  - 미세조정으로 안전 과제 완료율이 거의 0에서 7.5–29.8%, 개입 후 안전 행동이 16–40%에서 51–72%로 상승
  - 시연을 늘려도 해소되지 않는 격차 — 개입 롤아웃의 21–42%가 여전히 위반, 6개 과제군 중 2개는 모든 정책에서 안전 성공 2% 미만
  - 이 패턴이 분포 이동과 실물에서도 지속
- **가치** — 성공률 지표가 가리는 안전 실패를 재현 가능한 판정으로 드러내는 평가 도구
  - 정책별 안전 민감도를 비교할 수 있는 공통 사양 기반

### (c) 시사점

- 성공률과 별개의 안전 평가 축을 갖춘 접촉 집약 벤치마크 확보
- 사양 기반 자동 감시기가 평가 하니스의 판정 설계 참고안
  - 학습 판정기에 의존하지 않아 롤아웃 재판정 가능
- 안전 주석 시연 8,000개로 안전 인지 미세조정 실험 가능
- 다지 손이 아닌 Franka 그리퍼 중심이라 다지 조작 코퍼스로는 보조 위치

### (d) 먼저 확인할 점

- 저장소·페이지 URL 없이 데이터 공개 진술만 있어 실제 공개 위치와 라이선스 확인 필요
- 실물 평가가 Franka 단일 플랫폼이고 수치가 초록에 없어 규모는 본문 확인 필요
- 시뮬레이션과 실물의 안전 결과가 부분 일치에 그친다는 저자 진술, 시뮬레이션 판정의 실물 대표성 한계
- 가정 조작 6개 과제군 한정, 다지 손 과제 포함 여부 확인 필요

## 🥉 논문 3

**Ego4WAM: What Matters When Scaling Egocentric Human Data for Robot Learning?**
[arXiv:2609.40341](https://arxiv.org/abs/2609.40341) · Zhihao Sun, Liu Liu, Xinjiang Wang 외 6인 · arXiv preprint · source: citation-graph · 코드 미공개

**점수 7/15** · R2 · N2 · M2 · Real1 · Repro0 — 초록·arXiv comment 모두 코드·프로젝트 페이지 신호 없음

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML)

### (b) 논문 요지

- 에고센트릭 인간 데이터의 어떤 속성이 로봇 성능을 좌우하는지 통제 비교
- **문제** — 에고센트릭 데이터를 늘리면 좋아진다는 보고는 있으나 어떤 속성과 사용법이 이득을 만드는지 불명확
  - 정렬 정도, 행동 범위, 지도 신호가 시간 합계로만 요약돼 서로 뒤섞임
- **기존 한계** — 기존 연구는 인간 데이터 증가에 따른 유리한 스케일링을 보이는 데 그침
  - 인간 행동 궤적 확보에는 카메라·손 자세 추정이 필요해 처리 비용이 늘고 라벨 신뢰도가 떨어짐
  - 평가가 인간 행동 예측 오차에 치우친 경우가 많음
- **핵심 방법** — 월드-액션 모델(WAM) 백본을 고정하고 데이터 속성과 사용 전략만 바꿔 비교
  - 로봇과 정렬한 인간 시연의 효과 분석
  - 데이터 시간과 과제 다양성의 분리
  - 액션 라벨 없는 영상의 월드 모델링 기여와 이후 영상-액션 학습과의 상호작용
- **차별점** — 데이터 시간 하나를 스케일 축으로 삼지 않고 정렬·다양성·지도·사용 전략의 역할을 분해
  - 인간 행동 예측 지표가 아니라 실물과 RoboDojo의 폐루프 정책 성능으로 평가
- **핵심 기여** — 데이터 수집·활용 지침으로 정리되는 실증 결과
  - 정렬된 인간 시연이 분포 외 일반화를 크게 높이고 목표 과제 로봇 데이터 필요량을 줄임
  - 데이터 시간과 과제 다양성이 서로 다른 능력에 영향
  - 액션 라벨 없는 영상만으로도 이후 영상-액션 학습의 기반으로 유효
  - 결론 기준 — 인간 데이터가 로봇 데이터를 완전히 대체하지는 못하고, 드문 장기 꼬리 과제 추가는 정밀 과제를 오히려 해칠 수 있음
- **가치** — 무엇을 수집하고 어떤 지도를 얻고 어떻게 쓸지에 대한 실증 기준
  - 규모 단일 지표 중심의 데이터 투자 판단 재고

### (c) 시사점

- 에고센트릭 데이터 수집 설계의 직접 근거
- 정렬 데이터와 다양성 데이터의 역할 분리, 정렬 시연 소량이 로봇 데이터 필요량을 줄이는 방향
- 액션 라벨 없는 에고센트릭 영상도 활용 가능하다는 결과
  - 손 자세 라벨이 부족한 대규모 영상의 가치 평가에 참고
- 신규 코퍼스가 아닌 연구 결과 중심이라 코퍼스 후보가 아닌 설계 근거로 사용

### (d) 먼저 확인할 점

- 코드·체크포인트 공개 여부, 초록에는 신호가 없고 결론이 공개 예정을 진술하나 시점·위치 미명시
- 실물 결과가 초록상 수치 없이 폐루프 평가로만 언급, 과제 수와 성공률 본문 확인 필요
- 단일 WAM 백본 고정 결과라 다른 정책 구조에서의 일반성 확인 필요
- 사용 데이터 코퍼스 공개 여부와 라이선스 확인 필요
