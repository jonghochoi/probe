## 🥇 논문 1

**The Imitator Game: Benchmarking Robot Imitative Ability Beyond Action Prediction**
[arXiv:2608.22301](https://arxiv.org/abs/2608.22301) · Xunzhe Zhou, Yiyang Cai, Fengyi Wang 외 9인 · arXiv preprint · source: citation-graph · 코드 공개 예정

**점수 12/15** · R3 · N3 · M3 · Real2 · Repro1 — 초록 "The project website and access to Imitator Arena are available at https://imitator-game.github.io"

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 논문 요지

- 인간 시연의 의도 모방을 4단계로 재는 벤치마크와 쌍 코퍼스
- **문제** — 로봇이 시연의 궤적이 아니라 의도를 재현하는지 가를 측정 기준 부재
  - 인간 영상이 로봇 조작의 실용적 감독 자원이 되려면 장면이 달라져도 목적을 유지하는 능력 필요
- **기존 한계** — 인간 영상 학습의 궤적 수준 의존과 기존 평가의 장면 편중
  - 손 키포인트·옵티컬 플로를 뽑아 로봇 액션으로 리타깃하고 유사한 장면에서 재생하는 방식은 물체 배치·형상·도구가 바뀌면 시연 모션이 무효화
  - 기존 일반화 벤치마크는 학습 중 본 장면의 교란 강건성 위주 평가
  - 영상 조건 정책은 시연과 실행 환경의 불일치가 작은 분포 내 시험 위주
- **핵심 방법** — 시연 장면과 로봇 장면의 불일치를 4단계로 넓혀 가는 평가 틀
  - L0 — 장면 동일 실행, 시연 궤적 재현
  - L1 — 공간 적응, 물체 정체성은 같고 배치가 다름
  - L2 — 시각·물리 일반화, 의미 역할은 같고 외형·형상이 다른 물체
  - L3 — 의도 수준 전이, 물체가 의미·기능이 다른 것으로 교체(주전자에서 수도꼭지로 컵 채우기)
  - 쌍 코퍼스 IG-10K와 블라인드 A/B 사람 평가 플랫폼 Imitator Arena로 구성
- **차별점** — 궤적 재생이 통하지 않게 되는 지점을 단계별로 분리하는 설계
  - 장면 불일치를 한 축으로 단계화해 과제 이해가 필요해지는 경계를 식별
- **핵심 기여** — 벤치마크, 코퍼스, 평가 플랫폼과 9개 모델 평가
  - IG-10K — 환경 정렬 인간-로봇 쌍 에피소드 2만 개 이상, 과제 50개 이상, 6개 도메인, 4단계 전부를 실물·시뮬레이션 양쪽에 구현한 유일한 코퍼스라는 저자 주장
  - Imitator Arena — 구조화된 블라인드 A/B 사람 평가 개방 플랫폼
  - 9개 최신 모델(학습 변형 15종)에서 L0에서 L2까지 성능 안정, L3에서 붕괴하며 기능적 대체가 결정적 장벽
  - 영상 조건 모델이 캡션 조건 모델보다 우수하나 미관측 과제 제로샷 성공률은 전 모델 13% 미만
  - IG-10K 사전학습 모델에 쌍 인간-로봇 시연 10개만 더해 미세조정 시 이득이 사전학습 규모와 함께 증가
- **가치** — 인간 영상 활용 수준을 궤적에서 의도로 끌어올릴 공개 측정 기준 확보
  - 단순 스케일링으로 의도 수준 모방이 따라오지 않는다는 근거 제시

### (c) 시사점

- 인간→로봇 전이 코퍼스와 평가 공백을 한 릴리스로 겨냥
- 환경 정렬 쌍 에피소드 2만 개 이상으로 인간 영상 활용 효과를 단계별 측정 가능
- 실물·시뮬레이션 양쪽 구현이라 전이 평가 하니스 설계 참조 가능
- 10개 시연 미세조정 이득은 소량 로봇 데이터 전이 경로의 기준점

### (d) 먼저 확인할 점

- 저자 기술 한계 — IG-10K가 유한하고 수작업 설계, 과제-단계 쌍마다 대체 패턴 1종이라 대체 변동성 미측정
- 단계는 장면 불일치만 등급화하고 시연자-로봇 형태 차이는 거의 고정
- 시뮬레이션 L3 결과는 유한 자산과 규칙 기반 모션 계획의 편향 존재
- 평가 정책은 의도 수준 모방용이 아니라 이 벤치마크에 맞춰 적응한 것
- 다지 손과 접촉 모달리티 비중, 라이선스 조항은 초록 미명시, 본문 확인 필요
- 코드는 프로젝트 페이지 안내만 있어 공개 시점 확인 필요

## 🥈 논문 2

**Towards a General Humanoid Loco-Manipulation Model via Egocentric Whole-Body Human Data Pretraining**
[arXiv:2610.00438](https://arxiv.org/abs/2610.00438) · Chongyang Xu, Zhao Wu, Jin Chen 외 9인 · arXiv preprint · source: citation-graph · 코드 공개 예정

**점수 9/15** · R3 · N2 · M2 · Real1 · Repro1 — 초록 "We will release our code, models, and data to support further research."

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML)

### (b) 논문 요지

- 500시간 전신 인간 데이터와 3단계 사전학습 휴머노이드 VLA
- **문제** — 휴머노이드 이동 조작 학습에 필요한 몸 전체 움직임과 물체 상호작용을 함께 담은 시연의 확장 곤란
  - 휴머노이드 전신 원격조작 수집은 로봇 시간과 인력 소요로 과제·환경 확장이 어려움
- **기존 한계** — 에고센트릭 영상 기반 감독의 전신 커버리지 부족
  - 영상에서 손목·손 궤적을 복원해 액션 감독으로 쓰는 기존 방법은 손 중심
  - 접근, 자세 조정, 파지 유지 같은 몸 움직임과 손-물체 상호작용의 시간적 협응을 담지 못함
- **핵심 방법** — 전신 모션을 동기 기록한 코퍼스와 3단계 학습
  - HumanVerse-500 — 경량 착용 장비로 에고센트릭 영상과 신체 모션을 동기 수집하고 영상에서 손 모션을 복원
  - 1단계 — 다양한 에고센트릭 데이터셋으로 손 모션 사전학습
  - 2단계 — HumanVerse-500으로 신체·손 모션 협응을 학습하는 전신 미드트레이닝
  - 3단계 — 하위 과제와 로봇 형태로 적응하는 로봇 후학습
  - 공유 표현 공간으로 단계 간 전이, 도메인별 인터페이스로 인간-로봇 상태·액션 차이 처리
- **차별점** — 손목·손 궤적만이 아니라 신체와 손 모션을 동기화한 전신 감독 사용
  - 단계 간 공유 표현 공간과 도메인별 인터페이스 분리로 인간 경험을 로봇 제어로 전이
- **핵심 기여** — 코퍼스, 정책, 스케일링 결과
  - HumanVerse-500 — 개방 환경 인간 이동 조작 500시간, 에고센트릭 영상과 신체·손 모션 동기
  - λ0 — 공유 인간-로봇 표현 공간의 전신 휴머노이드 VLA
  - SIMPLE에서 3.9%p, 실물 이동 조작 4개 과제에서 22.5%p로 평가 대상 최강 베이스라인 상회
  - 평가한 데이터 규모 범위에서 전신 인간 데이터 증가가 검증 손실을 줄이고 실물 과제 진행도를 개선
  - 두 인간 데이터 단계 중 전신 미드트레이닝이 실물 성공에 더 크게 기여, 인간 시연이 로봇 미관측 물체의 진행도 개선
- **가치** — 인간 에고센트릭 경험을 전신 휴머노이드 제어 감독으로 쓰는 스케일링 근거 확보

### (c) 시사점

- 전신 모션을 동기한 에고센트릭 코퍼스로 손 중심 코퍼스의 빈자리 보완
- 인간 데이터 규모와 실물 진행도 관계를 보여 코퍼스 확보 우선순위 판단 근거
- 단계별 기여 분해(미드트레이닝 우세)가 데이터 수집 설계 참조점

### (d) 먼저 확인할 점

- 코드·모델·데이터 모두 공개 약속 단계, 공개 시점과 라이선스 확인 필요
- 손가락 수준 정밀도와 촉각·힘 모달리티는 범위 밖으로 보여 다지 접촉 조작과의 거리 확인 필요
- 실물 평가가 4개 과제에 그쳐 일반화 폭은 본문 확인 필요
- 수치는 평가 대상 베이스라인 대비 상대 이득이며 베이스라인 구성은 본문 확인 필요

## 🥉 논문 3

**HandEdit: A Unified Benchmark for Egocentric Human-to-Robot Dexterous Hand Image Editing**
[arXiv:2608.12122](https://arxiv.org/abs/2608.12122) · Zhenjie Yang, Xingyu Jiao, Guopeng Zhong 외 18인 · arXiv preprint · source: citation-graph · 코드 공개 예정

**점수 8/15** · R3 · N2 · M2 · Real0 · Repro1 — arXiv comment "Technical Report. Project Page: https://handedit.github.io/"

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 논문 요지

- 인간 손 프레임을 26종 로봇 형상으로 바꾸는 편집 벤치마크
- **문제** — 에고센트릭 인간 영상과 로봇 데이터를 함께 학습할 때 손 외형·관절·시점 차이로 생기는 형태 간극
  - 단순 스타일 전이로는 해소 불가, 편집 결과가 장면·물체 상태·과제 의미·손-물체 접촉을 보존하면서 URDF가 정한 로봇 형상을 따라야 함
- **기존 한계** — 로봇화 접근의 형상 종속과 전용 평가 자원 부재
  - 렌더링한 로봇을 인간 장면에 삽입하는 기존 접근은 평행 그리퍼·고정 플랫폼·형상별 파이프라인에 묶임
  - 범용 이미지 편집 모델은 형상 전용 사전지식 부재
  - 인간→로봇 다지 손 편집을 이미지 편집 문제로 다룬 대규모 데이터셋·통합 평가 프로토콜·벤치마크 없음
- **핵심 방법** — 공개 손-물체 데이터에서 편집 쌍을 만들고 2트랙으로 평가
  - EgoDex, ARCTIC, OakInk2, HOI4D, HO-Cap 5종에서 클립 30만 개, 장면 600개 이상, 물체 1.1천 개 이상 추출
  - 편집 인스턴스 2억 건 이상, 목표 URDF 26종(손 단독 13종, 손-팔 13종)
  - 손 단독과 손-팔 2트랙, URDF 조건 평가
  - 일반 유사도, VLM 판정, 형상 인식 지표를 묶은 평가 스위트
- **차별점** — 인간→로봇 다지 손 전이를 URDF 조건 이미지 편집 문제로 정식화
  - 로봇 형상을 URDF로 지정해 형상 26종을 한 프로토콜로 비교
- **핵심 기여** — 데이터셋, 벤치마크, 평가 스위트, 11개 편집기 평가
  - 형상 인식 이미지 편집 데이터셋 최초라는 저자 주장, 2억 건 이상
  - 손 단독과 손-팔 2트랙 통합 벤치마크
  - 상용·오픈소스 편집기 11종을 원래 조건 인터페이스로 평가하고 사람 평가로 지표 검증
  - 범용 편집기의 한계 확인
- **가치** — 풍부한 인간 영상을 다지 로봇 학습 데이터로 바꾸는 편집 모델 개발의 기준 자원

### (c) 시사점

- 에고센트릭 인간 영상을 로봇 외형으로 바꾸는 편집 축의 첫 공개 기준점
- 26개 URDF 포괄로 손 형태가 다른 다지 로봇 간 비교 가능
- 원천이 EgoDex 등 공개 데이터라 에고센트릭 축과 직접 연결

### (d) 먼저 확인할 점

- 실물 로봇 평가 없음, 편집 품질이 정책 성능 향상으로 이어지는지 미검증
- 원천 데이터 라이선스가 CC-by-NC-ND, GPL-3.0 등으로 혼재, URDF는 비상업적 연구·벤치마크 평가 한정이라 하류 사용 제약 확인 필요
- 코드는 프로젝트 페이지 안내만 있어 데이터 배포 방식 확인 필요
- 평가가 이미지 편집 지표 위주로 접촉 보존의 정량 검증 폭 확인 필요
