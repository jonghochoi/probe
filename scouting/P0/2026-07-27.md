## 🥇 논문 1 — 우선순위 ★★★

**AXIS: A Growable Community-Driven Data Engine for Scalable Robot Manipulation**
[arXiv:2607.21588](https://arxiv.org/abs/2607.21588) · Mengfei Zhao, Dihong Huang, Yikai Tang 외 12인 · source: citation-graph

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 핵심 기여
- 특수 하드웨어·중앙집중식 오퍼레이터·고정 태스크 세트에 의존하는 기존 로봇 시연 수집 파이프라인의 확장성 한계 지적
- 브라우저 기반 원격 텔레옵으로 커뮤니티가 직접 시연을 수집하는 성장형(growable) 데이터 엔진 AXIS 제시
- 태스크 자동 생성·검증, 성공 여부 자동 판정, 품질 필터링, 궤적 스무딩, 시각·물리 기반 증강까지 원시 수집분을 학습 준비 데이터로 변환하는 전체 파이프라인 통합
- 현재 릴리스 기준 207개 다양 태스크·5만+ 궤적 규모, 태스크 스냅샷 단위 데이터 조직화 + held-out 평가 프로토콜 동반
- `π0.5` 정책 연속 사전학습 시 AXIS 데이터로 전체 성공률 5.8%p 개선, RoboCasa365 사전학습 대비 37.3% 우위, 데이터 볼륨 증가에 따른 일관된 스케일링 확인

### (c) 시사점
- 중앙집중형 하드웨어·오퍼레이터 의존을 낮추는 크라우드소싱 텔레옵 모델 — 데이터 수집 비용 구조 자체를 바꾸는 접근
- 태스크 자동 생성·검증까지 자체 파이프라인에 포함돼 신규 태스크 확장이 외부 개입 없이 지속 가능
- 데이터 볼륨-성능 스케일링을 정량 확인한 사례 — 향후 자체 데이터 축적 로드맵의 참고 곡선으로 활용 가능

### (d) 먼저 확인할 점
- 데이터셋·엔진 코드의 실제 공개 저장소(GitHub/HuggingFace) 링크가 초록·메타데이터상 확인되지 않음 — 프로젝트 페이지 직접 확인 필요
- 커뮤니티 기여 기반 수집 특성상 하드웨어·환경 편차에 따른 데이터 품질 분산 검증 필요
- 207개 태스크의 다지 손·접촉 집약도 비중이 초록상 불명확 — 병렬 그리퍼 위주 여부 확인 필요

## 🥈 논문 2 — 우선순위 ★★

**From Grasps to Dexterity: Large-Scale Grasp Pretraining for Dexterous Manipulation**
[arXiv:2606.30749](https://arxiv.org/abs/2606.30749) · Ying Yuan, Xinyu Liu, Sriram Krishna, David Held · source: citation-graph

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 핵심 기여
- 대규모 dexterous grasp 데이터셋이 grasp 생성·pick-and-place 조작에만 국한 활용돼 온 관행 지적, articulated tool-use(도구의 기능적 가동부 조작)로 활용 범위 확장 시도
- hand sub-goal 예측(고수준) + goal-conditioned 컨트롤러(저수준)를 결합한 계층적 모방학습 프레임워크 채택
- 기존 대규모 grasp annotation으로부터 35.5만 궤적 규모의 grasp-pretraining 데이터셋을 구축해 저수준 컨트롤러 사전학습에 활용, 이후 다운스트림 태스크 시연으로 파인튜닝
- 협응된 손가락 움직임을 요구하는 6개 articulated tool-use 태스크로 구성된 시뮬레이션 벤치마크 DexCraft 신규 제시
- 시뮬레이션·실환경 모두에서 end-to-end diffusion policy 및 from-scratch 계층적 정책 대비 우위 확인, 실환경 DP3 대비 전체 태스크 성공률 33.3%p 개선

### (c) 시사점
- grasp 데이터셋이 단순 파지 합성용을 넘어 접촉 집약적 다지 조작의 사전학습 데이터로도 재활용 가능함을 실증 — 기존 데이터 자산의 활용 범위 확장 여지
- articulated tool-use 벤치마크(DexCraft)는 in-hand-rotation/articulated-tool 평가 계열에 직접 부합하는 신규 축적 사례
- 실환경 정량 개선폭까지 보고돼 sim 벤치마크 결과의 실전 전이 신뢰도가 상대적으로 높음

### (d) 먼저 확인할 점
- 35.5만 궤적 pretraining 데이터셋 자체의 공개 범위·다운로드 경로가 초록상 확인되지 않음 — 프로젝트 페이지 직접 확인 필요
- DexCraft 벤치마크가 6개 태스크로 아직 소규모 — 태스크 다양성 확장 전까지 범용 벤치마크로서의 커버리지 제한적
- 기존 grasp annotation 데이터셋(원 출처)의 라이선스 조건이 그대로 승계되는지 확인 필요

## 🥉 논문 3 — 우선순위 ★

**RoboInter1.5: A Holistic Intermediate Representation Suite for Embodied World Modeling and Robotic Manipulation**
[arXiv:2607.18709](https://arxiv.org/abs/2607.18709) · Ziqin Wang, Hao Li, Weijun Wang 외 5인 · source: citation-graph

### (a) 관련 Pillar / Decision
[![P0](https://img.shields.io/badge/P0-f5d5d5.svg)](#ref-P0) / [![D4ML](https://img.shields.io/badge/D4ML-d97706.svg)](#ref-D4ML) [![D6SE](https://img.shields.io/badge/D6SE-d97706.svg)](#ref-D6SE)

### (b) 핵심 기여
- 기존 로봇 데이터셋 대다수가 수집 비용이 높고 임베디먼트 특정적이며 세분화된 구조적 주석이 부족하다는 공백 지적
- 전작 RoboInter1.0을 확장한 통합 중간표현(intermediate representation) 스위트 — 데이터·벤치마크·모델을 한데 묶은 리소스로 재정의
- RoboInter-Data: 571개 씬에 걸친 23만+ 조작 에피소드, 서브태스크·프리미티브 스킬·객체/그리퍼 그라운딩·세그멘테이션·어포던스·grasp pose·contact point·motion trace 등 10종 이상 조밀 프레임 단위 주석 포함
- RoboInter-VQA로 중간표현 추론 능력을 평가하는 공간·시간 임베디드 VQA 벤치마크 신규 도입, RoboInter-VLA로 중간표현이 실행(암묵적/명시적/모듈형 plan-then-execute)에 주는 이득 분석
- RoboInter-World로 중간표현을 구조화된 조건화 신호로 활용해 미래 월드 상태 예측까지 확장

### (c) 시사점
- 대규모 조밀 주석(중간표현) 계층을 표준 데이터 자산으로 취급 — 별도 원시 데이터 수집 없이도 기존/신규 조작 에피소드의 활용 가치를 끌어올리는 접근
- VQA 벤치마크(RoboInter-VQA)가 embodied reasoning 평가 축 확장 후보
- 데이터·벤치마크·모델을 한 릴리스로 묶어 재현 경로가 상대적으로 명확한 구조

### (d) 먼저 확인할 점
- arXiv 관리자 노트상 전작(2602.09973)과 본문 상당 부분 중복 명시 — 순수 신규분과 확장분 구분을 위해 버전 비교 확인 필요
- 23만+ 에피소드가 실로봇 신규 수집분인지 기존 코퍼스 재주석인지 초록상 불명확 — Sim2Real 근거 별도 확인 필요
- 공개 저장소(GitHub/HuggingFace) 링크가 초록·메타데이터상 확인되지 않음 — 프로젝트 페이지 직접 확인 필요
