# 프레임은 늘어도 세계는 하나다 — 같은 자리에 도착한 점은 한 점으로 합친다

## 1 무엇이 문제인가

### 모든 점이냐 긴 영상이냐 — 지금까지는 하나만 고를 수 있었다 | Sparse Tracking · First-frame Dense · All-frame Dense

[점 추적](term:point-tracking)의 지형을 원문 §1 은 한 문장으로 자릅니다. 희소 추적기는 긴 시간
지평을 따라갈 수 있지만 **사용자가 찍어 준 소수의 질의점**만 따라가고, 장면의 나머지는 모델링하지
않습니다. 밀집 추적기는 반대로 프레임마다 픽셀 공간에서 다시 인코딩하는 구조라 영상이 길어질수록
계산이 폭발해요.

그래서 기존 밀집 방법들은 둘 중 하나로 타협해 왔습니다. 하나는 [첫 프레임에 보이는 점만
추적](term:first-frame)하는 쪽 — 나중에 새로 드러나는 표면은 무시합니다. 다른 하나는 [모든 프레임의
모든 점을 추적](term:all-frame)하되 48–64 프레임짜리 짧은 클립에 머무는 쪽입니다. 저자들의 결론은
그래서 단정적입니다 — **전체 길이 영상에서 보이는 장면 점 전부를 추적한 선행 방법은 없다.**

### 같은 벽을 200 번 다시 그리는 비용 | Per-frame Redundancy · Pixel-space Scaling

왜 그 칸이 비어 있었는지에 대한 원문의 진단은 **중복**입니다. 프레임 단위 2D 표현에서는 새 프레임이
들어올 때마다 시각 토큰 격자가 통째로 추가되고, 그 프레임이 새 장면을 보여 주든 이미 본 표면을 다시
보여 주든 똑같이 처리됩니다. 비용과 메모리는 영상 길이에 선형으로 늘어나요.

§2 는 이 비용에 크기를 붙입니다. 같은 표면이 매 프레임 독립적으로 표현되기 때문에, 512×512
해상도의 200 프레임 영상에서 모든 점을 추적하려면 **$`10^{10}`$ 개 수준의 예측**이 필요하다는
것입니다. 정적인 벽 한 장이 200 번 다시 태어나 200 개의 궤적을 받는 셈이에요.

저자들이 비집고 들어가는 틈은 간단한 관찰입니다. 영상은 결국 **밑에 깔린 3D 세계를 2D 카메라에
투영한 흐름**일 뿐이니, 표현을 3D 장면 쪽에 두면 비용이 프레임 수가 아니라 고유한 장면 내용에
비례하게 만들 수 있다는 것. 이 프레임 기준 스케일링과 3D 장면 기준 스케일링 사이의 간극이 이
논문의 출발점입니다.

### 상관 볼륨에서 3D 특징 구름으로 — 이 논문이 물려받은 것과 버린 것 | PIPs · 4D Correlation · TAPIP3D · WAFT

§2 는 이 논문의 자리를 아주 정확히 짚습니다. PIPs 와 TAP-Vid 는 사용자가 정한 소수의 질의점을 영상
내내 따라가는 현대 희소 추적의 틀을 세웠고, 뒤따른 방법들(CoTracker3 등)은 같은 레시피를 씁니다 — 긴
영상은 **슬라이딩 창**으로 자르고, 각 창 안에서는 질의 특징과 밀집 영상 특징 사이의
[4D 상관 볼륨](term:corr-volume)을 보며 **반복 정제**합니다. 이 논문은 앞의 둘(슬라이딩 창과 반복
정제)은 그대로 물려받습니다. 버리는 것은 상관 볼륨이에요.

3D 로 넘어온 희소 추적기들도 같은 벽에 부딪힙니다. TAPIP-3D 는 3D 특징 구름 안에서 이웃 어텐션을
하고, SpatialTracker-v2 는 2D 와 3D 상관을 함께 써 기하와 운동을 공동 정제하지만, 저자들의 지적은
**내부 특징 구름이 여전히 프레임마다 픽셀 격자 전체를 들고 있다**는 것입니다. 3D 를 쓰는데도
메모리는 영상 길이에 선형이에요. 이 논문은 세 군데에서 갈라집니다 — 3D 표현이 픽셀 공간에 묶이지
않고 새 장면이 나올 때만 자라며, 상관 대신 WAFT 의 3D 확장을 쓰고, 질의점이 아니라 모든 점을
추적합니다.

## 2 무엇을 바꿨나

### 창 하나 안에서 — 이미지 특징을 세계 좌표로 들어 올린다 | Encoding · Pointmap Unprojection · Per-frame Voxelization

입력은 RGB 영상과 함께 프레임별 세계 좌표 [포인트맵](term:pointmap) $`\mathbf{P}\in\mathbb{R}^{T\times H\times W\times 3}`$ 입니다. 깊이 센서에서
오든 [VGGT-Ω](term:vggt-omega) 같은 피드포워드 복원 모델에서 오든 상관없어요. 출력은 장면의 고유한
점 $`N`$ 개 전부에 대한 3D 궤적 $`\mathbf{X}\in\mathbb{R}^{N\times T\times 3}`$, 프레임별 가시성 로짓,
그리고 점당 정적/동적 로짓 하나입니다. 로짓은 시그모이드를 거쳐 확률이 되기 전의 점수예요 — 클수록 '보인다',
'움직인다' 쪽입니다.

영상은 **겹치지 않는 $`L{=}16`$ 프레임 창**으로 처리합니다. 창 안의 각 프레임은 얼린
[DINOv3-small 과 학습되는 ViT Adapter 헤드](term:dinov3)를 거쳐 $`(L, H/4, W/4, D)`$ 모양의 특징
지도가 되고, $`D{=}384`$ 입니다. 특징 지도의 각 칸은 같은 해상도로 줄인 포인트맵의 3D 좌표와 짝지어져
**세계 좌표 위의 토큰**이 됩니다. 원문이 '역투영(unproject)' 이라고 부르는 이 단계는, 2D 픽셀에 찍힌
특징을 그 픽셀이 본 표면의 3D 위치로 옮겨 놓는 일이에요. 장면 기하는 첫 카메라 $`\mathrm{cam}_0`$ 의 좌표계에서 하나의 전역
스케일로 정규화돼요.

여기서 첫 번째 [복셀화](term:voxel)가 들어갑니다. 목적은 **한 프레임 안의 공간 중복**을 줄이는 것 —
멀리 있는 벽처럼 여러 픽셀이 사실상 같은 작은 공간을 찍은 경우입니다. 한 프레임 안에서 같은 복셀에
떨어진 토큰들은 평균 풀링으로 하나가 됩니다. 중요한 것은 이 단계가 **프레임마다 따로** 일어난다는 점이에요. 서로 다른
시각에 같은 3D 영역을 지나간 서로 다른 표면이 잘못 합쳐지지 않게 하려는 것입니다. 그렇게 줄어든
토큰을 $`L`$ 프레임에 걸쳐 이어 붙인 것이 $`(N, D)`$ 모양의 **시공간 특징 구름**이고, 창 처리가
끝나기 전까지는 여러 프레임에서 관측된 같은 표면의 대표가 여러 개 남아 있습니다.

### 끝점 먼저, 궤적은 움직이는 점만 | Endpoint Refiner · Static/Dynamic Logit · Position Embeddings

창 안의 모든 점에 $`L`$ 프레임짜리 궤적을 전부 디코딩하는 것은 계산상 불가능에 가깝고, 저자들 말로
**대부분 낭비**입니다. 실제 장면의 점 대다수는 세계 좌표에서 가만히 있으니까요. 게다가 다음 창으로
상태를 넘기는 데에는 궤적 전체가 필요 없습니다. 점을 넘겨주고 같은 표면을 합치려면 **창 경계에서의
도착지**만 알면 됩니다.

그래서 추적이 두 단계로 갈립니다. 첫째 단계인 끝점 정제기는 활성 점 전부를 대상으로 목표 시각
$`t_{\mathrm{tgt}}`$ 에서의 3D 위치를 반복 갱신하면서, 가시성과 **정적/동적 분류**를 함께 냅니다.
궤적 전체를 푸는 둘째 단계는 동적으로 분류된 점에만 돌아요.

각 점에는 출발 시각 $`t_{\mathrm{src}}`$ 가 붙습니다. 이번 창에서 처음 관측된 프레임 번호이거나,
앞 창에서 넘어온 점이면 $`-1`$ 이에요. 목표 시각은 추론 때와 학습 중간 창에서는 늘 창 경계
$`L{-}1`$ 이고, **학습의 마지막 창에서만** $`\{0,\dots,L{-}1\}`$ 에서 무작위로 뽑습니다. 임의 시각으로의
흐름을 가르치기 위한 장치입니다.

트랜스포머가 점이 어디서·언제 왔고 어디로·언제 가는지 알 수 있도록, 특징 $`\mathbf{f}_i`$ 에 네 개의
[사인파 임베딩](term:sinusoidal)을 더합니다.

세 가지를 냅니다 — 3D 잔차 $`\Delta\mathbf{x}`$, 가시성 로짓 $`v`$, 정적/동적 로짓 $`s`$. 목표 위치는
$`\mathbf{x}^{(k)}_{\mathrm{tgt}}=\mathbf{x}^{(k-1)}_{\mathrm{tgt}}+\Delta\mathbf{x}^{(k)}`$ 로 갱신되고, 갱신된 특징은 다음 모듈과 다음 창으로

점은 관측된 3D 위치에서, 앞 창에서 넘어온 점은 그 창의 출력에서 시작해요.

### 4D 상관 볼륨 대신, 출발과 현재 추정 두 자리의 특징 샘플링 | 3D WAFT · Template Matching · Visibility Cue

끝점 정제기의 입력은 특징 하나가 아니라 셋을 이어 붙인 것입니다. 매 트랜스포머 통과 전에 점마다
**현재 목표 위치 추정을 목표 프레임 $`t_{\mathrm{tgt}}`$ 의 카메라로 그 프레임의 2D 특징 지도에 투영**해 그
자리를 [쌍선형 샘플링](term:bilinear)한 목표 특징 $`\mathbf{g}_{\mathrm{tgt}}`$, 그리고 점이 **태어난 자리**에서 한 번만 샘플링해 두는
출발 특징 $`\mathbf{g}_{\mathrm{src}}`$ 를 구해 $`[\mathbf{f}_{i};\mathbf{g}_{\mathrm{src},i};\mathbf{g}_{\mathrm{tgt},i}]`$ 를 만듭니다.
이것이 [WAFT](term:waft) 를 3D 점 구름으로 옮긴 **3D WAFT** 예요.

```probe-term
{"id": "waft", "title": "WAFT — Warping-Alone Field Transforms",
 "body": "광류 — 두 프레임 사이 픽셀마다의 2D 이동 — 를 푸는 방법으로, 상관 볼륨을 만들지 않고 현재 추정한 대응 위치에서 특징을 워핑(샘플링)해 원래 특징과 나란히 셀프어텐션에 넣습니다. 이렇게 만든 특징만으로 대응 찾기가 충분하다는 것을 보였고, 이 논문은 투영 대상을 2D 픽셀에서 3D 점으로 바꿔 씁니다."}
```

두 특징을 함께 주면 모델이 받는 것은 사실상 **암묵적 템플릿 매칭 신호**입니다. 둘이 비슷하면 지금
추정이 맞을 가능성이 높고, 다르면 더 고쳐야 한다는 뜻이에요. 출발 특징을 같이 넣는 이유를 원문은
모델이 점의 원래 생김새를 **잊지 못하게** 하려는 것이라고 씁니다. 그리고 이 비교는 상관 볼륨처럼
모든 위치 쌍을 미리 깔아 두지 않습니다. 출발 특징은 점이 생길 때 한 번, 목표 특징은 반복마다 한 번 샘플링하면
끝이에요.

### 궤적 정제기는 서로를 보지 않는다 | Trajectory Refiner · Track Token · Track Independence

끝점 정제기가 목표 시각 위치와 정적/동적 로짓을 갱신하고 나면, 동적 점마다 창 길이 $`L`$ 의 궤적을
정제합니다. 첫 반복에서는 출발 위치와 목표 위치 사이 **등속 보간** — 점이 두 위치 사이를 같은 속도로 직선 이동했다고
가정하고 중간 시각의 위치를 채우는 것 — 으로 궤적을 초기화하고, 그 뒤에는
직전에 추정한 궤적을 쓰되 $`t_{\mathrm{tgt}}`$ 위치만 끝점 정제기가 고친 값으로 바꿉니다.

궤적의 각 시각에는 세 벡터를 이어 붙입니다 — 트랜스포머를 거친 점 특징, 출발 특징
$`\mathbf{g}_{\mathrm{src}}`$, 그리고 그 시각의 등속 추정 위치에서 2D 특징 지도를 쌍선형 샘플링한
특징. 여기에 트랙 전체의 요약 역할을 하는 [`[cls]` 토큰](term:cls)을 하나 덧붙여
$`(N_{\mathrm{dyn}}, L{+}1, D)`$ 모양의 트랙 특징이 됩니다.

디코더는 두 연산을 번갈아 쌓습니다. 하나는 **트랙 안의 시간 셀프어텐션**으로, 한 점의 시각별 토큰이
자기 궤적을 따라 정보를 주고받습니다. 다른 하나는 `[cls]` 토큰에서 **특징 구름 전체로의
교차어텐션**으로, 장면 맥락을 트랙에 다시 넣어 줘요. 마지막 층 뒤의 MLP 가 $`N_{\mathrm{dyn}}\cdot L`$ 개
토큰마다 3D 흐름 잔차와 가시성 로짓을 냅니다.

### 41M 학습 파라미터, 세 합성 데이터셋, 창마다 끊는 역전파 | Training Recipe · Gradient Accumulation · PointOdyssey Fixes

긴 시퀀스를 메모리 안에서 학습하는 방법이 부록 A.4 에 따로 적혀 있습니다. 창 사이로는 역전파하지
않으면서도, 2D 인코더(ViT Adapter)는 **영상 전체에서** 감독을 받게 만드는 장치예요. 2D 특징 지도를
시퀀스 전체에 대해 먼저 뽑아 기울기를 받는 분리된 잎 텐서로 감싸고, 창마다 손실과 역전파를 돌려
그 텐서의 기울기 버퍼에 누적한 뒤, 모든 창이 끝나면 백본 쪽으로 **한 번만** 역전파합니다.

```python 창 단위 역전파와 인코더 기울기 누적 — 원문 부록 A.4 의 서술을 단계로 옮긴 것
F = encoder(I)                              # 시퀀스 전체의 2D 특징 지도
F_param = F.detach().requires_grad_(True)   # 기울기를 받는 분리된 잎 텐서

state = None
for window in sliding_windows(F_param, P, L=16):   # 특징과 포인트맵을 같은 창으로
    out, state = tracker(window, state)
    loss = L_coord + l_vis * L_vis + l_dyn * L_dyn + l_conf * L_conf
    loss.backward()           # 추적기 모듈과 F_param.grad 에 누적
    state = state.detach()    # 창 경계에서 순환 상태를 끊는다 (BPTT 없음)

# 모든 창이 끝난 뒤 내적 <F_param.grad, F> 로 인코더에 한 번에 전파
(F_param.grad * F).sum().backward()
optimizer.step()
```

### 저자가 스스로 적은 네 가지 | Author-Stated Limits · Memory Growth · External Geometry · Irreversible Merge

§5 는 네 가지 한계를 적습니다. 그중 세 번째는 이 논문의 핵심 장치 — 창 경계 병합 — 를 직접 겨눕니다.

> [!WARNING] 저자들이 적은 한계 넷
> (1) 복셀 병합이 메모리 증가를 묶어도, 끝없이 탐험하는 영상에서는 **활성 메모리가 계속 자란다.**
> (2) **외부 기하에 의존**하므로 성능이 포인트맵 품질에 묶인다. (3) 병합이 **되돌릴 수 없는 평균
> 풀링**이라, 추적 오류가 서로 다른 표면을 영구히 한 트랙으로 접을 수 있다. (4) 모델 용량과 사전학습
> 데이터를 키우면 복잡한 실세계 동역학에서 더 얻을 여지가 있다.

::: details 네 한계의 원문 서술과 저자들이 제시한 다음 수 (원문 §5)

### 손가락은 복셀 몇 칸인가 | D7VC · D4ML · Egocentric Video · Irreversible Merge

것(D7VC)이 우리 결정입니다. 이 논문은 그 방향에 꽤 가까이 서 있어요. TAPVid-3D 전체 길이 평가의 세 데이터셋 중 이 논문이
