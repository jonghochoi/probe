### 카드를 밀어내는 엄지는 백본을 기다려주지 않는다 | Tactile Reactivity · Frequency Mismatch

카드 케이스에서 카드 한 장만 빼내는 동작을 생각해 봅시다(이 논문의 평가 과제 X). 엄지로 카드를
문질러 조금 밀어내고, 같이 딸려 나온 아래 카드는 도로 밀어 넣고, 위의 한 장만 뽑습니다. 사람에게는
아무것도 아니지만, 카드가 얼마나 밀렸는지·몇 장이 걸렸는지는 카메라보다 **손끝 감각**으로 먼저
드러나는 정보입니다(이 예시의 해석은 우리 것이고, 원문 서론은 카드를 슬롯에 밀어 넣기와 열쇠로
자물쇠 열기를 예로 듭니다). 이런 동작에 필요한 것을 원문은
**tactile-reactive behavior** 라고 부릅니다 — 촉각 신호에 대한 즉각적 폐루프 운동 반응이고, 기존
시각 기반 제어 루프가 허용하는 것보다 훨씬 빨라야 합니다.

원문은 [VLA](term:vla) 를 촉각 반응형으로 바꾸는 데 걸림돌이 **두 개**라고 정리합니다.

- **데이터.** 정책 사전학습용 촉각 데이터가 희소합니다. 그래서 지금의 대규모 사전학습 패러다임은
  거의 전부 시각 위주이고, 힘의 변화·미세 미끄러짐·국소 변형 같은 물리 신호가 통째로 빠져 있습니다.
  이걸 처음부터 배우려면 동기화된 시촉각 데이터가 엄청나게 필요한데, 정밀한 덱스터러스 원격조작을
  그 규모로 모으는 비용은 감당이 안 됩니다.
- **주파수 불일치.** 촉각 반응 제어는 고빈도 응답을 요구하는데, 표준 VLM 백본은 저빈도로 돕니다.
  이건 튜닝의 문제가 아니라 구조의 문제입니다.

기존 해법들이 어디서 멈추는지도 원문이 짚습니다. **dual-system** 계열(GR00T N1, Fast-in-Slow 등)은
느리게 생각하는 큰 모델과 빠르게 움직이는 작은 모델을 두 시스템으로 나눠, 빠른 운동 반응과 인지적
추론을 아예 **완전히 분리**해 버립니다. **가변 레이트 확산 정책**(RDP — 느린 계획과 빠른 촉각 반응을
서로 다른 주기로 돌리는 확산 정책)은 평행 그리퍼용 태스크별 모방학습에 머물러 있습니다. 어느 쪽도
덱스터러스(여러 손가락을 쓰는) 조작을 위한 **통합 파운데이션 모델**이 아니라는 것이 원문의 진단입니다.

### 전문가 셋으로 쪼갠 백본 — 잠재·행동·촉각 | Mixture-of-Transformers · Expert Split

정책 $`\pi_\theta`$ 가 받는 것은 RGB 관찰 $`\mathbf{o}_t`$, 언어 지시 $`\ell`$, 촉각 힘 이력

### τ = 0.4 에서 궤적을 자른다 | Cascaded Flow Matching · Asynchronous Refinement

이 논문의 핵심 장치입니다. 저빈도 시각운동 계획과 고빈도 촉각 정제를 합치기 위해, flow matching
궤적을 **고정된 시점** $`\tau_\mathrm{split}`$ 에서 자릅니다. 잘린 지점에서 위쪽 구간이 남긴
[KV 캐시](term:kv-cache)가 아래쪽 구간의 유일한 시각 정보원이 됩니다. 아래에서 **slow tick** 은 시각까지
보는 무거운 추론(청크당 한 번), **fast tick** 은 촉각 전문가만 도는 가벼운 추론(청크 안에서 여러 번)을
가리킵니다.

   {"sym": "\\mathcal{L}_\\mathrm{future}", "name": "미래 시각 잠재 예측", "note": "잠재 전문가의 보조 목적. 촉각 모달리티를 시각 맥락에 정렬시키는 역할"}]}

> [!NOTE] 행동 전문가를 전 구간에서 학습시키는 이유
> $`\mathcal{L}_\mathrm{act}`$ 의 $`\tau_\mathrm{act}`$ 는 $`[\tau_\mathrm{split},1]`$ 이 아니라
> $`(0,1]`$ **전체**에서 뽑힙니다. 원문의 근거는 두 가지 — 행동 전문가가 **혼자서도 행동을 생성할 수
> 있는 능력**을 유지하고, **사전학습 패러다임과의 일관성**을 지키기 위해서입니다. 공개 코드는 이를
> "촉각이 끊겨도 행동 전문가 혼자 돌 수 있게" 라고 적고, 학습 스텝의 10 % 에서 촉각 입력을 0 으로
> 지우는 드롭아웃까지 둡니다(원문에 없음). 추론 서버에는 `--disable_tactile` 스위치가 있어, 켜면 행동
> 전문가가 10 스텝을 혼자 다 풀고 fast tick 은 촉각 전문가를 부르지 않은 채 그 청크를 그대로 되돌려
> 줍니다. 코드는 이 경로를 "촉각 전문가 없는" 절제용 기준선이라 적습니다
> ([`test.py`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/scripts/test.py#L557-L582) · [L613-L620](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/scripts/test.py#L613-L620) ·
> [`modeling_vla.py`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/qwen_vla/modeling_vla.py#L567-L574)). 절제의 w/o Tactile 42 가 이 경로일
> 가능성이 높지만, 원문은 "촉각 입력 전부 제거"라고만 적어 그대로 확정되지는 않습니다.

원문 Algorithm 1 은 추론을 느린 루프와 빠른 루프 둘로 적고, 둘 사이의 동기화까지 명시합니다.

```pseudo Algorithm 1 — 비동기 촉각 반응형 캐스케이드 디노이징 (원문 부록 B)
 1: Require: pre-trained experts f_θ^act and f_θ^tac;
             total flow steps N, slow segment steps K_slow (K_fast = N − K_slow);
             step size Δτ = −1/N; boundary threshold τ_split = 1 − K_slow/N
             # 이 논문의 값: N = 10, K_slow = 6, K_fast = 4, τ_split = 0.4
 2: Ensure: executed actions A_{t:t+T_a} at corresponding execution offsets
 3:
    # 두 스트림이 주고받는 것은 아래 셋뿐
 4: Shared Memory: intermediate state x̂_τsplit, KV cache KV_τsplit, execution lock lock
 5:
 6: procedure SLOW-STREAM LOOP (LowFreq)        # 청크(T_a = 16 스텝)마다 한 번
 7:   for each action chunk window T_a do
 8:     Get vision-language context c^vl        # 무거운 시각 계산은 여기서만
 9:     Sample initial noise x_1 ~ N(0, I)
10:     # 상위 구간 적분 — 행동 전문가가 τ 를 1 → τ_split 로 내린다
11:     for k = 1 to K_slow do
12:       τ ← 1 − (k−1)/N
13:       v ← f_θ^act(x_τ, τ; c^vl)
14:       x_{τ+Δτ} ← x_τ + Δτ · v               # Euler 한 스텝
15:     end for
16:
        # 커밋이 끝날 때까지 fast tick 은 시작하지 못한다
17:     acquire lock
18:       x̂_τsplit ← x_τsplit                   # 반쯤 디노이징된 행동
          # 시각-언어 KV 에, τ_split 에서 다시 인코딩한 행동 위치를 잇는다
19:       Refresh and re-encode position cache:
20:       KV_τsplit ← [ KV^lat | KV^act_τsplit ]
21:     release lock
22:   end for
23: end procedure
    # 한 청크 안에서 네 번 — δ 는 학습 때 지연 증강이 뽑는 값과 같다
24: procedure FAST-STREAM LOOP (HighFreq)
25:   for offsets δ ∈ {0, 4, 8, 12} inside window do
26:     Sample real-time tactile stream c^tac   # 매 tick 새로 읽는 유일한 관찰
27:
28:     acquire lock                            # 락 안에서는 복사만 한다
29:       Clone context: kv ← clone(KV_τsplit)
30:       x ← x̂_τsplit
31:     release lock
32:     # 말단 구간 적분 — 촉각 전문가가 τ_split → 0 을 마저 내린다
33:     for k = 1 to K_fast do
34:       τ ← τ_split − (k−1)/N
          # 시각 타워·잠재 전문가·행동 전문가는 다시 돌지 않는다
35:       v ← f_θ^tac(x, τ; c^tac, kv)
36:       x ← x + Δτ · v
37:     end for
38:
39:     Â_{t+δ : t+δ+T_a} ← x                   # 오프셋 δ 부터의 청크를 교체
40:     Execute updated action chunk
41:   end for
42: end procedure
```

추론 설정은 [Euler 적분](term:euler) $`N{=}10`$ 스텝, $`\tau_\mathrm{split}{=}0.4`$ — 그래서 $`K_\mathrm{slow}{=}6`$,
$`K_\mathrm{fast}{=}4`$ 입니다. 17–21행과 28–31행의 락은 장식이 아닙니다. 실기 런타임은 **단일 스레드 request 소켓 +
명시적 실행 락**으로 두 스트림을 직렬화해, 진행 중인 slow tick 이 캐시와 경계 상태를 공유 메모리에
완전히 커밋하기 전에는 어떤 fast tick 도 시작하지 못하게 합니다(공개 추론 서버
[`test.py`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/scripts/test.py#L330-L353) 에서 확인). 그리고 두 스트림이 필연적으로
어긋나는 부분은 [지연 증강](term:delay-aug)으로 학습에 미리 넣습니다.

공개 코드는 Algorithm 1 과 한 군데가 다릅니다. 알고리즘은 정제된 청크로 남은 행동을 **바꿔 끼우는**
것처럼 적지만, 로봇 쪽 클라이언트의 기본 설정은 같은 시점을 덮는 청크들(정제 @0, @4, @8, @12)을
**평균**해 실행합니다([`default.yaml`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/config/default.yaml#L92-L94) ·
[`eval_trex_async.py`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/eval/eval_trex_async.py#L75-L96) · [L1080-L1086](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/eval/eval_trex_async.py#L1080-L1086)). 평균하면 뒤늦은
정제일수록 몫이 줄어 촉각 반응이 무뎌질 수 있는데, 논문 실험이 이 설정으로 돌았는지는 원문에 없습니다.

새로 배웁니다(공개 코드 기준 — 원문은 동결 여부를 적지 않음).

**공간 축 — 변형 맵 인코더.** 손끝마다 단일 채널 [변형 맵](term:deform-map)이 나옵니다. 힘 벡터로는

경량 CNN — 입력 스템을 단일 채널로 바꾸고 **잔차 스테이지 앞의 세 개만** 남기며, 원문에 따르면 각
스테이지 뒤에 $`3\times3`$ 합성곱을 붙여 중간 특징을 **128 채널**로 재투영합니다(공개 코드에는 두 곳에만
있음 — 아래 코드 확인 표). 이 인코더는 자기지도 합성곱 오토인코더(입력을 압축했다가 다시 복원하도록

  표현을 배우고, 행동 전문가는 **[리타게팅](term:retargeting)된 사람 팔·손 동작**을 통일된 행동

### 촉각을 빼면 23 포인트, 비동기를 빼면 5 포인트 | Ablations · Split Step

절제 실험은 대표 6 개 과제(Flip Page · Apply Toothpaste · Split Cup · Open Lock · Extract Card ·
Screw Lightbulb)에서 진행합니다.

| 설정 | 평균 | 차이 |
|---|---|---|
| **전체 모델** | **65** | — |
| w/o Tactile — 촉각 입력 전부 제거 | 42 | −23 |
| Deform — 변형 맵만 | 54 | −11 |
| MLP Force + Deform — VQ-VAE 를 MLP 로 교체 | 58 | −7 |
| MLP Force + VQ-VAE Force — 힘만, 변형 없음 | 59 | −6 |
| w/o Async — 동기 정제 | 60 | −5 |

읽는 순서가 중요합니다. **촉각 자체가 23 포인트**로 압도적이고, 그다음이 두 갈래를 나누는 문제입니다
— 힘 쪽을 통째로 빼면(변형 맵만, 54) 11 포인트, 변형 맵을 빼면(힘만, 59) 6 포인트, 힘의 VQ-VAE 시간
인코딩만 빼면(MLP Force + Deform, 58) 7 포인트가 빠집니다. 즉 힘 갈래를 통째로 뺀 손실(11)이 변형 맵을 뺀 손실(6)보다 크고, 힘 갈래 안에서 VQ-VAE 시간
인코딩만 MLP 로 낮춰도 변형 맵을 뺀 것과 비슷한 7 포인트가 빠집니다. 다만 6·7·11 포인트는 모두
6 과제 × 16 회 시행에서 나온 값이라, 순서를 매기기보다 **두 갈래가 다 필요하다**고 읽는 편이 안전합니다.

**비동기 정제의 5 포인트**는 이 논문의 이름이 붙은 장치가 벌어들인 몫입니다. 동기 baseline 대비
일관되게 개선되고, 저빈도 시각운동 계획과 고빈도 촉각 제어를 **분리한 것 자체**의 이득이라고
원문은 해석합니다.

가로축은 행동 전문가가 밟는 스텝 수 $`K_\mathrm{slow}`$ 이고, $`\tau_\mathrm{split}=1-K_\mathrm{slow}/10`$
이라 **스텝이 클수록 분할 시점은 작아집니다.** 세 과제 모두 $`K_\mathrm{slow}{=}6`$($`\tau_\mathrm{split}{=}0.4`$)
근처가 가장 높고 양쪽으로 내려가지만, 폭은 2~7 포인트입니다(컵 분리 71 → 78 → 73). 원문의 해석은 행동
전문가 몫이 너무 적으면 하위 정제에 줄 시각운동 사전 지식이 부족하고, 너무 많으면 촉각 전문가가 촉각
피드백을 반영할 여력이 남지 않는다는 것입니다.

> [!WARNING] 원문 문장의 방향이 뒤집혀 있다
> 원문 §5.3 은 이 해석을 "$`\tau_\mathrm{split}`$ 이 너무 **작으면** 행동 전문가의 사전 지식이 부족"
> 이라고 씁니다. 그런데 $`\tau_\mathrm{split}`$ 이 작다는 것은 행동 전문가가 궤적의 **더 많은** 부분을
> 맡는다는 뜻입니다. 그림의 가로축인 **분할 스텝** $`K_\mathrm{slow}`$ 로 읽어야 문장이 성립합니다.

> [!NOTE] 이 곡선이 말해 주는 것과 말해 주지 않는 것
> 분할 지점은 **어느 전문가가 궤적의 얼마를 소유하는가**를 정하는 값이라, 중간이 최적이라는 것은 두
> 전문가가 서로 다른 몫을 낸다는 신호입니다. 다만 측정 범위가 1~8 스텝이라 한쪽에 궤적 전부를 주는
> 극단(0 이나 10)은 시험하지 않았고, 차이도 수 포인트라 어느 해석을 **기각**할 만큼 크지는 않습니다.

## 4 연구축에 무엇이 걸리나

### 제어 레이트를 하나로 두기로 했다 | D3GS · D1MZ · Control-Rate Separation

여기부터는 논문이 아니라 **이 결정에 미치는 영향**입니다.

모달리티는 나누되 제어 레이트는 하나로 가기로 정해 뒀습니다 — **(ii) 모달리티 분리 +
(α) 공유 레이트**(P1 · D1MZ). T-Rex 는 그 조합의 **다른 쪽 칸**을 골라 5 포인트(w/o Async 60 → 65)를
벌었다고 보고합니다. 크지 않은 숫자지만, 문제는 크기가 아니라 **분할 축**입니다.

| Decision | 이 기본값 | 이 논문 | 판정 |
|---|---|---|---|
| **D3GS** 분할 형태 | (iii) 하이브리드 — 공유 트렁크 + body/hand 분리 헤드 | 파라미터는 전문가별, 어텐션은 공유하는 MoT 전문가 3 개, **행동 공간은 62 차원 단일** | 다른 축의 분할 |
| **D1MZ** 입력 모달리티 + 제어 레이트 분리 | 모달리티 분리 + **공유 레이트** | 모달리티 분리 + **가변 레이트**(청크당 1 : 4) | 반대 선택, 실측 근거 있음 |
| **D2DV** concat 을 넘는 융합 | 교차 어텐션 / 비대칭 융합 | 촉각 토큰 concat, 단 **전용 전문가**가 소비 | 다른 층위의 해법 |
| **D3AG** proprio-촉각-힘 토큰 구성 | 손가락별 결속, 교체 가능 센서 헤드 + 공통 토큰 포맷 | 손가락 공유 conv + **손가락 정체 임베딩**, 손가락당 이산 토큰 1 개 | 강한 수렴 |
| **D3RP · D3WV** 계보와 단계 레시피 | PaliGemma-2B × $`\pi_0`$, 백본 동결 + 행동 전문가만 | Qwen3VL-2B, 3 단계(에고 → 촉각 중간 → 태스크) | 병렬 사례 |

| **D9QJ** 사전학습 데이터 구성 (미결) | 에고 중심 + 표적 로봇 액션, "전부 섞기 대 에고 전용"은 미결 | 에고 전용 사전학습 + **촉각은 별도 중간학습으로 분리** | 직접 증거 |

> [!CAUTION] D1MZ — "공유 레이트"를 고른 이유가 이 논문에 의해 약해진다
> 공유 레이트의 매력은 단순함이었습니다. 가변 레이트를 하려면 두 스트림의 동기화, 낡은 캐시,
> 스레드 안전이 전부 따라오니까요. T-Rex 는 그 비용을 **실행 락 + delay augmentation** 두 개로
> 정리해 보였고, 5 포인트를 벌었습니다. 공유 레이트를 뒤집을 근거는 아니지만(D1MZ), **"복잡해서
> 안 한다"는 근거는 약해졌습니다** — 구현이 코드로 공개됐고, 그 서버는 락 하나로 직렬화한 단순한 형태입니다.

> [!CAUTION] D3GS — 해부학으로 자르고, 이 논문은 시간으로 자른다

> 않습니다.
> 다만 이 논문이 65 % 를 낸 접촉 과제들이 정확히 body/hand 분할로 잡으려던 영역이라는 점은

### System0 를 RL 없이 지나가는 길 | D5DQ · D6ZD · D4NT · D17 · Imitation vs RL

이 접촉 반응 서브루프는 **시각을 배제한 촉각 + 고유수용감각 기반 저수준 모듈**이고,

물건**입니다.

| 항목 | 이 System0 (기본값) | T-Rex 촉각 전문가 |
|---|---|---|
| 학습 방식 | PPO, Isaac Lab 8k–16k env, 접촉 보상 설계 | **모방학습만** — 시연에서 나온 flow 목표 회귀 |

### 촉각 전문가가 몇 Hz 로 도는지 논문은 말하지 않는다 | Verification Plan · Open Questions

> [!IMPORTANT] 읽은 것들 사이에서 이 논문의 자리
> 이 코퍼스의 실시간 축은 지금까지 **지연을 어떻게 견디느냐**였습니다 —
> FASTER([arXiv:2603.19199](https://arxiv.org/abs/2603.19199))는 청크 안의 완성 시점을 어긋나게
> 주고, $`\pi`$R²([arXiv:2607.26055](https://arxiv.org/abs/2607.26055))는 관찰을 느린 채널과
> 빠른 채널로 갈라 백본을 비동기로 뺍니다. T-Rex 는 **같은 비동기 분리를 디노이징 궤적 위에서**
> 하되, 빠른 채널을 고유수용감각이 아니라 **촉각**으로 채우고 거기에 전용 파라미터를 붙입니다.
> 촉각 표현 축의 TactX([arXiv:2606.31236](https://arxiv.org/abs/2606.31236))와 합쳐 보면, 이
> 스택에 필요한 조각 세 개(빠른 루프 · 촉각 표현 · 촉각 코퍼스)가 서로 다른 논문에 흩어져 있습니다.

#### 먼저 확인할 것

- **가장 싼 점검 — 촉각 전문가의 실제 Hz 가 얼마인가.** 이 논문은 **한 번도 정책 주파수를 숫자로
  말하지 않습니다.** 있는 것은 저수준 제어 300 Hz, 원격조작 상위 스레드 30 Hz, 그리고 "청크 16 안에서
  오프셋 4 마다" 뿐입니다. 공개 코드가 답의 절반을 줍니다 — 로봇 쪽 추론 클라이언트의 기본 설정은 명령
  루프 **30 Hz**, 청크 16 스텝 전부 실행, 정제 오프셋 4·8·12([`default.yaml`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/config/default.yaml#L52-L53) ·
  [L86-L91](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/config/default.yaml#L86-L91))이라 fast tick 은 명목상 **7.5 Hz**, slow tick 은
  약 **1.9 Hz** 입니다. 그런데 같은 저장소의 README 는 "느린 디노이징 약 5 Hz · 빠른 촉각 정제 약 20 Hz"라고
  적어 둘이 맞지 않고, 저장소 어디에도 그 숫자를 내는 설정은 없습니다. 게다가 클라이언트는 응답이 올 때까지 다음 스텝으로 넘어가지 않는 **하나의 순차
  루프**라([`eval_trex_async.py`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/hardware_code/eval/eval_trex_async.py#L1038-L1078)), 실제 주기는
  추론 지연만큼 더 깁니다. 7.5 Hz 는 πR² 가 정책 루프 안에서 닫은 25 Hz 힘 반응의 3 분의 1 에도 못 미칩니다. 공유
  레이트 선택을 다시 볼 때(D1MZ) 저자에게 **실측 주기**를 먼저 물어야 합니다.
- **비동기의 5 포인트가 어디서 왔는가.** 원문은 "동기 정제" baseline 이 정확히 무엇인지(같은
  체크포인트에서 오프셋 0 한 번만 정제하는지, 따로 학습한 모델인지) 정의하지 않고, 공개 코드에도
  해당 모드는 없습니다. 같은 촉각 입력을 쓴다고 가정하면 촉각의 23 포인트 중 18 은 **입력이 있다는
  사실**에서, 5 만 **청크 안 재정제**에서 오는 셈입니다. 공유 레이트를 뒤집을지 판단하려면(D1MZ) 이 5 가 지연에
  민감한 과제에서만 나오는지, 전 과제에 고르게 퍼지는지를 봐야 합니다 — 원문은 과제별 분해를
  주지 않습니다.
- **이 손가락 토큰과 이 논문의 토큰을 나란히 놓을 것(D3AG).** T-Rex 는 손가락당 이산 토큰 **1 개**
  입니다(코드북 64). 손가락 토큰을 훨씬 넓게 잡고 contact-binary / slip-binary 보조
  헤드까지 붙일 생각이었습니다. **64 개 코드로 접촉 상태를 표현하기에 충분한가**가 분리 측정
  대상이고, 이 논문은 코드북 크기 절제를 하지 않았습니다.
- **손가락 공유 conv + 정체 임베딩이 이 "교체 가능 센서 헤드"와 어떻게 만나는가(D3AG).**
  T-Rex 는 다섯 손가락이 합성곱 가중치를 공유하고 정체만 임베딩으로 주입합니다 — 적어둔
  "공통 토큰 포맷"과 발상이 같습니다. 다만 저자들의 동기는 이식성이 아니라 **파라미터 효율과
  손가락 수 확장성**입니다. 센서 종류가 바뀌었을 때도 성립하는지는 이 논문이 다루지 않습니다.
- **사전학습 데이터 구성에 넣을 데이터점(D9QJ).** "전부 섞은 덤프 대 에고 전용"을 미결로
  두고 있고, 에고 → 로봇 커리큘럼은 "보류하되 추적"으로 남겨 뒀습니다(D3WV). T-Rex 는 두 칸을 한
  번에 채웁니다 — **에고 전용 사전학습 + 별도 촉각 중간학습**으로 45 → 65. 같은 100 시간을 태스크
  특화로 쓰는 것보다 물체-원시 조합으로 쓰는 쪽이 낫다는 Fig. 6 의 결과와 묶으면, 그 미결 항목의
  축이 **"섞는가 나누는가"에서 "어느 단계에 넣는가"** 로 한 칸 옮겨갑니다.
- **접촉 모달리티 코퍼스가 하나 새로 생겼다(P0 · D1AL).** 100 시간 · 7,755 에피소드 · 손끝 10 개
  변형 맵 + 6 축 렌치는 최우선 플래그로 잡아 둔 바로 그 유형입니다. 공개분은 그중 **약 50 시간 ·
  5,400+ 궤적**(LeRobot v3.0, MIT)이고, 사전·중간학습 체크포인트와 후학습·추론 코드도 함께
  나왔습니다([`README.md`](https://github.com/ZhuoyangLiu2005/T-Rex/blob/ba4047c/README.md)). 허용 라이선스 기준도 통과합니다(D8SD). 남은 추적 대상은
  공개되지 않은 나머지 약 50 시간과 사전·중간학습 코퍼스입니다(저장소는 후자가 이번 공개에 포함되지
  않는다고 명시).

엎어놓은 마작패를 손끝으로 알아내야 하는 과제가 있습니다. 카메라에는 뒷면밖에 안 보이니, 무늬는

대한 반응이 시각 제어 루프보다 훨씬 빨라야 하는데, VLA 의 백본은 그 속도로 돌지 않습니다.

촉각을 그냥 입력에 이어 붙이면 되지 않을까요. 저자들이 그걸 실제로 재봤습니다. 잘 만들어진 VLA 에
열 손가락 힘/토크를 state 로 붙였더니 12 과제 평균이 17 에서 6 으로 **떨어졌습니다**. 신호를 준 게
아니라 방해를 준 셈이죠.

그래서 이 논문은 촉각을 입력이 아닌 자리에 놓습니다. 행동을 노이즈에서 뽑아내는 디노이징 궤적을
중간 지점에서 자르고, 위쪽 구간은 시각과 언어를 보는 큰 전문가가, 아래쪽 구간은 카메라 영상을 직접
보지 않고 위쪽이 남긴 시각 맥락 캐시만 참조하는 작은 촉각 전문가가 맡습니다.

실제 동작은 이렇습니다. 큰 전문가가 청크당 한 번 돌아 노이즈 제거를 60 % 쯤 진행한 행동과 시각 맥락
캐시를 공유 메모리에 올려두면, 작은 전문가는 그 지점에서 출발해 실시간 촉각만 새로 받아 나머지를 네 번
다시 풉니다. 무거운 시각 네트워크는 그동안 한 번도 다시 돌지 않습니다. 이 구조와 서버·로봇 코드는
공개돼 있고, 공개 설정에서는 명령 30 Hz 기준으로 정제가 7.5 Hz 꼴로 돕니다.

두 스트림이 어긋나는 것도 미리 계산에 넣었습니다. 빠른 쪽이 볼 촉각과 느린 쪽이 남긴 시각 캐시
사이의 시간차를 학습 중에 무작위로 흉내 내서, 배포될 때 겪을 어긋남과 같은 분포를 미리 겪게 합니다.

촉각을 읽는 방식도 두 갈래입니다. 손끝 힘의 최근 16 프레임은 손가락마다 이산 토큰 하나(코드 64 개 중 하나)로
눌러 담고, 손끝 패드가 눌린 모양은 따로 가벼운 CNN 이 읽습니다. 앞쪽은 시간이 어떻게 흘렀는지를,
뒤쪽은 무엇에 어떻게 닿았는지를 담당하는 셈이죠.

이걸 학습시킬 데이터는 새로 모았습니다. 특정 과제를 반복해 찍는 대신, 가정용 물체 207 개와 손동작
원시 22 개를 곱해 실현 가능한 502 개 조합을 골라 100 시간을 채웠습니다. 같은 100 시간을 과제 특화로
쓴 쪽보다 일반화도 제로샷 전이도 나았다고 보고합니다.

숫자는 꽤 큽니다. 12 개 접촉 과제에서 평균 65 %, 가장 강한 비교군이 35 % 입니다. 촉각을 통째로
빼면 42 로, 비동기 구조만 동기로 바꾸면 60 으로 내려갑니다.

저자들이 남겨둔 자리도 분명합니다. 정밀한 접촉 협응이 필요한 긴 과제는 원격조작으로 시연을 만드는
것 자체가 어려워 강화학습이나 온라인 정제가 필요하고, 센서 왜곡과 기기 간 캘리브레이션 드리프트,
