### 카드를 밀어내는 엄지는 백본을 기다려주지 않는다 | Tactile Reactivity · Frequency Mismatch

카드 지갑에서 카드 한 장만 빼내는 동작을 생각해 봅시다. 엄지로 카드 뭉치를 문질러 조금 밀어내고,
두 장이 같이 나오면 아래 것을 도로 밀어 넣고, 위의 한 장만 뽑습니다. 사람에게 이건 아무것도 아니지만
로봇 정책에게는 두 장이 같이 나왔다는 사실이 **손끝에만** 나타납니다. 논문의 표현으로는
**tactile-reactive behavior** — 촉각 신호에 대한 즉각적 폐루프 운동 반응이고 기존 시각 기반 제어
루프가 허용하는 것보다 훨씬 빨라야 합니다.

원문은 [VLA](term:vla) 를 촉각 반응형으로 바꾸는 데 걸림돌이 **두 개**라고 정리합니다.

- **데이터.** 정책 사전학습용 촉각 데이터가 희소합니다. 그래서 지금의 대규모 사전학습 패러다임은
  거의 전부 시각 위주이고 힘의 변화·미세 미끄러짐·국소 변형 같은 물리 신호가 통째로 빠져 있습니다.
  이걸 처음부터 배우려면 동기화된 시촉각 데이터가 엄청나게 필요한데, 정밀한 덱스터러스 원격조작을
  그 규모로 모으는 비용은 감당이 안 됩니다.
- **주파수 불일치.** 촉각 반응 제어는 고빈도 응답을 요구하는데 표준 VLM 백본은 저빈도로 돕니다.
  이건 튜닝의 문제가 아니라 구조의 문제입니다.

```text Algorithm 1 — 비동기 촉각 반응형 캐스케이드 디노이징 (원문 부록 B)
공유 메모리: 중간 상태 x̂_τsplit, KV 캐시 KV_τsplit, 실행 락 lock
τ_split = 1 − K_slow/N,  Δτ = −1/N,  K_fast = N − K_slow

procedure SLOW-STREAM LOOP (LowFreq)
  for each action chunk window T_a do
    시각-언어 컨텍스트 c^vl 획득
    초기 노이즈 x_1 ~ N(0, I) 샘플링
    ▷ 상위 구간 적분
    for k = 1 to K_slow do
      τ ← 1 − (k−1)/N
      v ← f_act(x_τ, τ; c^vl)
      x_{τ+Δτ} ← x_τ + Δτ · v
    end for
    acquire lock
      x̂_τsplit ← x_τsplit
      위치 캐시 갱신·재인코딩: KV_τsplit ← [ KV^lat | KV^act_τsplit ]
    release lock
  end for
end procedure

procedure FAST-STREAM LOOP (HighFreq)
  for offsets δ ∈ {0, 4, 8, 12} inside window do
    실시간 촉각 스트림 c^tac 샘플링
    acquire lock
      kv ← clone(KV_τsplit);  x ← x̂_τsplit
    release lock
    ▷ 말단 구간 적분
    for k = 1 to K_fast do
      τ ← τ_split − (k−1)/N
      v ← f_tac(x, τ; c^tac, kv)
      x ← x + Δτ · v
    end for
    Â_{t+δ : t+δ+T_a} ← x
    갱신된 행동 청크 실행
  end for
end procedure
```

$`K_\mathrm{fast}{=}4`$ 입니다. 락은 장식이 아닙니다. 실기 런타임은 **단일 스레드 request 소켓 +
명시적 실행 락**으로 두 스트림을 직렬화해, 진행 중인 slow tick 이 캐시와 경계 상태를 공유 메모리에

어긋나는 부분은 [지연 증강](term:delay-aug)으로 학습에 미리 넣습니다.

## 4 우리는 무엇을 하나

### 우리 D5 는 "공유 레이트"였다 | D1 · D5 · Control-Rate Separation

여기부터는 논문이 아니라 **우리 결정에 미치는 영향**입니다.

우리 P1 의 D5 v1 은 **(ii) 모달리티 분리 + (α) 공유 레이트** 입니다. 모달리티는 나누되 제어 레이트는
하나로 간다는 선택이었죠. T-Rex 는 그 조합의 **다른 쪽 칸**을 골라 5 포인트(w/o Async 60 → 65)를
벌었다고 보고합니다. 크지 않은 숫자지만 문제는 크기가 아니라 **분할 축**입니다.

| Decision | 우리 v1 | 이 논문 | 판정 |
|---|---|---|---|
| **D1** 분할 형태 | (iii) 하이브리드 — 공유 트렁크 + body/hand 분리 헤드 | 어텐션만 공유하는 MoT 전문가 3 개, **행동 공간은 62 차원 단일** | 다른 축의 분할 |

| **D10** concat 을 넘는 융합 | 교차 어텐션 / 비대칭 융합 | 촉각 토큰 concat, 단 **전용 전문가**가 소비 | 다른 층위의 해법 |

> 공유 레이트의 매력은 단순함이었습니다. 가변 레이트를 하려면 두 스트림의 동기화, 낡은 캐시,

### 촉각 전문가가 몇 Hz 로 도는지 논문은 말하지 않는다 | Verification Plan · Open Questions

> [!IMPORTANT] 우리가 읽은 것들 사이에서 이 논문의 자리
> 우리 코퍼스의 실시간 축은 지금까지 **지연을 어떻게 견디느냐**였습니다 —
> FASTER([arXiv:2603.19199](https://arxiv.org/abs/2603.19199))는 청크 안의 완성 시각을 어긋나게
> 주고 $`\pi`$R²([arXiv:2607.26055](https://arxiv.org/abs/2607.26055))는 관찰을 느린 채널과
> 빠른 채널로 갈라 백본을 비동기로 뺍니다. T-Rex 는 **같은 비동기 분리를 디노이징 궤적 위에서**
> 하되, 빠른 채널을 고유수용감각이 아니라 **촉각**으로 채우고 거기에 전용 파라미터를 붙입니다.
> 촉각 표현 축의 TactX([arXiv:2606.31236](https://arxiv.org/abs/2606.31236))와 합쳐 보면, 우리

  System0 에 기대하는 반응 속도와 한 자릿수 차이입니다. **논문이 모호한 지점**이고 우리 D5 를
  다시 볼 때 가장 먼저 저자에게 물어야 할 값입니다.
