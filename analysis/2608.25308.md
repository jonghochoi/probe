### VLM 을 아무리 좋게 만들어도 전달 구간은 그대로다 | Spatial Forcing · EVO-0 · VLA-Adapter

VLA 의 시각 인지를 끌어올리려는 시도는 이미 여러 갈래로 나와 있습니다. 다만 원문이 보기에 대부분은
**VLM 쪽 표현을 좋게 만드는 데 몰려** 있습니다. EVO-0 은 VGGT 의 3D 기하 특징을 VLM 에 직접
통합하고, Spatial Forcing 은 VGGT 특징으로 VLM 중간 임베딩을 증류해 추론 시점의 3D 파운데이션
모델 의존을 없앱니다. GEAR-VLA 와 SpatialVLA 는 학습 가능한 3D 공간 모듈을 넣고 VLM 표현에
정렬시킵니다.

원문의 반론은 한 문장입니다 — **VLM 표현이 풍부해졌다고 해서 전달 이후 행동 전문가가 같은 정보에
닿는다는 보장은 없다.** VLA-Adapter 처럼 VLM 과 Action DiT 사이의 효율적인 연결을 파는 연구도
있지만, 전달된 시각 표현이 행동 전문가 **안에서** 얼마나 접근 가능한지는 명시적으로 다루지
않는다는 것이고요.

행동 전문가 쪽을 직접 건드린 선행 연구가 없지는 않습니다. PointVLA 는 가벼운 모듈로 3D 포인트
클라우드 특징을 주입하고, ABot-M0 은 3D 파운데이션 모델의 특징을 그대로 넣습니다. 원문은 이들과의
차이를 **전달 과정 자체를 최적화하고 그 과정에서 일어나는 시각 표현 열화를 완화하는 것**으로
잡습니다.

### 헤드를 일부러 작게 만든다 — 2.3M | Depth Head · Softplus · Top-k Hard Patch

질의를 세워 놓기만 하면 그 안에 무엇이 들어갈지는 정해지지 않습니다. 그래서 학습 때만 붙는 과제
헤드가 각 질의를 특화시킵니다. 깊이 헤드 $`\Phi_{\rm Depth}`$ 는 공간 질의를 받아 여러 뷰의 밀집
깊이 맵을 내고, 출력에 [softplus](term:softplus) 를 걸어 미터 단위 깊이가 양수로 나오게 묶습니다.

```probe-eq

 "tex": "\\hat{\\mathbf{D}}=\\sigma_{+}(\\Phi_{\\rm Depth}(\\mathbf{E}^{\\prime}_{d})),\\quad \\hat{\\mathbf{D}}\\in\\mathbb{R}^{H\\times W\\times V}",
 "symbols": [{"sym": "\\sigma_{+}", "name": "softplus", "note": "log(1 + e^x). 예측 깊이를 양수로 제한합니다"},
             {"sym": "\\mathbf{E}^{\\prime}_{d}", "name": "공간 질의의 최종 층 출력", "note": "헤드의 유일한 입력 — 여기 없는 정보는 헤드가 만들어 낼 수 없습니다"},
             {"sym": "V", "name": "카메라 뷰 수", "note": "LIBERO 2, RoboTwin 3"}]}
```

```probe-term

 "body": "$`\\log(1+e^{x})`$ — 어디서나 양수인 매끄러운 활성화. ReLU 와 달리 0 에서 꺾이지 않아 회귀 출력에 쓰기 좋고, 여기서는 **미터 단위 절대 깊이가 음수로 나가지 않게** 막는 역할입니다."}
```

헤드 구조 자체는 평범합니다. 투영 층 $`\mathcal{P}_{d}`$ 는 `LN(2048)` → `Linear(2048, 256)` →
`GELU` → `Dropout`, 그 뒤에 뷰별 트랜스포머 인코더 층 두 개 $`\mathcal{T}_{d}`$, 마지막에 밀집
예측용 합성곱 디코더 $`\mathcal{C}_{d}`$. 중요한 건 **크기**입니다 — 약 2.3M 파라미터로, 원문이
말하듯 **의도적으로 가볍게** 잡았습니다.

> [!NOTE] 헤드가 작아야 정보가 질의 쪽에 남는다
> 깊이 헤드가 충분히 크면 질의가 부실해도 헤드 혼자 깊이를 만들어 낼 수 있고, 그러면 감독이
> 질의를 특화시키지 못합니다. 약 2.3M 이라는 크기는 성능 목표가 아니라 **정보가 어디에 저장될지를
> 정하는 설계 변수**입니다. §4 의 무작위 특징 대조군이 같은 논리의 사후 확인입니다.

깊이 손실은 세 항의 합입니다. 전역 절대 스케일을 잡는 smooth-$`L_{1}`$, 근거리 물체와 로봇 팔과
조작 영역을 강조해 먼 배경이 최적화를 지배하지 못하게 막는 절대-상대 손실, 그리고 국소적으로 어려운
영역을 골라 오는 top-$`k`$ 하드 패치 손실 — 쉬운 배경 픽셀이 많아 기울기가 희석되는 것을 막기
위한 항입니다.

```probe-eq
 "tex": "\\mathcal{L}_{depth}=\\mathcal{L}_{\\rm sm}+\\lambda^{d}_{1}\\mathcal{L}_{\\rm rel}+\\lambda^{d}_{2}\\mathcal{L}_{\\rm patch}",
```

의미 헤드 $`\Phi_{\rm Seg}`$ 는 **구조가 같고** 입력 질의, 출력 차원, 활성화 함수만 다릅니다.
softplus 대신 softmax 를 걸어 $`H\times W\times C\times V`$ 짜리 의미 분할 로짓을 냅니다. 손실은
픽셀별 클래스 감독인 교차 엔트로피에, 영역 겹침을 직접 최적화하고 배경 지배와 클래스 불균형의
편향을 완화하는 [soft dice 손실](term:dice)을 0.5 가중치로 더한 것입니다.

:::

하이퍼파라미터로 워밍업합니다. 그 뒤 학습 가능한 모든 부품을 함께 최적화하고요. 추론 시점에는 보조
헤드가 제거되고 깊이·분할 어노테이션도 필요 없습니다.

### 의미는 나란히, 기하는 그다음 | Parallel Cross-Attention · Learnable Gate · Mandatory Geometry Branch

여기가 이 논문의 설계 중심입니다. 진단 결과가 **의미는 거칠게나마 남고 기하는 거의 없다**였으므로,
처방도 두 정보를 똑같이 취급하지 않습니다.

로봇 상태 $`\mathbf{s}`$ 와 노이즈 행동 $`\mathbf{x}_{t}`$ 가 각각의 인코더를 거쳐 Action DiT 의
입력 토큰 $`\mathbf{H}_{0}`$ 가 되고, 층 $`l`$ 에서 $`\mathbf{H}_{l}`$ 은 **두 개의 병렬
교차어텐션**의 질의가 됩니다 — 하나는 VLM 이미지 토큰을, 다른 하나는 의미 질의를 키와 값으로
씁니다. 둘의 출력은 이어 붙여 $`\mathrm{Fuse}`$ 로 투영되고, 잔차로 더해집니다 — 이때 의미 쪽 항에만
층별 [학습 가능 게이트](term:gate)가 곱해집니다.

### 감독만도 주입만도 2 점 남짓, 둘이 함께라야 18.8 점 | Task Supervision × Query Injection

### 얼려서 다시 재 본다 — 무작위 특징이 바닥을 잡아 준다 | Frozen Probing · Random Feature Control · t-SNE

성공률만으로는 "표현이 실제로 복원됐는가"에 답할 수 없으니, 저자들은 §1 의 진단 프로토콜을 다시
돌립니다. 각 표현을 얼리고 동일한 가벼운 헤드를 깊이와 분할에 대해 학습시키는 방식이고, 이번에는

결과의 방향은 셋입니다. 무작위 특징에서는 성능이 나쁘고 — 즉 진단 수치가 헤드의 용량이 아니라
얼린 특징에 담긴 정보를 반영한다는 확인입니다. 공간 질의가 깊이 MAE 최저, 의미 질의가 분할 mIoU

### 우리가 "평면 concat 을 넘어" 라고 쓴 자리는 관찰 입구뿐이었다 | D10 · D8 · Transfer Interface

우리 관찰 융합 결정은 시각·고유수용감각·촉각·힘을 평면 concat 대신 **교차 어텐션 기반 비대칭
융합**으로 묶는다는 것이고(D10), 멀티카메라 쪽은 기하 기반 인코더로 **통합 3D 일관 임베딩**을

혹은 들어가는 순간입니다.

이 논문이 재 놓은 것은 그 입구 이야기가 아닙니다. 입구에서 아무리 잘 묶어도, 그 표현이 **행동

### 동결이 기본값인 우리와, LoRA 가 전제인 이 방법 | D19 · D20 · Rank-128 LoRA

이 논문은 사전학습 언어·비전 백본을 얼리되 VLM 을 **rank-128 LoRA** 로 적응시킵니다. 질의 토큰이
VLM 입력 시퀀스 안에 살고, 인과 마스크로 어텐션 패턴까지 바꾸기 때문에 VLM 쪽에 학습 여지가 필요한
구조입니다. 워밍업 단계에서도 학습되는 것이 LoRA · 두 질의 · 과제 헤드 셋이고요.

> LoRA 가 필수인지 편의인지 이 논문만으로는 판정이 안 됩니다. 우리 쪽에서 재 볼 값이 하나 늘어난
