# 격자 칸을 골라 버리지 말고 칸 사이를 찍어 읽으면, 시각 토큰 16 개로도 정책은 덜 흔들린다

## 1 무엇이 문제인가

### 256 개 시각 토큰 중 대부분은 배경을 실어 나른다 | Token Budget · Quadratic Attention · Inference Cost

[VLA](term:vla) 는 시각 인코더가 만든 토큰을 언어 · 행동 토큰과 이어 붙여 하나의 트랜스포머에 넣습니다.
이 논문이 문제 삼는 것은 그 시각 쪽 토큰 수입니다. DINOv2 를 예로 들면 이미지 한 장이 $`16\times 16=256`$
개 패치 토큰이 되고, 뒤따르는 트랜스포머의 계산량은 시퀀스 길이에 대해 **제곱으로** 늘어납니다(§1, §3.1).
저자들의 관찰은 그 256 개 중 **대부분이 과제와 무관한 배경**이라는 것입니다 — 정작 중요한 말단 장치(집게)와 물체가
배경과 같은 우선순위로 처리됩니다(§2.1).

### 칸을 골라 남기는 한, 집을 자리는 두 칸 사이에 걸린다 | Discrete Selection · Quantization Error · Training-free Pruning

토큰을 줄이는 기존 연구를 저자들은 두 갈래로 나눕니다(§1, §2.2).

- **의미 기반 프루닝** — 교차 모달 어텐션으로 중요한 토큰을 고릅니다(SparseVLM 등). 눈에 띄는 물체
  몸통은 잘 남기지만, **모서리나 접촉점처럼 기하적으로는 결정적인데 의미적으로는 밋밋한 영역**을
  버리는 경향이 있습니다.
- **동적 프루닝** — 이미지마다 남기는 토큰 수를 바꿉니다(EfficientVLA · VLA-Cache 등). 대부분
  [학습 없는 프루닝](term:training-free)이라, 이미 학습된 정책에서 끌어낸 정적인 규칙으로 움직이고
  과제 요구에 맞춰지지 않습니다. EfficientVLA 는 배경 패치를 버리고 남은 길이가 이미지마다 달라
  하드웨어 처리량이 떨어지고, VLA-Cache 는 고정 격자 위의 이산적 갱신 임계값에 기댑니다.

(1) 전역 좌표 예측, (2) 기하 정보를 주입한 격자 샘플링 — 이고, Figure 3 이 그 전체입니다.

그 위에 가벼운 MLP 가 **정수 격자 인덱스가 아닌 연속 좌표**를 냅니다 — $`P=\sigma(\mathrm{MLP}(z))`$,

그렇게 만든 희소 시각 토큰 $`T_{spa}`$ 가 언어 · 행동 토큰과 이어 붙어 트랜스포머로 갑니다.

### 네 이웃의 가중합이 좌표까지 미분을 흘린다 | Differentiable Bilinear Sampling · Sub-patch Feature · Gradient Flow

이 논문이 핵심 혁신이라 부르는 곳입니다(§3.3). 예측한 좌표 $`P(x,y)`$ 는 대개 격자 중심과 맞지 않습니다.
GridS 는 그 자리의 특징을 **주변 네 칸의 가중합**으로 정의합니다 — [이중선형 보간](term:bilinear)입니다.

왼쪽 위 이웃을 $`P_{1}=(\lfloor x\rfloor,\lfloor y\rfloor)`$ 로 두고 소수부를 $`\Delta_{x}=x-x_{i}`$,
$`\Delta_{y}=y-y_{i}`$ 라 하면, 네 이웃의 가중치는 다음과 같습니다.

```math
\begin{aligned}
\omega_{1}&=(1-\Delta_{x})(1-\Delta_{y}), &\qquad \omega_{2}&=\Delta_{x}(1-\Delta_{y}),\\
\omega_{3}&=(1-\Delta_{x})\Delta_{y}, &\qquad \omega_{4}&=\Delta_{x}\Delta_{y}
\end{aligned}
```

어느 한쪽 칸을 골라야 합니다(§3.3).

그래서 좌표를 내는 MLP 는 사람이 정한 규칙이 아니라, **행동 예측 오차를 줄이는 쪽으로 샘플링 점을 옮기도록**
하류 과제가 직접 학습시킨 함수가 됩니다(§3.3). 원문은 MLP 와 좌표 인코더의 구조를 적지 않는데, 공개 코드에
모듈 전체가 몇 줄로 있습니다. 아래는 SmolVLA 쪽 PyTorch 구현에서 순전파만 옮긴 것입니다.

```python 공개 코드의 GridS 순전파 — 평균 → 좌표 → 보간 → 위치 임베딩 (lerobot/src/lerobot/policies/active_token_sampler.py)
class ActiveTokenSampler(nn.Module):
    def __init__(self, vision_dim, num_tokens=16, embed_coords=True):
        super().__init__()
        self.num_tokens = num_tokens
        self.scout_mlp = nn.Sequential(                 # 좌표 예측기: C → 512 → 2K
            nn.Linear(vision_dim, 512), nn.ReLU(),
            nn.Linear(512, num_tokens * 2), nn.Sigmoid())
        self.coord_encoder = nn.Sequential(             # 좌표 인코더: 2 → 256 → C
            nn.Linear(2, 256), nn.ReLU(),
            nn.Linear(256, vision_dim))

    def forward(self, feature_map):                     # (B, C, H, W)
        B, C, H, W = feature_map.shape
        global_feat = feature_map.mean(dim=(2, 3))      # 식 (1): 전역 평균 풀링
        pred_coords = self.scout_mlp(global_feat).view(B, self.num_tokens, 2)
        grid_coords = pred_coords * 2.0 - 1.0           # [0, 1] → grid_sample 의 [-1, 1]
        sampled = F.grid_sample(feature_map, grid_coords.unsqueeze(1),
                                align_corners=False, mode="bilinear"
                                ).squeeze(2).transpose(1, 2)   # 식 (2)–(3): (B, K, C)
        return sampled + self.coord_encoder(pred_coords)       # T_spa = F_spa + E_pos
```

좌표 예측기는 은닉 512 의 2 층 MLP, 좌표 인코더는 은닉 256 의 2 층 MLP 입니다. 예측기의 입력은 정말
`global_feat` 하나뿐이어서, 지시나 상태가 좌표에 들어가지 않는다는 앞의 읽기가 코드로도 맞습니다.

`mode="bilinear"` 를 `"nearest"` 로 바꾸면 샘플링 경로로는 좌표에 기울기가 흐르지 않고, 좌표 인코더를
거치는 길만 남습니다. 부록 H 의 최근접 샘플링 절제(−4.1%)가 끊는 것이 이 경로이고, 원문은 그 원인을
"반올림이 기울기 흐름을 끊는다" 고 적습니다. 공개 코드(`openpi/src/openpi/models/grid.py`)의
`grid_sample_nearest` 가 그 변형으로, `jnp.round` 로 정수 칸을 고릅니다.

### 추론 때 붙이는 가위가 아니라, 파인튜닝 안에 들어가는 층이다 | Joint Optimization · Task Loss Only · Training Recipe

GridS 의 또 한 축은 **언제 붙이느냐**입니다. 기존 프루닝은 학습이 끝난 뒤 추론 시점에 적용됩니다. 저자들은
이 '학습 없음' 이 장점이 아니라, 선택이 미분 불가능해서 어쩔 수 없이 택한 타협이고 그 탓에 성능이 깎인다고
봅니다(§3.4). GridS 는 인코더와 트랜스포머 사이에 들어가 VLA 의 **표준 파인튜닝과 함께** 최적화되고,
보조 감독도 정답 어텐션 지도도 없이 **주 과제 손실 하나**로 끝까지 학습됩니다. 그래서 자기회귀형과
[플로우 매칭](term:flow-matching)형 VLA 모두에 그대로 붙습니다.

### 시점이 흔들리면 이기고, 초기 자세와 지시가 흔들리면 진다 | Viewpoint Loss · LIBERO-PLUS · RoboTwin

강건성 실험들이 부록 D 와 E 에 있습니다. 그중 부록 E 의 LIBERO-PLUS 와 RoboTwin 은 리뷰 의견을 받아 추가한
것입니다(§1).

**시점 상실**(부록 D). 정면과 손목 두 카메라로 학습한 뒤 **손목 카메라만으로** 평가합니다. 빠진 정면
시점은 해당 토큰을 가리거나(마스킹) 검은 이미지로 바꿉니다.

| 빠진 시점 처리 | 스위트 | 기준선 | GridS (K=16) |
|---|---|---|---|
| 토큰 마스킹 | Spatial / Object / Goal / Long | 0.66 / 0.88 / 0.76 / 0.30 | 0.92 / 0.92 / 0.94 / 0.70 |
| 검은 이미지 | Spatial / Object / Goal / Long | 0.62 / 0.84 / 0.62 / 0.18 | 0.82 / 0.92 / 0.68 / 0.44 |

원문 Table 6. 기준선은 정면 시점이 사라지면 Spatial 과 Long 에서 크게 무너지고(검은 이미지 Long 0.18),
GridS 는 모든 스위트에서 높게 유지됩니다. 저자들은 GridS 의 능동 샘플링이 손목 시점 토큰에서 물체 기하와
상호작용 지점을 직접 뽑도록 학습되어 특정 시점에 덜 의존하게 된다고 해석합니다.

같은 손목 전용 조건에서 K 를 바꾸면(Table 7) 곡선이 매끄럽지 않습니다. K = 1 은 실패하고(Spatial 15.2,
Long 0.8), K = 4 에서 크게 솟고(79.2 / 90.2 / 63.0 / 53.2), K = 6 · 8 · 10 에서 다시 무너졌다가(K = 10 의
Object 25.0), K ≥ 12 에서 회복합니다. 저자들은 원인을 **열린 질문**으로 남기고 가설 둘만 적습니다. 하나는
4 · 16 · 32 처럼 대칭 배치가 쉬운 수에서 좌표 최적화가 잘 된다는 것이고, 다른 하나는 손목 시야에서 K = 4 가
집게 두 끝과 목표 두 점에 딱 맞는다는 것입니다.

같은 조건이어야 할 두 표의 K = 16 값은 어긋납니다. Table 6 의 검은 이미지 GridS 는 0.82 / 0.92 / 0.68 / 0.44,
Table 7 의 K = 16 은 80.6 / 84.8 / 68.0 / 50.8 입니다. Table 7 의 캡션은 '정면 시점 마스킹', 본문은 '검은
이미지' 라고 적어 조건 표기도 엇갈립니다.

### 토큰 하나로 96.6% — 저자들이 '정보 병목' 으로 읽는 것 | K=1 · Information Retention · Bottleneck

가장 극단의 실험은 부록 G 입니다. $`\pi_{0.5}`$ 위에서 시각 토큰을 **단 하나**(K = 1)로 줄입니다. K 가 이미지마다의 수이므로(Figure 1), 카메라 두 대에서는
모두 두 개로 읽힙니다.

### 저자들이 적은 세 가지 한계 | Limitations · Static Budget · PEFT Compatibility

부록 J 는 "두 가지 주된 한계" 라고 시작하지만 실제로는 셋을 적습니다.

> [!WARNING] 저자 명시 한계 ① — 단일 배치 실속도
> 연산이 크게 줄어도 배치 1 의 벽시계 가속은 약 1.2 배이고, 최대 이득은 큰 배치에서만 나옵니다(부록 J).

> [!WARNING] 저자 명시 한계 ② — 고정된 토큰 수
> K 는 모든 과제에 미리 정한 값이고, 장면 복잡도에 맞춰 바꾸지 못합니다. K 를 늘리면 오히려 나빠지는 뒤집힌 U 자가 그 비용을 보여 줍니다(부록 J).

> [!WARNING] 저자 명시 한계 ③ — LoRA 와 맞지 않는다
> 전체 파인튜닝 대신 LoRA 로 붙이면 GridS 가 조밀 기준선보다 8.3% 낮습니다(부록 J).

::: details 세 한계에 대한 원문의 설명 (부록 J)
1. **단일 배치 실속도.** 조밀 기준선이 JAX 컴파일로 이미 최적화되어 있어, 순차적인 단일 배치 실행에서는
   병목이 계산에서 고정 커널 오버헤드로 옮겨 갑니다. 그래서 GridS 의 효율은 현재 높은 처리량 · 큰 배치
   설정에서 주로 실현됩니다.
2. **고정된 K.** 토큰 수를 실시간 장면 복잡도에 맞춰 조절하지 못하며, 프레임마다 최적 K 를 예측하도록
   구조를 넓히는 것을 중요한 후속 과제로 듭니다.
3. **[PEFT](term:peft) 호환성.** 저자들의 가설은 표현 불일치입니다. GridS 는 시각 토큰의 공간 분포 자체를

   못한다는 것입니다.

## 4 연구축에 무엇이 걸리나

### 전체 파인튜닝을 전제로 한 압축 — 얼린 백본 결정과 정면으로 만난다 | D3RP · D3WV · D1WE

이 논문은 관찰 쪽(P2) 모듈이지만, 우리 결정 로그에 견주어 보면 가장 세게 닿는 곳은 **어디까지 학습시키느냐**(P4)인
것 같아요. 원문은 GridS 를 전체 파인튜닝에 붙인다고 쓰고, 저자들 스스로 LoRA 로 학습 범위를 좁히면 무너진다고
적었기 때문입니다.

> [!CAUTION] D3RP — 얼린 VLM 위에서는 이 모듈이 서지 못할 수 있다
> 우리는 PaliGemma × $`\pi_{0}`$ 계보를 쓰되 VLM 을 통째로 얼리고 행동 전문가만 학습하기로 했습니다(D3RP).
> GridS 는 VLM 이 받는 시각 토큰의 구조 자체를 바꾸고, LoRA 만 허용해도 기준선보다 8.3% 낮습니다. 완전히
> 얼리면 그보다 자유도가 더 적습니다.

여기서 나오는 질문은 둘입니다. 첫째, 얼린 VLM 아래에서 GridS 를 붙이면 얼마나 잃는가 — 원문은 LoRA 까지만
쟀으므로 이 칸은 비어 있습니다. 다만 공개 코드에 단서가 하나 있습니다. 실기 기준선 SmolVLA 의 기본 설정
(`configuration_smolvla.py`)은 `freeze_vision_encoder=True` · `train_expert_only=True` 로 VLM 을 통째로 얼리고
행동 전문가와 GridS 샘플러만 학습합니다. 실기 실험이 이 기본값으로 돌았다면 Table 3 의 61.9% 는 우리와 같은
얼린 VLM 조건에서 나온 숫자인데, 원문은 실기의 학습 범위를 적지 않아 아직 단정할 수 없습니다. 둘째, 그 손실이 VLM 의 재적응 문제라면, 찍어 낸 토큰을 VLM 을 거치지 않고
**행동 전문가에만** 따로 넣는 배치로는 피할 수 있는지입니다. 우리 구조에서 학습되는 쪽은 행동 전문가뿐이므로,
GridS 의 자리를 VLM 입력이 아니라 행동 전문가의 시각 조건 쪽으로 옮겨 보는 것이 우리 제약 안에서 이 장치를
시험하는 가장 직접적인 방법인 것 같습니다.

> [!CAUTION] D3WV — 입력 구조를 바꾸는 일은 마지막 단계에 둘 수 없다
> 우리 학습 순서는 계보 선택 → 조합된 데이터로 추가 사전학습 → VLM 을 안정시킨 채 몸통 · 손 전문가 학습 →
> 보수적 배포 적응입니다(D3WV). GridS 는 '어차피 하는 하류 파인튜닝' 에 끼운다는 전제인데, 그 자리가
> 우리에게는 가장 보수적이어야 할 마지막 단계입니다.

우리 순서에서 GridS 를 쓰려면 시각 토큰 구조가 바뀌는 시점을 앞당겨야 할 것 같아요 — 추가 사전학습 단계부터
희소 토큰으로 학습해 VLM 이 처음부터 그 구조에 익숙해지게 하는 쪽입니다. Table 4 의 이득은 스텝당 3 배
안팎의 가속이라, 스텝을 가장 많이 쓰는 단계에서 절감도 가장 커집니다 — 그래서 비용 쪽에서는 오히려 그 단계가
GridS 의 가장 좋은 자리일 수 있습니다. 행동 표현 쪽은 걸리는 것이 없습니다. GridS 는 플로우 매칭 행동
머리를 건드리지 않고 $`\pi_{0}`$ · $`\pi_{0.5}`$ 위에서 그대로 동작하므로 연속 플로우 매칭 머리를 쓰기로 한
결정(D1WE)과는 충돌하지 않습니다.

### 2D 좌표 몇 개로 고르는 관찰 — 정합과 접촉은 어디에 남나 | D8EJ · D9NB · D3AG · D2DV

> [!CAUTION] D8EJ — 시점마다 2D 로 찍고, 시점 사이는 묶지 않는다
> 우리는 다중 카메라를 기하 접지된 3D 일관 임베딩으로 묶기로 했습니다(D8EJ). GridS 의 좌표는 이미지 평면의
> 2D 점이고, 좌표 인코더도 그 2D 위치만 싣습니다. 시점 사이의 정합은 다루지 않습니다.

그런데 강건성 결과는 우리가 3D 접지로 얻으려던 것과 같은 방향을 가리킵니다. LIBERO-PLUS 의 카메라 시점
교란에서 Spatial 은 기준선 67.0 대 GridS 86.4 이고, 정면 시점을 아예 뺀 조건에서도 기준선보다 훨씬 덜
무너집니다. 3D
정합 없이 **배경을 덜 보는 것만으로** 시점 강건성의 상당 부분이 나온다면, D8EJ 의 이득을 잴 때 GridS 같은
토큰 축소를 대조군에 넣어야 3D 접지 자체의 몫을 가를 수 있을 것 같습니다. 역으로 3D 일관 임베딩 위에서
점을 찍는다면 좌표를 2D 가 아니라 공유 3D 공간에서 예측하는 형태가 자연스러운 다음 단계로 보입니다.

> [!CAUTION] D9NB — 범용 인코더 뒤에서 행동 손실로 고른다
> 우리는 범용 SigLIP · ImageNet 스템보다 행동 · 동역학을 아는 인코더를 선호합니다(D9NB). GridS 는 인코더를
> 바꾸지 않고, 범용 인코더가 만든 조밀 격자에서 **어디를 읽을지**만 행동 손실로 배웁니다.

GridS 의 이 방식은 D9NB 에 대한 찬반 증거가 아니라 그 옆의 **값싼 보완**인 것 같아요. 인코더 비교가 없으므로 동역학 인지
인코더가 GridS 와 겹치는 일을 하는지, 서로 더해지는지는 이 논문으로 알 수 없습니다. 다만 얼린 SAM 으로 좌표를
이끌었을 때 6.2% 떨어졌다는 결과(부록 H)는 우리 쪽에도 의미가 있어 보입니다 — 범용 시각 사전이 '어디를 볼지'
를 정하면 행동이 원하는 자리와 어긋난다는 관찰이고, 이는 시각 표현을 행동에 묶어야 한다는 D9NB 의 동기와
같은 방향입니다.

> [!CAUTION] D3AG — '접촉점을 지킨다' 는 주장은 접촉으로 재지 않았다
> 우리 손가락 토큰 설계의 두 번째 조건은 접촉에 관련된 특징을 잃지 않는 것입니다(D3AG). GridS 는 접촉점 같은
> 서브패치 세부를 지킨다는 것을 출발점으로 삼지만, 원문의 근거는 성공률과 보존 지도이고 접촉 구간에서 점이
> 어디에 찍혔는지는 재지 않았습니다.

우리 손에서 이 질문은 더 날카로워집니다. 집게 하나인 SO-100 과 달리 다지 손은 손가락이 물체를 가리는
장면이 많고, 접촉은 손끝 몇 mm 에서 일어납니다. 로봇 초기 상태 교란에서 GridS 가 일관되게 진다는
결과(−8.8 ~ −14.0%p)를 저자들이 "팔의 운동학적 윤곽을 뭉갠다" 로 읽은 것도 같은 걱정을 키웁니다 —
몸의 형상이 중요한 장면에서 토큰 축소가 불리하다면, 손가락 스물두 관절의 자세가 중요한 우리 장면은 더
그럴 수 있습니다.

융합 쪽에서는 계산 하나가 달라집니다. 우리는 시각 · 고유수용 · 촉각 · 힘을 평면 연결이 아니라
교차 어텐션으로 묶기로 했고(D2DV), 손 쪽에는 손가락 10 개와 손바닥 2 개 토큰을 두기로 했습니다(D3AG). GridS 자체는 희소 토큰을 언어

손 토큰이 시퀀스에서 차지하는 몫이 완전히 달라집니다. 이 코퍼스의 AT-VLA([arXiv:2605.07308](https://arxiv.org/abs/2605.07308)) · DeCAL([arXiv:2609.09119](https://arxiv.org/abs/2609.09119)) 이 촉각 토큰을 그냥

재지 않았습니다.

### 무엇을 기준으로 점을 찍는가 — 검증 계획과 코퍼스 지도 | Verification Plan · Corpus Map

GridS 를 우리 쪽으로 가져올 때 순서대로 확인할 것은 셋인 것 같아요.

1. **얼린 VLM 아래의 비용.** VLM 을 얼리고 행동 전문가만 학습하는 조건(D3RP)에서 GridS16 을 붙였을 때의
   손실을 잽니다. 손실이 크면, 희소 토큰을 VLM 입력이 아니라 행동 전문가의 시각 조건으로만 넣는 배치를
   같은 조건에서 맞댑니다. 원문에 LoRA 결과(−8.3%)가 있으므로 그 사이 어디쯤일지가 첫 기준입니다. 그 전에
   공개 코드의 SmolVLA 기본값(VLM 동결)으로 실기 결과가 재현되는지를 먼저 보면, 이 질문의 절반은 남이 이미
   잰 셈이 됩니다.
2. **접촉 구간에서 점이 어디에 찍히는가.** 원문의 보존 지도 계산(부록 I)은 그대로 가져올 수 있으니, 다지 손
   시연에서 손끝이 물체에 닿는 프레임만 골라 K 개 점이 손끝 · 접촉 영역에 얼마나 붙는지를 셉니다. 접촉 직전에
   점이 손끝을 떠난다면 '접촉점을 지킨다' 는 주장이 우리 손에서는 성립하지 않는 것이고, 촉각 토큰(D3AG)이
   그 빈자리를 메워야 합니다.
3. **좌표를 무엇이 정하는가.** GridS 의 좌표는 평균 특징 하나에서 나오고 지시도 상태도 보지 않습니다.
   LIBERO-PLUS 의 언어 지시 교란에서 일관되게 지는 결과(−6.6 ~ −12.0%p)가 이 구조와 관련이 있을 것 같은데,
   원문은 좌표 예측기에 지시나 상태를 넣은 변형을 시험하지 않았습니다. 우리 구조에서는 몸통 행동이 손
   머리를 조건화하므로(D9ZP), 손 쪽 시각 토큰의 좌표를 몸통 행동으로 조건화하는 것이 자연스러운 변형입니다.

> [!IMPORTANT] 코퍼스 지도 — 볼 곳을 무엇으로 정하는가
> 이 코퍼스에는 시각 입력에서 볼 곳을 고르는 논문이 여럿 있습니다. ThinkProprio([arXiv:2602.06575](https://arxiv.org/abs/2602.06575))
> 는 **관절 상태와 지시**로 패치를 고르고, Seeker([arXiv:2608.13422](https://arxiv.org/abs/2608.13422)) 는
> **행동 지도만으로** ROI 를 배우고, FRAM([arXiv:2609.30965](https://arxiv.org/abs/2609.30965)) 은 **예측한 미래
> 궤적**의 점으로 특징 지도를 짚습니다. GridS 는 **아무 조건 없이** 평균 특징에서 점을 냅니다.

넷을 나란히 놓으면 비어 있는 칸이 보입니다. FRAM 과 GridS 는 둘 다 연속 좌표에서 특징 지도를 보간으로 찍는다는
같은 도구를 쓰는데, 좌표를 정하는 근거가 정반대입니다 — 하나는 시연 로그에서 만든 궤적 라벨이고, 다른 하나는

VLA 는 카메라 이미지 한 장을 256 개 토큰으로 바꿔 언어와 함께 트랜스포머에 넣는데, 그 대부분은 과제와 상관없는 배경이에요. 트랜스포머 비용은 토큰 수의 제곱으로 늘어나니, 줄이고 싶은 게 당연하죠. 기존 방법들은 그중 몇 칸을 골라 남기는 식이었습니다.

문제는 로봇이 쥘 자리가 종종 두 칸의 경계에 걸린다는 거예요. 칸 단위로 고르면 한쪽만 남길 수 있으니 세밀한 위치가 깎입니다. 게다가 그 방법들은 대부분 학습이 끝난 뒤에 붙이는 규칙이라 과제에 맞춰지지도 않아요.

이 논문은 칸을 고르지 않고 점을 찍습니다. 특징 지도를 평균한 벡터 하나에서 작은 MLP 가 연속 좌표를 몇 개 내고, 그 자리의 특징을 둘러싼 네 칸을 거리에 따라 섞어 새로 만들어요. 원래 자리를 잃은 토큰에는 좌표를 위치 임베딩으로 다시 실어 줍니다.

핵심은 이 섞는 방식이 좌표에 대해 미분된다는 점이에요. 행동을 틀린 만큼의 손실이 어디를 찍을지까지 거슬러 올라가니, 라벨 하나 없이 평소 하던 파인튜닝 안에서 같이 배웁니다.

LIBERO 에서 토큰을 16 개로 줄이면 연산이 76% 가량 줄어드는데 성공률은 오히려 조금 올라요. 같은 조건으로 학습시킨 무작위 선택이나 점수 상위 선택은 기준선보다 떨어지니, 수가 줄어서가 아니라 찍는 방식 덕이라는 게 저자들 주장입니다.

실기 저가 팔에서는 차이가 더 커요. 큐브 쌓기에서 기준선이 한 자릿수에 머물 때 60% 안팎을 내고, 처음 보는 장면에서도 버팁니다. 토큰을 오히려 늘리면 다시 나빠지는 뒤집힌 U 자도 눈에 띄고요.

LIBERO 에 교란을 더한 벤치마크에서는 카메라 시점을 바꿨을 때 크게 앞섭니다. 대신 로봇이 낯선 자세에서 출발하거나 지시를 바꿔 말하면 일관되게 뒤져요. 몸의 윤곽이나 작은 단서가 필요한 자리에서는 줄인 만큼 잃는 셈입니다.

토큰 하나만 남겨도 LIBERO 평균이 거의 그대로라는 결과까지 내놓고, 저자들은 이걸 배경을 잊게 만드는 정보 병목으로 읽어요. 학습 스텝도 큰 배치에서 3 배 안팎 빨라집니다.
