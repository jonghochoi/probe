# 명령은 그 로봇의 말이고, 움직임은 모두의 말이다 — 기록에서 꺼낼 것은 실제로 간 거리

## 1 무엇이 문제인가

### 같은 명령을 보내도 로봇마다 가는 거리가 다르다 | Control Command · Under-reaching · Tracking Error

로봇 정책을 크게 키우는 지금의 주된 방법은 데이터를 많이, 여러 출처에서 모으는 것입니다. 서로 다른
로봇 기종을 섞은 Open X-Embodiment 같은 모음이 있고, 같은 Franka 를 여러 실험실이 따로 굴려 모은
DROID 같은 모음이 있습니다. 그리고 거의 모든 정책은 이 데이터를 [행동 복제](term:bc) 로 배웁니다 —
기록된 행동을 그대로 따라 하도록요.

원문이 짚는 문제는 그 "기록된 행동"의 정체입니다. 관례상 행동은 로봇 아래쪽에서 도는
[저수준 제어기](term:osc) 에 넣어 주는 **입력 명령**으로 정의됩니다. 그런데 명령과 실제 움직임은 같지
않습니다. 제어기가 명령을 완벽히 따라가지 못하니, 로봇은 대개 **명령한 것보다 덜 움직이고**, 원하는
거리를 가려면 명령을 그보다 크게 줘야 합니다.

[최소평균제곱 알고리즘](term:lms) — 한 표본으로 한 번 경사를 내려가는 가장 단순한 온라인 회귀입니다.

```probe-term

```

한 스텝은 이렇게 흐릅니다. 정책이 원하는 변위 $`\Delta p^{\text{target}}_t`$ 를 내면, 어댑터가
명령 $`\hat u_t=W_t\Delta p^{\text{target}}_t+b_t`$ 를 만들고, 로봇이 그것을 실행한 뒤 실제로 간
거리 $`\Delta p^{\text{obs}}_t`$ 를 봅니다. 문제는 **원하는 변위에 대한 정답 명령은 아무도 모른다**는
것입니다. 그래서 원문은 오차를 거꾸로 정의합니다 — "실제로 간 거리"에 대해서는 정답 명령을 압니다.
방금 보낸 $`\hat u_t`$ 가 바로 그 거리를 만든 명령이니까요.

원문은 이 해석을 따로 적지 않지만, 부호를 따라가 보면 왜 이것이 "덜 가면 더 세게 민다"가 되는지
보입니다. 로봇이 덜 갔다면 $`\Delta p^{\text{obs}}_t`$ 가 목표보다 짧고, 지금 어댑터는 그 짧은 거리에 대해 실제로 보낸 것보다

### 두 배 빨리 돌려도, 상자가 여섯 배 무거워져도, 게인이 바뀌어도 | 30 Hz Execution · Payload · Controller Gain Shift

세 번째 질문은 한 로봇 안에서 실행 조건이 바뀌는 경우입니다. 모두 앞의 PnP Box 정책을 그대로 씁니다.

#### 15 Hz 로 모은 데이터를 30 Hz 로 실행

제어 주기를 올리면 명령이 더 자주 들어가 로봇이 빨리 움직입니다. 그런데 명령은 수집 때의 주기에
묶여 있어서, 같은 명령을 두 배 빈도로 보내면 로봇이 덜 미친다는 것이 원문의 설명입니다(명령 하나가
실행될 시간이 반으로 줄기 때문으로 읽힙니다).

SPACE 가 왜 30 Hz 에서 버티는지는 원문이 따로 풀지 않습니다. 우리 읽기로는 정책이 내는 거리가 주기와
무관하고, 어댑터의 온라인 갱신이 30 Hz 에서 덜 가는 만큼 명령을 키우기 때문일 것 같아요. 보정을
30 Hz 로 다시 했는지는 적혀 있지 않습니다.

### 보정만으로도, 갱신만으로도 안 된다 | Offline vs Online Ablation · Calibration Diversity · Gain Tuning · Delta Accumulation

부록 C 는 어댑터의 두 반쪽이 각각 필요한지, 그리고 더 단순한 대안이 있지 않은지를 묻습니다.

#### 오프라인 초기화 대 온라인 갱신

| PnP Box | 성공률 |
|---|---|
| 보정 + 온라인 갱신 (SPACE) | 96 % |
| 보정만 (갱신 없음) | 15 % |
| 갱신만 ($`W_0=I`$, $`b_0=\mathbf{0}`$ 에서 시작) | 0 % |
| 갱신만, 20 롤아웃 내내 이어서 | 30 % |

*원문 부록 C.2, Table 3 — SPACE 는 50 롤아웃, 나머지는 20 롤아웃*

보정만 하고 갱신하지 않으면 **15 %**. 롤아웃 도중 로봇 자세가 바뀌면 처음 맞춘 지도가 틀어집니다.
반대로 보정 없이 항등 지도에서 갱신만 하면 **0 %**. 항등 지도($`W_0=I`$, $`b_0=\mathbf{0}`$)는 첫
스텝에서 예측한 거리를 그대로 명령하는 것이라, 앞의 "어댑터 없이 0 %"와 같은 자리에서 출발하는
셈입니다.

마지막 줄이 흥미롭습니다. 갱신을 롤아웃 20 번 내내 이어서 약 3,000 스텝을 먹였는데도 — 보정 데이터 500 스텝의 여섯 배 — 30 % 에 그칩니다. 원문의
설명은 [LMS](term:lms) 가 원래 **최근 동역학을 따라가도록** 설계돼 있어, 많은 데이터를 모아 평균을
잡는 데는 맞지 않는다는 것입니다. 둘은 역할이 다릅니다 — 보정이 큰 틀을, 갱신이 지금 자세의 어긋남을
맡습니다.

닫혀 있는 로봇에는 아예 쓸 수 없다**는 것.
