### 1,600 개를 뿌리고 움직인 다섯 개만 남긴다 | Co-Tracker · Dense Point Trajectory · Active Points

궤적을 만드는 절차는 세 단계입니다. 시점 $`t`$ 와 시간 창 $`N`$ 이 주어지면, 최근 관찰
$`\mathbf{h}_t=(o_{t-N},\ldots,o_t)`$ 에 [Co-Tracker](term:cotracker) 를 돌립니다. Co-Tracker 는
시작 프레임 $`o_t`$ 를 $`K\times K`$ 격자로 나눠 각 칸을 $`N`$ 프레임에 걸쳐 따라가고, 그 결과로
$`K\times K`$ 개의 밀집 점 궤적이 나옵니다. 실제 설정은 $`K=40`$ 이니 **한 번에 1,600 개의 점**이
따라가지는 셈입니다.


### 매 스텝 40×40 을 돌릴 수는 없다 | Sparse Re-query · Inference Pipeline · Track Loss

학습 때는 데이터를 미리 만들어 두면 그만이지만, 추론 때는 매 시점 궤적이 실시간으로 필요합니다.
1,600 점 밀집 추적을 매 스텝 돌리는 것은 불가능하니, 저자들은 **한 번 뿌리고 다섯 개만 따라가는**
구조를 씁니다. $`t=0`$ 에 $`K\times K`$ 밀집 추적으로 활성 점을 찾고, 이후에는 그 다섯 점만
Co-Tracker 에 물어 궤적을 갱신합니다.

여기에 한 가지 현실이 끼어듭니다. 부록 E 에 따르면 Co-Tracker 는 **30~40 스텝쯤 지나면 추적을
놓치기 시작합니다** — 행동의 크기에 따라 다릅니다. 그래서 일정 주기마다 밀집 격자를 다시 뿌려
활성 점을 재보정합니다. §5 는 그 주기를 20 스텝으로 적고 있습니다.

```python 추론 파이프라인 — 밀집 재보정과 희소 추적의 교대 (원문 부록 E, Algorithm 1)
# K: Co-Tracker 격자 크기 (예: 40 x 40)
# M: 추적할 점 개수 (예: 5)
# N: 궤적 길이 (예: 6)
# T: 최대 추론 스텝 (예: 500)
# redraw_steps: KxK 밀집 추적을 다시 계산하는 주기

image = env.reset()
historical_observations_queue = Queue(max_length=N)
tracked_points = None

for t in range(0, T):
    if t >= N:
        # t == N 이거나 redraw_steps 마다: 추적 유실을 막는 밀집 재보정
        if t == N or (t % redraw_steps == 0 and t > 0):
            grid_points = generate_grid_points(K, image.shape)   # K x K 격자점
            trace = cotracker(historical_observations_queue, grid_points)
            trace = sample(trace, M)                             # M 개 표본추출 (2 x N x M)
            tracked_points = trace[:, -1, :]                     # 최신 프레임의 활성 점으로 갱신
        else:
            # 기존 점만 이어서 추적
            trace = cotracker(historical_observations_queue, tracked_points)
            tracked_points = trace[:, -1, :]

        image_overlaid = overlay_trace(image, trace)
        action = traceVLA([image, image_overlaid], trace_prompt)
    else:
        # 초기 N 스텝은 궤적 안내 없는 프롬프트로
        action = traceVLA([image, image], prompt)

    image = env.step(action)
    historical_observations_queue.append(image)
```

눈여겨볼 것은 `else` 가지입니다. 아직 이력이 $`N`$ 스텝만큼 쌓이지 않은 초기 구간에서는 **같은
원본 이미지를 두 번** 넣고 궤적 안내가 없는 프롬프트를 씁니다 — 학습 때 드롭아웃으로 만들어 둔
바로 그 입력 형태입니다. 드롭아웃은 조명 실패에 대한 보험만이 아니라 매 에피소드 첫 여섯 스텝의
**정상 동작 경로** 이기도 합니다.

### 세 개의 대조군이 각각 무엇을 죽이는가 | Ablation · History Frames · Text Trace

§4.3 은 이 논문에서 가장 값진 부분입니다. "그래서 이득이 어디서 왔나"를 세 방향에서 잘라 봅니다.

**첫째, 그냥 더 파인튜닝해서 오른 것 아닌가.** 같은 데이터셋으로 궤적 없이 파인튜닝한 대조군을
놓습니다. 7B 는 **1.1% 오르고**, 4B 는 오히려 **0.3% 내려갑니다**. 같은 데이터에 궤적을 얹으면
7B 전체가 47.7% 가 됩니다.

**둘째, 과거 프레임을 그냥 넣으면 안 되나.** 궤적 길이와 맞춰 $`N=6`$ 장의 과거 관찰을, 궤적
방식과 똑같이 학습되는 구분자 토큰으로 이어 붙이고 텍스트 프롬프트에도 안내를 넣습니다. 정보량만
따지면 여섯 장의 완전한 프레임이 다섯 개의 선보다 많습니다. 결과는 **6% 하락** 입니다. 저자들은
시점 간 시각 토큰의 **중복** 이 모델을 산만하게 만든 탓으로 봅니다.

## 4 연구축에 무엇이 걸리나

### 동역학을 인코더에 넣을 것인가 픽셀에 그릴 것인가 | D9NB · D2DV · Input-side vs Encoder-side

여기부터는 논문이 아니라 **이 결정에 미치는 영향** 입니다.

D9NB 은 "일반 SigLIP/ImageNet 스템보다 **동작·동역학 인식 인코더**(DynaFLIP 계열) 또는
기하 증류 인코더(eVGGT)를 선호한다"고 적어 두었습니다. 이 문장은 동역학 인식을 **인코더 가중치가
갖는 성질** 로 전제합니다. TraceVLA 는 같은 목적지에 다른 문으로 들어갑니다 — 인코더는 일반
스템 그대로 두고, 동역학을 **입력 픽셀에 그려서** 넣습니다.

| Decision | 이 기본값 | 이 논문 | 판정 |
|---|---|---|---|
| **D9NB** 동작/동역학 인식 시각 인코더 | 인코더를 동역학 사전학습된 것으로 교체 | 인코더 무변경, 동역학을 입력 픽셀에 렌더링 | 경로 분기 미구분 |
| **D2DV** concat 을 넘는 이질 모달리티 융합 | 교차 어텐션 / 비대칭 융합, flat concat 반대 | 과거 프레임 토큰 concat 은 −6%, 채널 내 렌더링은 +7.5%p | 방향 지지, 기제 다름 |
| **D8EJ** 다중 카메라 공간-기하 접지 | 다시점 3D 일관 임베딩으로 등록 | 단일 3인칭 카메라 · 순수 2D 로 카메라 자세 변화에 20%+ | 부분 반례 |
| **D3RP** 백본 적응 범위 | (a) VLM 전면 동결 + 액션 전문가만 학습 | 백본 포함 5 에폭 전면 파인튜닝, 동결 실험 없음 | 미측정 |
| **D9KS** 예측 공간 | 잠재 / 3D flow 예측 | 회고적 2D 픽셀 flow, 예측 없음 | 하한선 후보 |

> [!CAUTION] D9NB — "동역학 인식"이 인코더의 성질인지 입력의 성질인지 이 문장은 가르지 않는다
> D9NB 은 동역학 인식을 인코더 선택 문제로만 적어 두었습니다. TraceVLA 는 인코더를 손대지 않고
> 입력 쪽에서 같은 것을 얻습니다. 두 경로는 비용 구조가 완전히 다릅니다 — 인코더 교체는 사전학습
> 자산을 갈아엎지만, 픽셀 렌더링은 파인튜닝 데이터만 다시 만들면 됩니다. 이 시각 인코더 결정은
> 이 갈래를 구분해 적어야 합니다(D9NB).

> [!CAUTION] D2DV — 반대 방향의 증거가 아니라, 훨씬 강한 형태의 지지다
> D2DV 은 flat concat 을 안티토픽으로 두었습니다. TraceVLA 의 과거-프레임 대조군은 그 조항의
> 이례적으로 선명한 증거입니다 — 정보가 **더 많은데도** 토큰으로 이어 붙이자 6% 가 깎였으니까요.
> 다만 이 논문이 제시하는 대안은 교차 어텐션이 아니라 **같은 채널 안에서의 재표현** 입니다. 교차

### 손 안에서도 활성 점이 남을까 | D9KS · D3RP · Verification Plan

이 방법이 이 스택으로 그대로 넘어오지 않는 지점은 분명합니다. TraceVLA 의 모든 과제는 **평행
그리퍼의 거시 운동** 입니다 — 팔이 화면을 가로질러 움직이니 픽셀 이동량이 크고, 활성 점 문턱
$`\kappa`$ 가 자연히 걸러 줍니다. 이 1 단계 데모인 손바닥 안 정육면체 회전에서는 팔이 거의 서
있고, 움직이는 것은 손가락과 물체 표면이며, 그나마 손가락에 가려집니다.

> [!CAUTION] D9KS — 회고적 2D flow 가 예측적 3D flow 의 하한선이 된다
> P3 D9KS 은 예측 공간을 **잠재 / 3D flow** 로 두고 원픽셀 생성을 비용 때문에 미뤘습니다.
> TraceVLA 는 그보다 훨씬 싼 쪽 — **회고적 2D 픽셀 flow** — 이 이미 상당 폭을 가져간다는 것을
> 보입니다. 세계 모델을 붙이기 전에 이 하한선을 재지 않으면, 나중에 잠재·3D flow 예측의
> 이득이(D9KS) 예측 능력에서 온 것인지 flow 정보 자체에서 온 것인지 구분할 수 없습니다.

> [!CAUTION] D3RP — 전면 파인튜닝 결과를 동결 백본 계획에 그대로 옮길 수 없다
> D3RP 의 적응 범위는 (a) VLM 전면 동결 + 액션 전문가만 학습입니다. TraceVLA 의 이득은 백본을
> 포함한 5 에폭 파인튜닝에서 나왔고, 논문에는 동결 조건 실험이 없습니다. 게다가 이 방법은 **입력
> 형식 자체를 바꾸므로** — 두 이미지, 구분자 토큰, 고쳐 쓴 프롬프트 — 백본이 그 형식을 배울 기회가
> 없으면 성립할 이유가 약합니다. 이 조건에서는 미측정입니다.

#### 먼저 확인할 것

- **가장 싼 점검 — 이 데이터에 활성 점이 남는가.** 손바닥 안 회전 영상에 $`K=40`$ 격자로
  Co-Tracker 를 돌리고, 문턱을 넘는 궤적 개수를 세는 것만으로 답이 나옵니다. 다섯 개를 못 채우면
  이 방법은 이 1 단계에서 시작조차 못 합니다. 코드도 데이터도 이미 있는 점검입니다.
- **동결 조건에서도 서는가.** π 백본을 동결한 채 액션 전문가만 학습하는 (a) 설정에서(D3RP) 궤적
  오버레이를 넣어 봅니다. 여기서 이득이 사라진다면 이 방법은 그 동결을 흔드는 비용을 요구하는
  것이고, 그때는 인코더 교체 경로와(D9NB) 정면으로 비용을 비교해야 합니다.
- **어느 모달리티가 "보이지만 시간에서 잃는" 것인가.** 이 논문의 이득은 **화면에 있었는데 시간이
  지나 사라진** 정보를 되돌린 데서 옵니다. 이 촉각·힘은 애초에 3인칭 화면에 없는 정보라 성질이
  다릅니다. 융합과 토큰 구성을 다시 볼 때(D2DV · D3AG) 두 부류를 갈라 놓아야, 렌더링 처방이 어디까지
