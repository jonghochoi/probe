이 선택들이 일반화 가능한 모방학습을 열어젖힌 건 맞습니다. 그런데 원문의 표현대로 결과는
**"제한된 반응성과 증가한 지연"** 이고, 그래서 이 모델들은 빠르고 매끄러운 반응 제어를 요구하는 동적
조작에 **부적합**합니다.

정확히 무엇이 문제인지 짚어보면 두 가지가 얽혀 있습니다.

- **반응성 저하** — 다음 청크를 예측하는 동안 큰 (서브)청크를 *개루프*로 실행해야 합니다. 실행 중
  들어오는 감각은 반영할 곳이 없습니다.
- **지연 증가** — 예측된 행동이 **낡은(stale)** 감각 입력의 함수입니다.

"그럼 서브청크를 아주 작게, 극단적으로는 하나만 실행하고 다시 예측하면 되지 않나?" — 원문이 바로 이
반론을 다룹니다. 순진하게 그렇게 하면 **불가능**합니다. 매번 커다란 시각·언어 백본을 통과시키고 그
뒤에 flow matching 의 여러 denoising 반복을 돌려야 하니까요.

> [!NOTE] 낡음을 그냥 견디는 게 아니라, 학습시킨다
> 느린 채널이 낡은 걸 흡수하려고 **학습 시점에 일부러 지연**시킵니다 —
> $`d_{\mathrm{vlm}}\sim\mathrm{Uniform}\{0,\dots,d_{\mathrm{vlm}}^{\max}\}`$. 그리고 그 정수
> 지연값을 **학습된 임베딩**으로 인덱싱해 느린 표현에 더합니다. 배포 시에는 *측정된*
> $`d_{\mathrm{vlm}}`$ 이 같은 임베딩을 씁니다. 즉 모델이 "지금 내 시각 정보가 얼마나 낡았는지"를
> **알고** 행동합니다.

저자들은 이 아키텍처 변형을 **Proprioception-Reactive Diffusion Forcing** 이라 부릅니다.

#### 한 번의 호출에서 벌어지는 일

에피소드 시작에는 표준 flow 추론으로 버퍼를 워밍업하고($`H`$ 위치 전부를 순수 노이즈에서 denoise),
측정된 초기 $`d`$ 에 맞게 다시 노이즈를 입힙니다. 그다음부터 매 호출은 **denoising 한 스텝**입니다.

```probe-eq
{"read": "한 번의 호출에서 각 위치를 Δτ_p 만큼만 정답 쪽으로 밀고, 그만큼 노이즈 레벨도 올린다.",
 "tex": "\\mathbf{x}_{p}\\leftarrow\\mathbf{x}_{p}+\\Delta\\tau_{p}\\cdot v_{\\theta}(\\mathbf{x},\\boldsymbol{\\tau},\\mathbf{o})_{p},\\qquad\\tau_{p}\\leftarrow\\tau_{p}+\\Delta\\tau_{p}",
 "symbols": [{"sym": "\\Delta\\tau_{p}", "name": "이번 호출의 전진량", "note": "구역(front·interior·tail)마다 다르게 정한다"},
             {"sym": "v_{\\theta}(\\cdot)_{p}", "name": "그 위치의 예측 속도", "note": "호출당 단 한 번만 계산 — 1 NFE"},
             {"sym": "\\mathbf{o}", "name": "관찰", "note": "신선한 고유수용감각 + 캐시된 비전·언어"},
             {"sym": "\\boldsymbol{\\tau}", "name": "전체 노이즈 레벨 벡터", "note": "계단 모양 $`\\boldsymbol{\\tau}^{\\star,d}`$"}]}
```

구역별로 다른 $`\Delta\tau_p`$ 를 골라 스케줄이 **오른쪽으로 $`d`$ 칸** 밀리게 합니다. 위치
$`[d,2d)`$ 가 $`\tau{=}1`$ 에 도달해 방출되고, 나머지 버퍼가 앞으로 회전합니다. 그다음 버퍼가
$`d`$ 만큼 미끄러지고 뒤에 $`\tau{=}0`$ 인 신선한 노이즈 칸 $`d`$ 개가 붙습니다.

> [!NOTE] $`d`$ 가 변해도 견디는 이유
> $`d`$ 가 일정하면 스케줄이 정확히 재현됩니다. **호출 사이에 $`d`$ 가 바뀌면** $`\Delta\tau_p`$
> 패턴이 새로 측정된 $`d`$ 에 맞게 적응하고, 버퍼는 몇 번의 호출에 걸쳐 새
> $`\boldsymbol{\tau}^{\star,d}`$ 로 끌려갑니다. 학습 때 $`d`$ 를 무작위화했기에 **모델 하나가 모든
> $`d`$ 를 감당**합니다.

```python 학습 스텝 — 계단 스케줄 + 앞부분 마스킹
# Algorithm 1 — πR² training step (paper §A.3), transcribed
def training_step(a, obs, v_theta, *, d_max, d_vis_max, j, alpha=0.2):
    """a: action chunk a[0:H].  obs: (o_fast, o_slow[t-T+1 : t])."""
    if uniform(0, 1) < alpha:
        # warm-up branch: ordinary flow — one tau shared by every position.
        # Keeps the network able to denoise a full chunk from pure noise,
        # which is what fills the buffer at episode start.
        t = uniform(0, 1)
        tau = full(H, t)
        mask = ones(H)                      # every position contributes
    else:
        # staircase branch
        d = randint(1, d_max)
        tau = staircase(d, H)               # three regions, §3.3
        tau = clip(tau + uniform(-j, j, H), 0, 1)   # jitter absorbs per-call drift
        mask = arange(H) >= d               # front d slots excluded from loss

    x = (1 - tau)[:, None] * randn_like(a) + tau[:, None] * a
    x[:d] = a[:d]                           # in-flight actions as inpaint conditioning

    d_vis = randint(0, d_vis_max)           # slow channel is deliberately stale
    pred = v_theta(x, tau, obs.fast, obs.slow_delayed(d_vis), delay_embed(d_vis))
    return (mask[:, None] * (pred - (a - eps)) ** 2).mean()
```

::: details 학습 세부 — 지터와 워밍업 분기
매 배치에서 $`d\sim\mathrm{Uniform}\{1,\dots,d_{\mathrm{max}}\}`$ 를 뽑아
$`\boldsymbol{\tau}^{\star,d}`$ 를 만듭니다. 앞쪽 $`d`$ 칸은 **정답 행동**으로 채우고
$`m_{p}=\mathbf{1}[p\geq d]`$ 로 손실에서 제외합니다 — 추론 시 inpaint 조건화를 그대로 흉내낸
것입니다.

여기에 대칭 지터를 겁니다. $`\tau_{p}\leftarrow\mathrm{clip}(\tau_{p}+\delta_{p},0,1)`$,
$`\delta_{p}\sim\mathrm{Uniform}[-j,j]`$. 호출별 $`d`$ 변동에서 생기는 중심 계단으로부터의 작은
이탈을 흡수하기 위함입니다.

확률 $`p=0.2`$ 로는 **표준 flow 스케줄**(위치 공유 단일 $`\tau`$, 마스크 없음)로 학습합니다. 같은
네트워크가 순수 노이즈에서 청크 전체를 denoise 할 수 있어야 에피소드 시작에 버퍼를 워밍업할 수 있기
때문입니다.
:::

### AdaLN 한 줄만 바꾼다 | Per-position AdaLN · Drop-in Compatibility

이 논문에서 실무적으로 가장 중요한 문장일지 모릅니다. 원문 표현 — *"위 절차는 **한 줄의 아키텍처
변경**으로 어떤 DiT 스타일 flow matching 액션에도 꽂힙니다."*

[AdaLN](term:adaln) 조건화가 **위치별**이 됩니다 — 청크 위치마다 하나의 $`(\gamma_p,\beta_p)`$ 쌍을
갖고, 위치 전체가 하나를 공유하지 않습니다.

```probe-term
{"id": "adaln", "title": "AdaLN (Adaptive Layer Norm)",
 "body": "각 DiT 블록을 노이즈 레벨 $`\\tau`$ 로 변조하는 방식. $`\\tau`$ 를 임베딩해 $`(\\gamma,\\beta)`$ 쌍을 만들고 정규화된 활성에 $`x(1+\\gamma)+\\beta`$ 를 적용합니다. 확산 트랜스포머의 표준 조건화 경로입니다."}
```

```diff 호환성 — 액션 헤드에서 바뀌는 유일한 한 줄
 class DiTBlock(nn.Module):
     def __init__(self, dim, chunk_len):
-        self.adaln = nn.Linear(dim, 2 * dim)          # one (gamma, beta) for the chunk
+        # πR²: the ONLY architectural change. AdaLN becomes per-position, so each
+        # chunk slot can sit at its own noise level. Initialised from the pretrained
+        # shared pair, so training starts position-uniform and specialises later.
+        self.adaln = nn.Linear(dim, 2 * dim * chunk_len)

     def forward(self, x, tau):
-        gamma, beta = self.adaln(embed(tau)).chunk(2, dim=-1)
-        return x * (1 + gamma) + beta                 # tau: scalar
+        gamma, beta = self.adaln(embed(tau)).chunk(2, dim=-1)
+        return x * (1 + gamma) + beta                 # tau: [H] per-position
```

> [!IMPORTANT] 왜 하필 GR00T 인가
> 이 논문의 base 모델은 [GR00T N1.7](term:groot) 입니다. 선택이 우연이 아닌데, GR00T 는 이미
> "비전-언어 모듈 → flow-matching 액션 헤드"라는 **분리된 두 모듈** 구조를 갖고 있었습니다. πR² 가
> 한 일은 그 두 모듈에 **서로 다른 시계**를 준 것입니다 — 구조는 이미 있었고 시간축만 없었던 셈이죠.
> 같은 이유로 이 방법은 π0 계열에도 그대로 붙습니다. P1 핀 논문인

> 노이즈 레벨을 공유하는 구조라, 개조 비용이 동일하게 AdaLN 한 줄입니다.

## 3 정말 되는가

### h를 늘리면 성능이 떨어진다 | Execution-Horizon Sweep · Amortised Denoising

먼저 지연이 없는 이상적 설정($`d=0`$)에서 두 가지를 분리해 봅니다. (i) 과제 성능과 실행 지평
$`h`$ 의 상충 — 개루프로 더 많이 실행할수록 최근 상태를 놓칩니다. (ii) πR² 의 **분할 상환된
denoising** 이 $`h{=}1`$ flow 의 반응성을 *호출당 비용의 일부만으로* 따라잡는지.

평가 조건이 공정하게 기울어져 있다는 점을 봐두세요 — 표준 flow 는 청크 전체를 예측하는 데
**16 denoising 스텝**을 쓰고, πR² 는 **1 스텝**으로 한 번에 하나의 행동을 방출합니다.

그런데 여기서 "시뮬레이션"이 정확히 무엇인지는 본문이 아니라 부록 A.1 에 있고, 그게 이 결과를
읽는 데 결정적입니다 — **손이 하는 과제**거든요.

### 지연이 커질수록 격차가 벌어진다 | Effective Delay · Deployment under VLA Latency

이제 현실적 지연을 넣습니다. GR00T-N1.7 의 계산 비용(비전·텍스트 VLM ≈ 60 ms, $`K{=}4`$ NFE
denoising ≈ 80 ms)을 기준으로 **단위 지연 $`d_0`$** 를 $`K=4`$ denoising 비용으로 정의합니다.
그러면 비전·텍스트 처리 ≈ $`0.75\,d_0`$, 1 NFE = $`d_0/4`$ 입니다.

여기서 **유효 지연**이 갈립니다. 이게 이 실험의 핵심입니다.

| 방법 | 호출당 유효 지연 | $`d_0\in\{1,2,3\}`$ 일 때 $`d`$ |
|---|---|---|
| naive-async | $`1.75\,d_{0}`$ | 2 / 4 / 6 |
| train-time RTC | $`1.75\,d_{0}`$ | 2 / 4 / 6 |
| πR² (async 없이) | $`1.0\,d_{0}`$ | 1 / 2 / 3 |
| πR² (async 포함) | $`0.25\,d_{0}`$ | 1 / 1 / 1 |

결과는 세 학습 시드 평균입니다. πR² w/ async 가 **모든 $`d_0`$ 에서 승리**합니다 —
0.43 / 0.42 / 0.45. naive-async(0.33 / 0.29 / 0.22)와 train-time RTC(0.36 / 0.32 / 0.19)를 이기고,
**지연이 커질수록 격차가 벌어집니다.**

> [!NOTE] 왜 격차가 벌어지나
> baseline 은 호출당 $`d{=}\lceil 1.75\,d_{0}\rceil`$ 를 치르는데 πR² 는 $`d{=}d_0`$ (async 없이)
> 또는 $`d{=}1`$ (async 포함)만 치릅니다. 비동기 처리가 **행동 지연을 1 에 묶어두고** 시각 지연
> $`d_{\mathrm{vis}}`$ 만 늘어나게 하므로, 성능이 $`d_{\mathrm{vis}}`$ 에 대해 **우아하게**
> 저하됩니다.

원문이 이 결과를 이렇게 읽습니다 — *"시각은 거친 안내를 제공하고, 최신 고유수용감각이 조작을
이끈다는 관점을 뒷받침한다."* 앞 절의 가설이 실험으로 되돌아온 지점입니다.

- **Don't Spill** — 공을 그릇에 넣고 그릇을 도마 위로 옮기되 공을 떨어뜨리지 않기. 그릇을 기울이지

목표(6 xArm6 + 12 XHand)로 25 Hz 에서 **2초 분량**입니다.

**진행 점수(Prog)** 도 보고하는데, 과제를 하위 목표로 쪼개 달성 비율을 재는 지표입니다 — 이쪽이

| Insert Box | 상자를 벽 쪽으로 밀기 → 세우기 → 쥐기 → 책 사이에 끼우기 (4) |
| Catch Book | 떨어지는 책을 잡아 들어올리기 (1) |

Catch Book 만 하위 목표가 하나라는 게 눈에 띕니다 — 중간 점수가 없는, 잡거나 놓치거나뿐인 과제라서
반응성 측정에 가장 날이 서 있습니다.
:::

| Setting | $`d`$ | Don't Spill | Tidy up Book | Insert Box | Catch Book |
|---|---|---|---|---|---|
| Flow, Synchronous ($`h{=}10`$) | 4~5 | 4/20 | 4/20 | 11/20 | 4/20 |
| Flow, Naive Async (dense, TE) | 4~5 | 7/20 | 7/20 | 12/20 | 2/20 |
| Flow, Train-Time RTC | 4~5 | 9/20 | 8/20 | 10/20 | 5/20 |
| **πR²** | **1~2** | **10/20** | **12/20** | **16/20** | **11/20** |

> [!IMPORTANT] baseline 세 개가 각각 무엇을 대표하나
> **Synchronous** 는 아무 대책 없는 기준선입니다 — 추론 동안 로봇이 *멈춥니다*.
> **Naive Async + [temporal ensembling](term:te)** 는 가장 흔한 현장 처방으로, 비동기로 돌리고
> 겹치는 예측을 평균냅니다. **Train-Time RTC** 는 위 계보의 최신 성과입니다.
> 즉 이 표는 단순한 성능 비교가 아니라 **지연 대응 전략의 역사**를 한 줄씩 세워둔 것입니다 —
> 멈추기 → 평균내기 → 앵커 걸기 → 아예 없애기.

> [!NOTE] 네 행이 정말로 같은 조건인가 (부록 A.2)
> 표의 네 행은 **같은 GR00T-N1.7 체크포인트에서, 같은 데이터와 같은 스텝 예산으로** 파인튜닝합니다.
> 다른 것은 노이즈 스케줄과 (πR² 만) AdaLN 수술뿐입니다. 위치별 $`(\gamma_p,\beta_p)`$ 는 사전학습된
> **공유 쌍에서 복사해 초기화**하므로, 학습 시작 시점의 πR² 는 위치에 대해 균일한 스케줄에서
> 출발했다가 서서히 분화합니다.
>
> 딱 하나 대칭이 아닌 항목이 있습니다 — 지연 샘플링 상한이 train-time RTC 는 $`d_{\max}=10`$,
> πR² 는 $`d_{\max}=5`$ 입니다. πR² 는 지연을 행동 지연과 시각 지연 **둘로 쪼개** 다루는 반면
> RTC 는 하나로 취급하니 견뎌야 할 폭이 다르다는 게 저자들의 근거고, 시뮬레이션 쪽 두 방법은
> 배치마다 $`p(d{=}k)\propto e^{-k}`$ 인 **지수 감쇠 분포**에서 $`d`$ 를 뽑는 것까지 공유합니다.
> 재현한다면 이 비대칭은 그대로 물려받을지 결정해야 할 지점입니다.

Train-Time RTC 가 가장 강한 baseline 이지만 πR² 가 **모든 지표에서** 앞섭니다. 반응성이 결정적인
과제 — Tidy Up Book, Insert Box, Catch Book — 에서 격차가 가장 크고 **절대 20~30%p** 개선입니다.
Catch Book 은 5/20 → 11/20 으로 두 배가 넘습니다.

> [!NOTE] RTC 가 실패에서 못 빠져나오는 이유
> 원문의 관찰이 날카롭습니다 — RTC 는 **이전에 생성된 in-flight 행동이 정책을 최근 운동의 연장 쪽으로
> 편향**시켜 실패 복구가 어렵습니다. 특히 Insert Box 에서 두드러집니다. 진행 중 행동을 앵커로 쓰는
> 바로 그 메커니즘이, 방향을 *바꿔야* 할 때는 족쇄가 되는 겁니다.

사례입니다.

## 4 연구축에 무엇이 걸리나

### 공유 레이트가 흔들린다 | D1MZ · Decision Log · P1 · P2 · P4

여기부터는 논문이 아니라 **이 결정에 미치는 영향**입니다.

> [!IMPORTANT] 읽은 것들 사이에서 이 논문의 자리
> **대체가 아니라 결합 대상입니다.** P1 핀 논문인
> Dexora([arXiv:2605.18722](https://arxiv.org/abs/2605.18722))와
> DexGrasp-VLA([arXiv:2511.00139](https://arxiv.org/abs/2511.00139))는 *액션 공간과 해부학적 분할*을
> 다루고 지연·반응성 축은 건드리지 않습니다. πR² 는 그 논의와 완전히 직교하는 축을 하나 더 얹습니다.
> 더 흥미로운 건 P2 쪽입니다. ForceFlow([arXiv:2605.11048](https://arxiv.org/abs/2605.11048))와
> ViTacFormer([arXiv:2506.15953](https://arxiv.org/abs/2506.15953))는 힘·촉각을 **구조적으로**
> 융합하되 모든 모달리티가 동기 갱신된다고 전제합니다. πR² 는 반대로 구조를 단순화(flat concat)하고
> **갱신 주기**를 비대칭화해 접촉 반응을 얻었습니다.

그래서 아직 아무도 답하지 않은 질문이 하나 남습니다 — **접촉 성능에 더 기여하는 것은 융합
"구조"인가 갱신 "주기"인가.** 어느 논문도 이 둘을 분리 측정하지 않았습니다. 융합과 토큰
구성을 정할 때(D2DV · D3AG) 직접 부딪히게 될 질문입니다.

| Decision | 이 기본값 | 이 논문 | 판정 |
|---|---|---|---|
| **D1MZ** 입력 모달리티 · 제어율 분리 | (ii) modality-separated + **(α) shared rate** | rate-separated — proprio 매 tick, VL 비동기 | (α) 정면 반박 |
| **D9ZP** Body↔Hand 정보 공유 | $`a_b\to(\gamma,\beta)`$ FiLM 단일 지점 | per-position AdaLN — 같은 계층을 청크 축으로 확장 | 새 설계 문제 발생 |
| **D6JW** π backbone 통합·분할 | π0 action expert slice + 양쪽 FT | 백본 동결 + 액션 헤드만, 변경은 AdaLN 한 줄 | "변경 최소화" 참조점 |
| **D5DQ** System0 역할 | System1 이 접촉 유지 속도를 못 냄 | System1 급 VLA 가 25 Hz 힘 반응 달성 | 정당화 근거 이동 필요 |

| **D3RP** VLM 백본 적응 범위 | (a) full VLM freeze + action expert only | 동일 — Qwen-VL·Eagle-2 동결 | 지지 |

> [!CAUTION] D1MZ — 가장 강하게 부딪히는 지점
> 이 기본값은 **(α) shared rate** 입니다. 이 논문은 modality-separated 를 지지하면서 동시에 shared
> rate 를 정면으로 반박합니다 — 고유수용감각은 매 tick, 비전·언어는 비동기라는 **rate-separated**
> 조건화가 VLA 규모에서 *구현 가능하고* 20~30%p 의 가치가 있음을 보였습니다.

> [!CAUTION] D5DQ — System0 의 정당화가 이동해야 한다
> System0 를 따로 두기로 한 전제는(D5DQ) **"System1 이 접촉 유지에 필요한 반응 속도를 못 낸다"**
> 였습니다. 그런데 이 논문은 System1 급 VLA 정책 자체를 25 Hz 폐루프 힘 반응까지 끌어올렸고,
> Figure 5 의 50 N vs 120 N 은 정확히 **System0 이 담당하려던 "과도한 힘 억제"** 입니다. System0
> 의 존재 이유가 사라지는 건 아닙니다 — 슬립 억제는 여전히 25 Hz *아래* 시간 척도의 문제니까요.
> 하지만 정당화가 **"System1 이 느리다"에서 "슬립은 25 Hz 로도 늦다"로 옮겨가야 합니다.** 이 > binary gating 도(D6ZD), System1 이 이미 매 tick 힘을 보고 있다면 게이팅 신호의 정보량을 재검토할
> 여지가 생깁니다.

#### 먼저 확인할 것

- **가장 싼 점검** — 이 과제의 접촉 이벤트 시간 척도(슬립 발생~감지)를 25 Hz 와 대조. System0 의
  정당화가(D5DQ) 실제로 "25 Hz 로도 늦다"에 걸리는지부터 정량화합니다.
- **D3AG 대조군** — flat concat(45-dim) 대 per-finger 토큰화를 *같은 과제*에서 비교. 논문이 flat
  으로도 힘 변조를 얻었으므로 이 가정의 필요조건 여부를 싸게 검증할 수 있습니다.
- **D9ZP 충돌 설계** — hand head 의 FiLM 이 body intent 와 노이즈 레벨 *두 소스*를 동시에 받아야
  합니다. 두 변조를 어떻게 합성할지가 미해결입니다.
- **GPU 예산** — 비동기 채널이 물리적으로 분리된 계산 자원을 요구합니다(A5000 2장). 이 배포 구성에
  그대로 반영되는지.

액션 청크는 좋은 발명이었습니다. 한 번 추론해서 미래 여러 스텝을 한꺼번에 내면 학습 신호가 풍부해지고 움직임이 매끄러워지죠. 대신 그 청크가 실행되는 동안 들어오는 감각은 쓰이지 못하고 버려집니다.

짧게 끊어 자주 다시 예측하면 될 것 같지만, 그게 안 됩니다. 큰 비전-언어 백본 한 번에 denoising 여러 스텝이 붙어 있어서, 한 번 예측하는 데 제어 주기 몇 개가 통째로 들어가거든요.

이 논문의 출발점은 그 비용의 내역을 뜯어본 데 있습니다. 한 호출을 재보면 이미지 전처리와 백본이 절반쯤, 나머지 절반이 denoising 반복입니다. 그런데 관절 각도와 손끝 힘을 읽어 작은 MLP 에 통과시키는 비용은 그 옆에서 거의 보이지 않을 만큼 작습니다.

여기서 나오는 관찰이 하나 있습니다. 모든 입력이 같은 속도로 갱신될 필요는 없다는 것. 비전과 언어는 어디로 갈지에 대한 굵은 안내를 주고, 접촉이 어긋났는지 미끄러지는지를 알려주는 쪽은 고유수용감각이니까요.

그래서 조건을 두 채널로 가릅니다. 비전-언어 특징은 백그라운드 스레드에서 비동기로 갱신되고 그동안은 캐시된 값을 씁니다. 고유수용감각은 매 tick 새로 들어옵니다. 얼마나 낡은 값을 쓰고 있는지는 정수 지연을 학습된 임베딩으로 넣어 모델에게 알려줍니다.

두 번째 장치는 노이즈 스케줄입니다. 청크의 위치마다 다른 노이즈 레벨을 두되, 이미 로봇으로 나가 있는 앞쪽 몇 칸은 깨끗한 값으로 못을 박아 조건으로 쓰고, 가운데는 비탈로 깔고, 뒤에는 순수 노이즈를 붙입니다.

이 모양 덕분에 호출마다 한 스텝만 밟아도 앞쪽에서 깨끗한 행동이 떨어져 나옵니다. 그리고 못 박는 칸의 개수를 실제로 측정된 지연에 맞춰 바꾸면, 한 번 학습한 모델 하나가 여러 하드웨어의 지연을 그대로 받아냅니다.

붙이는 비용은 놀라울 만큼 작습니다. DiT 블록을 조절하는 AdaLN 을 위치별로 바꾸는 한 줄이면 되고, 백본과 어텐션은 손대지 않습니다. 사전학습된 정책을 그 상태로 파인튜닝해서 쓸 수 있습니다.

효과가 가장 또렷하게 보이는 곳은 힘입니다. 책을 집어 정리하는 과제에서 이 방법은 손끝 힘이 50 N 근처에서 멈추는데, 낡은 계획을 밀고 나가는 비교군은 120 N 까지 올라가 책을 눌러 뭉갭니다.

저자들이 남겨둔 것도 분명합니다. 추론 서버와 로봇 사이의 통신 지연처럼 모델 바깥에서 생기는 지연은 이 방법이 손대지 않고, 백본 구조 자체는 그대로 두었기 때문에 고유수용감각을 더 강하게 쓰도록 설계하는 여지는 남아 있습니다.
