# 토큰의 위치는 한 점의 좌표가 아니라, 그 토큰이 본 것 전체의 회전 평균이다

## 1 무엇이 문제인가

### 같은 픽셀 차이가 다른 각도, 같은 프레임 차이가 다른 시간 | Index-based RoPE · Physical Scale · Geometric Encodings

로봇 정책이나 영상 모델의 트랜스포머는 카메라 여러 대에서, 여러 시점에 찍힌 토큰을 한 시퀀스에 섞어 읽습니다.
어텐션은 순서를 모르니 위치 신호를 따로 줘야 하고, 오늘날의 기본값은 [RoPE](term:rope) 입니다. 그런데 표준
RoPE 가 위치로 삼는 것은 **시퀀스 인덱스나 시공간 격자 좌표**입니다. 원문 §1 은 여기서 두 가지 어긋남을 짚습니다.

```probe-term
{"id": "rope", "title": "RoPE (Rotary Positional Embedding)",
 "body": "쿼리·키 채널을 두 개씩 묶어 위치에 비례하는 각도로 회전시키는 위치 인코딩. 두 토큰의 내적이 위치의 **차이**에만 의존하게 됩니다. 이 논문은 회전의 각도를 무엇에서 가져오느냐 — 인덱스가 아니라 물리 주소 — 와, 한 점이 아니라 여러 점의 회전을 평균하는 것을 바꿉니다."}
```

첫째, **같은 픽셀 오프셋이 서로 다른 시야각에 해당할 수 있습니다.** 화각이 넓은 손목 어안 카메라와 머리의
핀홀 카메라에서 "옆 패치"는 전혀 다른 각도만큼 떨어져 있고, 해상도를 바꾸거나 이미지를 자르면 같은 카메라
안에서도 그 관계가 바뀝니다. 둘째, **같은 프레임 인덱스 차이가 서로 다른 경과 시간을 나타낼 수 있습니다.**
샘플링 간격이 바뀌거나 비디오 토크나이저가 프레임 여러 장을 한 토큰으로 압축하면 "한 칸 뒤"의 의미가 달라집니다.
원문의 결론은 그래서 위치 인코딩이 **이산 인덱스 차이를 넘어 관측 기하와 실제 시공간 척도**를 나타내야 한다는 것입니다.

이 방향으로 이미 나온 답이 있습니다. [GTA](term:gta) 는 카메라 기하에 붙은 군 변환을 어텐션의 매칭과 값 집계에
걸었고, [P-RoPE](term:prope) 는 내부·외부 파라미터를 투영 변환 하나로 묶어 시야 절두체 전체의 관계를 상대 위치에
넣었으며, [RayRoPE](term:rayrope) 는 쿼리 카메라 좌표계에서 광선 좌표를 만들고 깊이와 그 불확실성을 예측해 광선
위 분포의 기대 회전을 Q/K/V/O 에 겁니다(원문 §2).

```probe-term

```

### 토큰 하나는 점이 아니라 영역이다 | Observation Footprint · Video Tokenizer · Integrated Encoding

두 번째 문제는 첫 번째보다 덜 눈에 띕니다. 카메라 기하를 넣는 인코딩조차 토큰 하나에 **주소 하나**를 줍니다.
그런데 이미지 토큰은 픽셀 한 칸이 아니라 패치 하나 — 픽셀 영역 — 를 모은 것이고, 시간 압축 비디오 토큰은 여러
시각의 관측을 합친 것입니다. 원문은 이것을 토큰의 [관측 발자국](term:footprint)이라 부르고, **중심 주소 하나로는 이
발자국을 다 묘사할 수 없다**고 씁니다.

```probe-term

```

원문 §2 는 이 발자국이 어디서 생기는지 구체적으로 짚습니다. DiT 는 이미지 잠재를 패치로 잘라 확산을 하고, Wan 은

### 회전을 평균해도 상대성은 그대로 남는다 | Expected Rotation · Relative-Position Property · Eq. (3)–(7)

주소가 정해지면 회전은 표준 RoPE 와 같은 꼴입니다. 머리 차원 $`d_h = 2M`$ 에 대해 주파수 벡터 $`\omega_m \in \mathbb{R}^D`$ 를($`D`$ 는 주소의 차원 — 시공간 7, 정적 6)
골라, 주소를 그 방향으로 투영한 각도만큼 2×2 블록을 돌립니다(식 (3)). 한 가지 다른 점은 $`\omega_m`$ 이 **축 하나가 아니라
주소 공간의 한 방향**이라는 것입니다. 부록 E.1 식 (22) 는 사인·코사인으로 만든 준난수 방향을 정규화하고, 크기는 정책·재구성 설정(대역 B)에서
$`\{0.0625, 0.125, 0.25, 0.5, 1, 2\}`$ 여섯 대역을 특징 쌍에 돌아가며 붙입니다(깊이·시점 합성은 다른 대역, 원문 표 12). 그러니 한 채널 쌍의 각도는 시간·카메라 중심·
시선 방향이 **섞인 선형 결합**입니다.

그다음이 이 논문의 핵심입니다. 토큰 $`i`$ 가 덮는 주소의 분포 $`\mu_i`$ 에서 회전을 평균해 그 토큰의 위치 연산자로 씁니다.

평균을 하면 걱정이 하나 생깁니다. RoPE 가 쓸모 있는 이유는 $`\mathcal{R}(x)^{\top}\mathcal{R}(y) = \mathcal{R}(y - x)`$ — 두 회전을
맞대면 **차이의 회전**만 남는다는 성질(식 (5))인데, 평균한 행렬도 이것을 지키는가. 원문의 답은 그렇다는 것이고, 증명은

그다음은 점별 회전의 상대 위치 성질입니다. 여기서 두 가지가 바로 따라 나옵니다. 모든 관측이 한 주소에 몰리면 $`M_i = \mathcal{R}(x_i)`$

$`\overline{R}_{i,m}^{\top}\overline{R}_{i,m} = \rho_{i,m}^2 I_2`$ 라, 발자국이 넓은 토큰은 자기 자신과의 위치 항도 주파수마다 $`\rho^2`$ 배로 줄어드는 셈입니다(원문이 직접 쓰지는 않은 귀결).

어텐션 로짓은 결국 $`\ell_{ij} = (M_i q_i)^{\top}(M_j k_j)/\sqrt{d_h}`$ 이고(식 (7)), 식 (6) 이 그 안의 위치 상호작용을 직접 제약합니다.
각 모델이 원래 쓰던 Q/K 정규화는 위치 연산자 **앞에** 둡니다(부록 E.1).

$`\Phi_i(\omega_m) = c_{i,m} + \mathrm{i}\,s_{i,m} = \mathbb{E}[e^{\mathrm{i}\omega_m^{\top}X_i}]`$ 이고, 이것은 방향(위상)과 크기를 함께 가집니다.

### 평균 회전의 길이가 결맞음이고, 값에는 항등 갈래를 섞는다 | Rotation Coherence · V/O Transformation · Identity Branch

평균 회전은 일반적으로 **회전과 수축의 합성**입니다. 주파수 $`m`$ 에서 $`\overline{R}_{i,m} = \rho_{i,m}R(\alpha_{i,m})`$ 로 쓸 수
있고, $`\rho_{i,m} = \sqrt{c_{i,m}^2 + s_{i,m}^2} \le 1`$ 을 원문은 [회전 결맞음](term:coherence)이라 부릅니다. 크기가 1 이 되는 것은
그 주파수에서 모든 관측의 회전이 같은 방향을 가리킬 때뿐입니다(위상이 $`2\pi`$ 의 정수배만큼 달라도 됩니다, 부록 A.2 식 (14)).

```probe-term

 "body": "한 주파수에서 토큰의 관측 회전들이 얼마나 같은 방향을 가리키는지 — 평균 회전 벡터의 길이로, 0 과 1 사이입니다. 발자국이 넓거나 주파수가 높을수록 회전이 흩어져 작아집니다. 이 논문은 이 값을 값·출력 변환의 혼합 비율로 다시 씁니다."}
```

부록 A.2 는 여기에 한 가지를 더 짚습니다. 모든 토큰이 같은 픽셀 노드 배치($`3\times3`$)를 써도 결맞음은 토큰마다 달라집니다.
결맞음을 정하는 것은 픽셀 오프셋이 아니라 **물리 주소 오프셋**이고, 매핑의 국소 야코비안을 거치면 같은 픽셀 템플릿도 내부
파라미터·시점 위치·카메라 방향에 따라 다른 주소 폭이 되기 때문입니다. 같은 카메라·같은 프레임의 카메라 중심 항은 모든 노드에
같아 크기를 바꾸지 않습니다.

이 결맞음을 쓰는 곳이 [V/O 변환](term:vo)입니다. GTA(값 집계)와 RayRoPE(Q/K/V/O)처럼 위치 변환을 값 쪽에도 걸면 기하가 **무엇을 고를지**(Q/K)
뿐 아니라 **고른 내용을 어떻게 섞을지**에도 들어갑니다. 그런데 평균 회전 $`M_i`$ 를 그대로 값에 곱하면 회전이 서로 상쇄될 때 값 특징이
눌려 사라집니다. 그래서 원문은 항등 갈래를 섞습니다.

길이도 늘지 않습니다 — 노드를 토큰으로 펼치지 않으니까요.

아래는 원문 식 (8)–(10) 과 부록 식 (20)–(21) 을 옮긴 단일 머리 스케치입니다 — 모델별 Q/K 정규화와 다중 머리 배치는 뺐습니다. 원문에는 공개 코드가
없어, 변수 이름은 우리가 붙였습니다.

```python 토큰별 회전 통계와 V/O 블록 — 원문 식 (8)–(10) · 부록 식 (20)–(21) 의 옮김
import torch

def node_weights(sigma=0.25):
    # 패치 안 3x3 노드: {1/6, 3/6, 5/6}^2, 중심 (1/2, 1/2) 기준 가우시안 (식 21)
    g = torch.tensor([1/6, 3/6, 5/6])
    p = torch.stack(torch.meshgrid(g, g, indexing="ij"), -1).reshape(9, 2)
    w = torch.exp(-((p - 0.5) ** 2).sum(-1) / (2 * sigma ** 2))
    return p, w / w.sum()

def rotation_stats(x, w, omega):
    # x: [N, K, D] 토큰별 K 개 노드의 물리 주소, w: [N, K] 정규화 가중치
    # omega: [M, D] 주파수 벡터 (방향 x 대역 크기)
    phase = torch.einsum("nkd,md->nkm", x, omega)        # 노드별 각도
    c = (w[..., None] * torch.cos(phase)).sum(1)          # [N, M]  식 (20)
    s = (w[..., None] * torch.sin(phase)).sum(1)
    return c, s                                           # 토큰당 한 번, 재사용

def rotate_pairs(z, c, s):
    # z: [N, 2M] 채널 쌍마다 [[c, -s], [s, c]] 를 곱함 (식 8) -> M_i z
    z1, z2 = z[..., 0::2], z[..., 1::2]
    out = torch.empty_like(z)
    out[..., 0::2] = c * z1 - s * z2
    out[..., 1::2] = s * z1 + c * z2
    return out

def vo_block(z, c, s, g=1.0, transpose=False):
    # G = (1 - g*rho) I + g * R_bar  (식 9);  transpose=True 면 G^T
    rho = torch.sqrt(c ** 2 + s ** 2)
    s_ = -s if transpose else s
    return (1 - g * rho).repeat_interleave(2, -1) * z + g * rotate_pairs(z, c, s_)

def pod_attention(q, k, v, c, s, g=1.0):
    q, k = rotate_pairs(q, c, s), rotate_pairs(k, c, s)   # Q/K 정규화 뒤에 적용
    a = torch.softmax(q @ k.T / q.shape[-1] ** 0.5, -1)    # 식 (7)
    h = a @ vo_block(v, c, s, g)                           # sum_j a_ij G_j v_j
    return vo_block(h, c, s, g, transpose=True)            # G_i^T, 식 (10)
```

`rotation_stats` 만 노드 수 $`K`$ 를 보고, 나머지는 전부 표준 RoPE 와 같은 2×2 블록 연산입니다. `g=0` 이면 `vo_block` 이 항등이 되어
Q/K-only 변형이 됩니다.

> [!WARNING] 시간 노드는 VAE 의 실제 수용장이 아니다
> 잠재 토큰마다 준 최대 4 프레임 구간은 **관측 노드를 정하는 명목상 구간**일 뿐, 인과 VAE 의 전체 수용장이 아니라고 원문이 직접
> 적습니다(부록 A.5). 토큰이 실제로 정보를 받은 범위와 인코딩이 가정한 범위가 다를 수 있습니다.

원문 계산으로 기준선 학습 파라미터의 약 0.052 %, 0.072 % 입니다(동결 인코더 제외).

### 재구성에서 P-RoPE 를 앞서지만, 샘플 간격만 바꾸면 진다 | Cross-view · Temporal Extrapolation · Input Changes

정책 실험의 비교 대상은 기하 인코딩 없는 원래 정책뿐입니다. P-RoPE 와 직접 맞붙는 것은 시각 기하 과제이고, 그 첫째가 **동기화된 교차뷰 재구성**입니다.
두 카메라의 동시 관측으로 세 번째 뷰를 그려 내는 과제를 Sharpa North, RoboTwin, AGIBot 세 데이터셋에서 각각 따로 학습합니다. 모델은
24 층, 폭 1152, 3억 8천만 파라미터급이고(표준 RoPE · POD-RoPE 382,409,856, P-RoPE 382,416,768), 입력은 256×320, Wan2.1 VAE 는 동결,
전역 배치 2,048 로 2,500 업데이트를 돕니다(부록 E.2, 표 13).

MSE 는 동결 VAE 의 잠재 공간에서 잰 오차이고, 나머지 [지표](term:metrics)는 문맥과 일관되게 VAE 로 디코딩한 목표를 기준으로 재며, 궤적 안에서 과제를 평균한 뒤 궤적을 평균합니다.

### 점보다 분포, 직접 평균보다 항등 갈래 | Component Ablation · Sharpa North Head-to-Wrist

또는 오른쪽 손목 뷰를 재구성합니다. 6 층 백본(46,168,704 파라미터)을 여섯 그룹이 같은 샘플링·초기화로 2,500 스텝 학습하고, 같은 검증 샘플

### 같은 위치 신호를 정책 구조 넷과 실기 로봇에서 쟀다 | D8EJ · Positional Registration in Policies

멀티카메라 공간·기하 접지에서 우리가 본체로 고른 것은 **기하 기반 멀티뷰 인코더로 만든 3D 일관 공간 임베딩을 VLM 앞에 두는 것**이고, 교차
어텐션 융합기는 가벼운 폴백으로 남겨 두었습니다(D8EJ). 이 코퍼스에서 그 사이의 자리 — **뷰별 토큰을 남긴 채 등록을 어텐션의 위치 신호에
싣는 방식** — 에는 이미 두 편이 있습니다. [G3VLA](https://arxiv.org/abs/2606.24472) 는 π0 · GR00T 1.5 에 새 교차뷰 융합 층을 붙여 PRoPE 를 넣고 LIBERO 와 실기 UR5 에서 쟀고,
[RayRoPE](https://arxiv.org/abs/2601.15275) 는 같은 계열을 3D 비전 과제에서만 쟀습니다.

이 논문이 보태는 것은 둘입니다. 하나는 새 융합 층 없이 **기존 어텐션이나 작은 잔차 모듈 안에서** 정책 구조 넷에 같은 방식을 들고 갔다는 것,

### 얼린 백본 안에는 들어가기 어렵다 — 값과 출력이 바뀐다 | D3RP · D5ZL · D6JW · Retrofit

이 논문의 π0 통합은 위치·내용 변환을 **기존 시각 어텐션 안에** 넣고, 그 상태로 과제마다 미세조정했습니다. 원문은 어느 층인지까지는 적지 않습니다.
우리 쪽 백본 결정은 PaliGemma-2B × π0 계열을 쓰되 **VLM 을 전부 얼리고 행동 전문가만 학습**하는 것이고(D3RP), 사전 보존 장치는 그 동결이 유지되는
동안 대기 상태입니다(D5ZL).

여기서 V/O 가 문제가 됩니다. Q/K 만 바꿔도 어텐션 가중치가 달라져 출력이 움직이지만, V/O 변환은 거기에 더해 $`G_j v_j`$ 와 $`G_i^{\top}`$ 로 **층이 내놓는 특징 자체를**
바꿉니다. 얼린 층 안에 넣으면 그 층의 출력이 사전학습 때와 달라지고, 그 변화에 나머지를 맞춰 줄 학습 신호는 동결이 막습니다.

> [!CAUTION] D3RP · D5ZL — π0 식 통합은 동결과 양립하지 않는다
> 원문의 π0 이득(Clean +12.07, Randomized +15.73 점)은 시각 어텐션 안에 변환을 넣고 **미세조정**한 결과입니다. VLM 을 얼려 두는 한(D3RP) 같은
> 방식은 쓸 수 없어 보이고, 남는 자리는 Fast-WAM · RDT 처럼 **잔차 모듈을 새로 붙이는** 쪽입니다.

잔차 모듈 쪽 숫자는 고무적으로 보입니다. 폭 192 모듈이 Fast-WAM 학습 파라미터의 약 0.052 % 이고, 실기에서는 같은 모듈에서 표준 RoPE 를 POD-RoPE 로만 바꿔 +20 점이 났습니다.

### 시간이 초 단위 주소가 되면, 예측 보조의 시간축은 어떻게 되나 | D3FQ · D8XB · D9KS · Time Address

Fast-WAM 은 학습 때 영상과 행동을 함께 모델링하는 world-action model 이고, 이 논문은 그 영상 갈래와 행동 갈래 모두에 분포 인코딩을 넣었습니다. 우리
쪽 세계 모델 역할은 **VLA 와 함께 학습하는 잠재 동역학 사전 + 미래 예측 보조**이고(D3FQ), 그것을 공유 백본 위의 보조 헤드로 붙이며(D8XB), 예측
공간은 잠재·3D 흐름입니다(D9KS). 원시 픽셀 영상 생성은 비용 때문에 미뤘습니다.

이 논문이 그 결정에 주는 것은 예측 공간이 아니라 **예측의 시간 좌표**입니다. 영상 토큰이 몇 프레임을 묶었고 그 프레임들이 실제로 몇 초에 찍혔는지가
위치에 들어가고, 조건부 시간 외삽에서는 목표의 시각과 카메라 기하를 주는 것만으로 $`h16`$(약 2 ~ 4 초) 예측이 P-RoPE 보다 나아집니다. 다만 비교 상대인
P-RoPE 에 시각이 어떤 식으로 들어갔는지는 원문에 없어, 이 이득을 시간 주소 하나에 돌리기는 어렵습니다. 미래 예측 보조의
목표 토큰에 "언제"를 실제 시각과 카메라 기하로 주는 것은 우리 구조에서도 바로 시도해 볼 수 있는 일로 보입니다.

> [!CAUTION] D3FQ · D9KS — 물리 시간 주소가 샘플링 간격 변화에 대한 강건성을 주지는 않았다
> 초 단위 시간을 주소에 넣었는데도, 샘플링 간격만 바꾸자 Sharpa North 에서 P-RoPE 보다 PSNR 이 낮아졌습니다(base +0.751 → stride5 −0.671). 예측
> 보조를 한 프레임률로 학습하고 다른 프레임률로 쓰게 된다면, 시간 주소만으로 그 차이를 메울 수 있다고 기대하기는 어려워 보여요(D3FQ, D9KS).

원인 하나를 짐작해 볼 수는 있습니다. 시간 매핑 $`f(\tau) = 2\tanh(\tau/2)`$ 에 척도 $`s_t = 0.125`$ 초를 쓰고 기준 $`t_0`$ 는 표본에서 가장 이른 시각이니,
0.5 초 뒤 노드만 해도 $`\tau = 4`$ 로 $`f`$ 가 상한 2 의 96 % 에 이르고, 2 초 남짓 뒤인 $`h16`$ 목표는 상한에 사실상 붙습니다(우리 계산).
먼 시각끼리는 시간 성분이 거의 구분되지 않는다는 뜻이라, $`h16`$ 의 이득도 시간보다 카메라 기하 쪽에서 왔을 가능성이 있습니다. 원문은 이 매핑을 위상 증가를 제한하려는 선택으로 설명할 뿐, 포화가 긴 지평이나 간격 변화에 무엇을
하는지는 따로 분석하지 않습니다. 그리고 이 논문의 외삽은 **행동이 아니라 목표의 기하와 시각**으로 조건을 겁니다. 우리가 고른 프레임별 행동 조건화(D6FM)와
겹치는 것은 아니고, 둘을 함께 줄 때의 효과는 이 논문 밖입니다.

평균한 회전은 짧아집니다. 관측이 넓게 퍼질수록 회전이 서로 상쇄되거든요. 이 길이를 결맞음이라 부르고, 값과 출력에 거는 변환에서 항등과 회전을 섞는 비율로 다시 씁니다. 결맞음이 0 이면 내용이 그대로 지나갑니다.
